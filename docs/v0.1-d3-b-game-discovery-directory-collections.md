# GoFurry V0.1-D3-B — Game Discovery, Directory & Collections

**状态：冻结 / 立即实施** · 2026-11-14  
**目标仓库：** `librecosta/gofurry`，只修改 `develop`。  
**基线：** `6cbba1c2ec564a4a0d66438a2a5c48126128da52`，D3-A3 RSS-ONLY 与 CI 成功。  
**阶段原则：** **一次做完游戏首页、目录、搜索、合集与 Start 游戏入口。** 已有 Game 身份、Harvest Steam 事实与持久自动资料直接复用；不要继续搭无关基础设施。D3-C 才制作丰富游戏详情与历史图表。

## 0. 核心定位与范围

GoFurry Games 是 **兽人/拟人游戏资料库和发现频道**。不是另一个 Start，不是 Steam 网站的镜像，也不是新评论/评分平台。资料库以已公开 Game 为主，自动建档照常生效，人工运营只用于**可选精选、合集策展和少数纠错**。

本阶段完成：
1. **API 业务发现读模型**：游戏卡片、受控类型映射、发行状态/日期、来源平台、目录搜索/筛选/分页、首页各个固定 Slice；
2. **首页** `/games`：可视化发现与分类入口；
3. **完整目录** `/games/directory`：组合搜索、类型/平台/发售状态/系统等真实支持的筛选与可用排序；
4. **合集** `/games/collections` 和 `/games/collections/{public_id}/{slug}`：持久、可排序的人工策展集合、真实作品时间线；
5. **轻量私有操作**：最多三项首页精选槽位和合集创建/关联/排序/发布的最小业务命令，留 D4 Admin UI；游戏主体无人工强制审核；
6. **Start** 仅启用现存 Games 链接，维持现有 Popover/导航视觉；CN/INTL SSR、SEO、双语、响应式、状态/错误与隔离自动验收。

不包括：完整游戏详情媒体画廊、价格历史/玩家曲线或新闻专页（D3-C）、真实 itch Provider（A3 已给出 RSS-ONLY）、UGC/评论/评分/抽奖、游戏点赞/收藏、Admin GUI（D4）、旧站真实迁移（D5）、CN→INTL 数据投影（D6）、第三方新爬虫、AI 重新判定、动态首页搭建器、用户画像或新微服务。

## 1. 公共业务身份与持久性硬约束

- 所有发现查询只依赖区域 PostgreSQL **已发布且未被显式 publication_blocked 的 Game**，继承 D2/D3-R1。不可再次加入 `Candidate.review_until`、`profile_at` 30 天、`collection_current` 存在、Heat、是否有封面/标签/准确发售日等作为 Game 的可见性条件。
- 缺少来源资料的 Game 仍然能在目录和搜索里被看到，只要存在已发布的持久名称/有效 Presentation。部分历史数据损坏时按 D2/D3-R1 原有真实 noindex/缺失处理，不能把数据库错误变成空列表或假 404。
- Game `id/public_id/slug` 及人工编辑值不可变更所有权。按来源可获得的数据可增量改善卡片，但来源或 Harvest 故障不删除持久内容、合集成员、精选配置或上次已成功选定的封面；时效价格不再“当前”时可省略折扣和报价，**不影响卡片存在**。
- 公共 SSR/API 从不在请求时向 Harvest/Steam/itch/AI Gateway 发请求。没有真实数据就显示有设计的空状态，**不得用测试 Fixture 或外部图片当真实游戏**。
- itch 来源只在已有 `game_sources` 有经确认记录时显示官方链接/发行渠道，不提供虚构价格、下载量或在线人数。CN 产品差异只有成人信息/评论；INTL 当前仍遵守既有 SFW 公开边界。

## 2. 游戏摘要、类型、发行状态和数据来源

建立最小 `GameCard` DTO（字段由实现以现有 API 习惯命名）：
- `public_id, slug, localizations`（真实 zh/en 文案及来源语言）、`first_published_at`（首次 **GoFurry 收录公开**时间）、`cover_url`（可选，只有可信 Steam 官方媒体）；短简介；
- 有限的 `platforms`（真实 Steam/itch_io 及 future source links，目录卡可显示图标），`genres`（受控可过滤代码，严格依据实际 Steam Genre ID/Name 或运营确认值），`systems`（只有真实 Steam windows/mac/linux 声明），`release`（类型+真实原始时间描述+精度），可选新鲜的分地区 `price_summary`；
- Game 页面不出现全局价格、全平台在线人数或一个平台的发布日冒充所有平台首发。

**Genre 映射**：首版以实际观测到的 Steam `genres` 显式 ID 优先、少量可验证和可维护的固定映射；没有依据不猜视觉小说、恋爱、furry 子类型。缺 Genre 不妨碍收录/展示；映射变化更新筛选元数据而非重写 Game 身份。不要将 Games 生搬硬套 Site 的八类别、主分类必填或用户评论标签。

**发行语义**：
- GoFurry 首次公开 `first_published_at`、Steam `coming_soon`、Steam 的平台发行日期原文和实际可解析的日期精度是不同数据，不能互相替代；
- 只有确切可解析日期才可以进入严格的发布日期排序，允许 year/month/quarter、TBA 和不可解析文本原样展示且归为 Unknown/预期；禁止将 Q3 或年份推断为某天；
- 如果来源明确 coming_soon=true，标记平台尚未推出；仅时钟超过原预计日期**不得推断已正式发布**，仍等待确切事实。已推出不代表首次在 Steam 发布或作品全球首发；
- 首页 `最近收录` 依据真实首次公开时间；`近期发售` 与 `即将发售` 仅基于可信且语义一致的来源事实，不能填充虚假日期；数据不足可以折叠板块。
- 价格/折扣仅在既有最新有效、区域/币种对应的 Steam 事实中显示，并带区域/观测时间；禁用过时折扣推荐，不能把缺价显示免费。玩家数和新闻若在首页使用只能带 Steam 来源；当前不建游戏 Heat/假热门榜。

**封面**：优先已选来源的现成 Steam `header/capsule`，严格服务器+前端 URL 检查已支持的 HTTPS 媒体域，源换代后保留持久已选可用链接（安全撤回另行标记）。不自行下载视频/全素材到 R2，不作 SSR HEAD，不用未经许可的第三方壁纸。图片缺失/加载失败可使用简洁排版回退，不渲染误导性的截图。封面展示遵守无闪烁/CLS/裁切规范。

为快速浏览而创建的数据库索引和必要的字段投影应保持极少，优先复用 `game_source_metadata`、`game_approved_presentations`、`game_sources` 与已存在的 `collection_current`；如果为 (N) 条 Game 每次都运行大 JSON 聚合非常慢，建立轻量持久 **discovery summary** 和增量刷新，禁止泛型 CMS/EAV。所有数据从持久来源生成，不进行整库每次 SSR 扫描。

## 3. 公共目录和搜索

新增 `GET /api/v1/games/directory` 与对应区域 SSR `/games/directory`：
- 搜索 `q`：有限长度的 Unicode 文本、真实 zh/en 名称和摘要，以及有明确来源的开发者名；保留中英文输入法组合、300ms 限制防抖、回车提交。无输入显示完整已发布目录，不能强制必须指定类型。
- 筛选：受控 Game genre（多选 OR）、发行渠道 Steam/itch、支持系统 Windows/macOS/Linux（仅确知时匹配）、发行阶段 `all/upcoming/released/unknown`，可选 `free/discount` 仅基于真实新鲜平台报价且 UI 明确“Steam 商店”而非游戏通用状态。避免三个时间范围双日期选择器、任意 pageSize 数字框、过度复杂 Advanced Filter。
- 排序：`added_desc`（默认，首次收录）、`name_asc`、`release_desc` 和 `upcoming_asc`；关键词查询可有真实 `relevance`，不得伪装人气榜。未知时间排在已知数据之后，所有排序稳定以 Public ID 破同分。
- URL 查询参数稳定、可恢复/分享、筛选全由后端执行。分页用有界 keyset/cursor（默认 24，最多 48），游标绑定具体筛选+排序防串页，分类变更导致游标失效返回 400；跨页不重复，失败仍可重试。详情返回目录保留筛选、页次和滚动位置（学习 D2-B Sites 已实现方式）。
- 性能：禁止 N+1，每页使用少量有界查询。空结果=真正无匹配，数据库/投影错误=503，不是 200 空目录；未发布/成人受限内容在关键词、计数、统计、精选、合集成员中均不泄露。

## 4. 固定 Game 首页布局

首页路径 `/games`，响应式克制但比 Sites 更偏视觉。固定代码布局，**不允许 Admin 后期动态注入布局/任意组件**：

1. **频道介绍 + 搜索**：一句真正的 zh/en 文案、输入后进入内部游戏目录，清晰浏览全部入口；不要复制 Start 搜索引擎 UI；
2. **精选游戏**：最多三个可选固定命名槽 `primary/secondary_1/secondary_2`，可为空。只显示真正人工设置且目前可公开的 Game；不自动冒充“编辑精选”。全部为空时隐藏精选，首页仍有自动的真实游戏内容，绝不因为无人策展而空白；
3. **最近收录 + 即将发售**：最近收录以首次 GoFurry 公开时间为准；即将发售遵循来源 coming_soon，未确定日期清楚展示 `待公布`，不伪造时间；
4. **类型探索**：固定受控 genre 的真实计数/快捷入口（只呈现确实支持的 Game Genre），允许某类为零，目录可访问；
5. **近期发行 / 免费与优惠**：真实公开游戏和可信新鲜 Steam 区域报价才显示，没有数据时不硬填；价格数据无法获取时可整体不显示该板块；
6. **精选合集**：最多 3 个确实已发布的集合，缺失时自然折叠，首页不依赖必须人工创建合集；
7. **近期官方动态**：可选，只有已绑定来源、可信发布时间/官方 URL 的 Steam 新闻且源作品公开时展示；本轮可以保持精简 3–6 条，不开发新闻详情页。

各板块允许真实数据不足时缩减/省略，但首页仍提供搜索、最近收录与目录入口。不同 Slice 可以避免显著重复但不人为改写排序/热门数据。绝不做假排行榜、假评分、假评论、抽奖。允许固定轻量交互动效；尊重 reduced-motion，不出现自动轮播造成的阅读干扰。

## 5. 精选合集：真正的编辑作品，非自动标签

新实体仅为 **GameCollection**（不是通用 CMS），具备 UUIDv7、随机 16 位 Public ID、可编辑 slug、独立 `draft|published|archived`、revision 和首次发布时间。含 zh/en 标题和摘要，可单语言发布并明确语言回退；没有英文不冒充已翻译。成员为 `collection_id + game_id` 和 **稳定的显式排序**，同一 Game 可属于多个合集。集合本身不需要任意 HTML 页面编辑器、全站排名/自动抽奖、背景上传模块。

- 后端：`GET /api/v1/games/collections`（公开列表/筛选/分页）及 `GET /api/v1/games/collections/:publicID`（合集详情 + 按当前 published/SFW 规则过滤的成员与有界分页）。前端 `/games/collections`、`/games/collections/{public_id}/{slug}` 有正确 canonical、hreflang、404/503；无法公开的成员自动不在公开列表出现，但**不从数据库成员表删除**，恢复出版后仍属于同合集。
- 允许两种列表视图语义：默认按**编辑顺序**的游戏卡片列表；若有可信时间，可提供 `时间线`（已发售/预期/未知日期）切换，保留用户选择。含年份/季度/TBA 的不能伪造日级日期。数据不足时仍展示普通合集列表。
- 精选槽位（合集首页最多三个）为**可选人工策展**。没有集合时正常空首页，不自动生成假合集；不把“缺合集”变成游戏发布门槛，不要求普通 Game 进入合集。
- 必要的初始管理命令可以私有 CLI：创建、编辑本地化标题/简介、设置 members/order、发布/归档、设置首页合集位、查看冲突；通过同一服务事务 + revision/CAS，单次操作不要求逐个 Game“审核”。真正的可视化内容运营留 D4。非公开写操作不可开放匿名路由。旧站合集数据真实导入留 D5，不能用种子 Fixture 作为生产合集。

## 6. 前端导航与访问

- 使用 TanStack Start + React SSR + SCSS Modules + Motion + 必要 Base UI；与 Sites 的版心、间距、Light/Dark、焦点、Hover、触屏风格一致，但封面比例/视觉更适合游戏内容。不要引入 Tailwind/StyleX、新组件库或造另一套复杂设计系统。
- CN 默认 zh，无前缀；INTL 默认 en，无前缀；另一语言使用已有 `/{language}` 契约。搜索查询 URL 跟随语言切换正确保留，已知缺失翻译按现有规则诚实回退/不建立伪译文 SEO。
- `apps/web/src/start/chrome.tsx` 当前 Games 项是 `aria-disabled` 按钮；本阶段只将它改为正确的本地化 `/games` 可用链接，保持 Sites 导航、其他 Popover、Start 搜索与视觉全部不变。
- 现有 `/{-$language}/games/$publicId/{-$slug}` 极简详情路由保持 D1 兼容；D3-B 不重建 Game Details（交给 D3-C）。新增 `/games/collections`、`/games/directory` 时防止 TanStack 动态 Public ID 路由误匹配，静态路径和非法路由有真实 404。
- 频道首页与合集详情可索引；含任意筛选搜索查询的目录标 `noindex,follow` 并有规范页 canonical，SEO 不使用假翻译。至少给出合格的页面标题、描述、OG、语言切换、实际有内容的静态 SSR 首屏；API/数据库故障给 503，不返回 200 假空壳。

## 7. 数据库、接口和无人工运营

- 允许 1 个或少量 Goose forward migration，必要的 Game 首页精选槽位、合集+本地化+成员、少量索引/初始收录时间；**不能修改已应用旧迁移**。不新增自增主键、泛型 CMS、通用素材管理、独立 microservice、消息队列、通用工作流或固定过期审查计时器。
- 如果 Game 需要新的 `first_published_at`，从可信已有 `published_at` 及历史状态迁移时遵守语义；无法证明的历史首次公开时间保持 NULL，不伪造。再次发布绝不覆盖首次收录时间。
- 管理 CLI 仅服务精选/合集编辑，不要求手动添加所有 Game。A2-B 的自动发现、自动 eligibility、D3-A1 Intake 持续运行并自动出现在 D3-B 目录；无新人工发布步骤、二次审批或手工填满标签的要求。
- 因价格、玩家数、新闻、media 缺失而降级局部 UI，不改变 published Game。响应只使用地区 GoFurry DB/API 的可信持久内容；查询保证有界/分页、SQL 注入防护、来源隔离。
- 数据模型的 `GameCollection` 不与自动 `genre` 分类混淆；不要重写 Steam Provider 或把 itch.io RSS-ONLY 结果变成公开已发布作品。

## 8. 强制验收

隔离 PostgreSQL 18 + Redis 8 + 现有固定 Harvest 测试夹具（无需公网 Steam/itch）：

1. 首次公开 Game 的自动来源资料进入首页/目录，**不需要再执行 review、标签填充或合集成员手工录入**；已发表 Site/Start 不变。
2. 同一 Game 的 Steam/itch source 是**同一张**作品卡；没有来源报价的 itch 不显示价格/玩家数；Steam 不同店区不覆盖。
3. 无封面/简介/Genre/日期/当前价格或只有英文的已发布 Game 仍在完整目录，locale/lang/noindex/回退准确。成人、draft、archived、publication_blocked 从所有首页、搜索、合集结果中剔除且不泄漏计数。
4. 受控类型 ID 映射、coming_soon、精确/部分日期、预计未来但日期已过去的边界；`最近收录 != 最近发售`；未知日期不能被编造成某日。
5. 搜索 q、类型、平台、系统、发行状态、价态多条件+按键盘/输入法操作、游标翻页、无重复、切换过滤器、返回后的列表位置恢复；浏览器 390px/1280px、Light/Dark、reduced-motion、触屏。
6. 真实编辑合集添加/移除/排序多个 Game、同 Game 参与多个合集、版本冲突、首发稳定 ID、归档及重新发布；成员失去公开资格时只是公共过滤，不修改关系；再次公开恢复展示。无合集时首页功能完整。
7. 首页 3 个精选槽位可为空且不会制造假精选；真实最新收录、即将发售、优惠和官方动态来源真实；未采集或过期仅影响时效 slice，不隐藏作品。
8. Harvest/Steam/Redis 不可用、Consumer 410/reset、31/181/365 天不采集时，已发布 Game 目录、合集关系和稳定卡片仍存在；价格/在线“当前”描述必须符合独立的时效门槛。
9. 路由/SEO：CN/INTL、`/games`、`/games/directory`、`/games/collections`、`/games/collections/{publicId}/{slug}` 的 SSR、canonical、URL 301、404/503、动态路由冲突和 Start Games 导航。
10. `task sql:check`、`task check:api`、`task check:catalog`、`task check:collection`、`task check:web`、适用 HMR、Docker/Containers 和匹配 SHA GitHub CI 通过。不删除测试/伪造数据；数据规模 100/1000/10000 Game+合集与目录分页耗时/内存报告。

交付 `docs/v0.1-d3-b-acceptance.md`：所建 API/路由/迁移、类型和时间语义、截图或浏览器证据、自动作品进入目录的真实隔离测试、耗时/性能、CI URL/SHA、范围未覆盖项。完成后推送 `develop` 并停止，下一阶段 D3-C 专门做 Game Detail + Insights，不拆 D3-B 额外小阶段。
