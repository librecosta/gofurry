# D1-B1 Harvest binding and evidence acceptance

## Setup

Omit `harvest` to keep the integration disabled. Apply GoFurry's migration explicitly with `task migrate ACTION=up CONFIG=<private-yaml>` on the intended database. Migration `202611110002` adds canonical source references, effective Site/Game bindings, shared schedule intent and membership, Consumer state and gaps, scoped current results, Site facts and daily coverage, Steam News and Steam player samples. Steam price stays in the scoped current projection. No public route was added.

On Harvest, provision two principals in a dedicated CN namespace with only the approved capability grants. Use role `writer` for Targets and Schedules, and role `reader` for the Consumer. With a separate operator credential call `POST /api/v1/consumers`. Set `stream` to the namespace, choose a Consumer `name`, and set `principal` to the reader principal name. Keep the returned UUIDv7. Keep the writer and reader YAML files under an ignored private directory. Use HTTPS on the private network. Plain HTTP is accepted for a literal loopback address in development.

```yaml
harvest:
  url: https://harvest.internal.example
  namespace: gofurry_cn
  consume: true
  reader_token: <private-reader-token>
  consumer_id: <enrolled-uuidv7>
  poll_interval: 5s
  page_size: 32
```

For the private writer YAML, use the same regional database, origin and namespace. Set `consume: false`, omit the reader token and Consumer ID, and set `writer_token`. The API can also reconcile continuously when its private YAML includes the writer credential. With a reader-only API, invoke the writer CLI after changing plans or removing source addresses or identities.

```text
api --config .local/harvest-writer.yaml collection bind-site PUBLIC_ID https://example.com/business
api --config .local/harvest-writer.yaml collection bind-steam PUBLIC_ID APP_ID
api --config .local/harvest-writer.yaml collection plan BINDING_ID web.http --interval 24h --anchor 2026-11-12T00:00:00Z --egress-region cn
api --config .local/harvest-writer.yaml collection reconcile
```

Bindings require a published Site/Game and an approved active address or Steam identity. Use an explicit UTC anchor and the same typed parameters for bindings that should share a schedule. Unbind explicitly when archiving catalog entries. After a lost Schedule POST, reconciliation adopts a single exact disabled match in the dedicated writer namespace. Reserve schedule creation in that namespace for this integration. If Harvest has no match, the original request can still be in flight. Once an operator verifies that request can no longer commit, `collection retry-absent PLAN_ID --confirmed-no-request-in-flight` rechecks absence and reopens the intent. Reconcile then sends the new request. Harvest has no Schedule creation idempotency key or owner field. Keep ambiguous plans pending until they can be verified.

## Evidence and limits

The Consumer stages a fresh projection and replays changes through the snapshot head before atomically committing the active generation and pending ACK. A 410 records a gap. A recovered snapshot yields attributable baselines and current facts. Intermediate history lost to retention stays unknown. Normal changes save facts and cursor together. Unchanged source confirmations may appear only in current results. The six-hour confirmation sweep records only the UTC day actually confirmed. Missing days remain Unknown. Detector ruleset changes and non-detection do not imply migrations or removal. Existing editorial records stay independent from collected facts.

GoFurry stores bounded normalized evidence, timestamps, source scope, rule versions and compact before/after values. News keeps up to 200 GIDs per scope for 180 days. Players keeps 30-minute buckets for 30 days. The durable Site ledger and daily coverage are retained for D1-B2. Bounded reset accepts at most 512 snapshot pages and 512 replay pages in eight minutes, with at most 100 items per page. Beyond those bounds the previous committed projection remains available and a diagnostic is logged.
