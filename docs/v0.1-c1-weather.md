## Configuration and lifecycle

Root private `config.yaml` now includes:

```yaml
geoip:
  database_path: data/geoip/dbip-city-lite-2026-11.mmdb
```

Relative paths resolve against the explicit `--config` YAML's directory, independently of the current working directory. `geoip: null`, absence or a blank `database_path` disables resolution. No environment, dotenv, default database path or second config source is consulted. Each CN/INTL deployment chooses its own local file/configuration.

`maxminddb-golang/v2` v2.9.0 opens and verifies the file once before the API listens. Normal requests perform only local IPv4/IPv6 `netip` lookups. Missing, corrupt or incompatible files produce a bounded startup warning and `unavailable`; status/backgrounds/suggestions remain usable. The reader is closed after draining, with a lock protecting an in-flight lookup during shutdown timeout. No IP or city coordinates are added to request/lifecycle logs.

The [DB-IP Lite MMDB schema](https://db-ip.com/db/format/ip-to-city-lite/mmdb.html) and the installed file were inspected. The resolver decodes only `city.names`, `country.iso_code`, `subdivisions[].names`, and `location.latitude/longitude`. It does not assume commercial GeoIP2 accuracy radius, postal code, timezone, subdivision codes or a provider city ID. City/subdivision records tested here contained English only. `zh-CN`/`zh` and `en` are preferred; a missing language reuses another actual record name, with deterministic fallback to an available language. No names are translated or fabricated.

City, a country code and both finite/in-range coordinates are required. Coordinates are rounded to two decimal places. Missing city/coordinates, invalid IP, private, loopback, link-local, multicast, shared/documentation/benchmark/reserved and conservatively excluded transition addresses yield `unavailable`.

## Client IP boundary

The default is `server.trusted_proxies: []`: forwarding headers have no effect. Configured values must be explicit IPs/CIDRs; invalid entries and `/0` are rejected. Fiber v3 uses `TrustProxy`, `TrustProxyConfig.Proxies`, `ProxyHeader: X-Forwarded-For` and `EnableIPValidation: true`. Its chain walk starts at the trusted TCP peer, moves right to left and stops at the first non-trusted address. The broad Loopback/Private/LinkLocal trust switches stay false.

The inactive [Nginx example](../deploy/nginx/gofurry.conf.example) assumes Nginx is the **direct public edge**. It overwrites X-Forwarded-For with `$remote_addr` rather than appending browser input, overwrites forwarded host/protocol and clears alternate forwarding headers. For this same-host example only, explicitly configure:

```yaml
server:
  # Keep existing address/environment.
  trusted_proxies: [127.0.0.1]
```

Only do this when that exact peer is an administered proxy and the API is inaccessible directly to public clients. Other hosts must name their actual proxy IPs/CIDRs. No private subnet or Cloudflare range is implicitly trusted. A future upstream CDN requires its own reviewed edge chain; this example does not trust browser-supplied CDN headers.

The current Web SSR background/suggestion fetches deliberately omit visitor IP headers. They cannot be used to infer a visitor city. In Vite Dev, the general Nitro API proxy is also not implicitly trusted, so local browser requests remain unavailable. Behind the example Nginx, `/api/` goes directly to Go. There is no new Web relay, IP query parameter or browser-controlled alternate-IP lookup. Future SSR location use must establish the same explicit edge trust boundary before forwarding a client identity; do not blindly relay request headers.

## HTTP contract and future weather fields

`GET /api/v1/start/location`:

```json
{
  "state": "ready",
  "source": "ip",
  "location": {
    "city": { "zh": "Hangzhou", "en": "Hangzhou" },
    "country_code": "CN",
    "subdivisions": [{ "zh": "Zhejiang", "en": "Zhejiang" }],
    "latitude": 30.27,
    "longitude": 120.16
  }
}
```

Unavailable is HTTP 200 with `{"state":"unavailable","source":"ip","location":null}`. Both use `Cache-Control: private, no-store`, the existing deployment Region/SFW headers and JSON v2. The endpoint ignores supplied `ip`, region/locale query parameters and cookies. It never returns an address, raw MMDB record or internal file/server details. Official Fiber in-memory limiters allow 30 requests/minute per resolved client IP and 600/minute per deployment; 429 retains the unified error/request-ID envelope and Retry-After. Other API routes have independent limiters.

C1-B consumes approximate latitude/longitude for provider queries and retains the bilingual city/subdivisions/country for labels and disambiguation. These are not a QWeather location ID, timezone, weather observation or temperature. The C1-A checks below record city resolution; the subsequent C1-B section covers the weather provider.

## C1-B: QWeather provider and cache

The implementation follows QWeather's [JWT authentication](https://dev.qweather.com/docs/configuration/authentication/), [dedicated API Host](https://dev.qweather.com/docs/configuration/api-host/) and [current weather](https://dev.qweather.com/docs/api/weather/weather-current/) contracts. Only the new `GET https://{api_host}/weather/v1/current/{latitude}/{longitude}?lang=zh|en` is used, with latitude first and both coordinates at two decimals. There is no legacy v7 parser.

The optional `qweather` block is documented in `config.example.yaml`. Its `enabled` defaults to false; `api_host` is a bare dedicated `*.qweatherapi.com` hostname. The other fields are `developer_id`, `project_id`, `credential_id`, `private_key_path` and `proxy_url`. Key paths resolve against the explicit YAML directory. Missing required values or unreadable/invalid keys disable weather with bounded diagnostics, leaving other APIs running. Explicit malformed enabled host/proxy settings are rejected by YAML validation. No environment credential/proxy lookup exists.

The supplied development PKCS#8 key was copied to ignored `data/private/qweather/gofurry-dev-private.pem`. An existing destination is compared before reuse and never silently overwritten. On this Windows workstation, the private directory ACL is limited to the current user and the file has inherited ACLs removed with one current-user Read permission. On Unix deployments, use directory mode 0700 / key mode 0600 (or read-only 0400). The source production key is not read or used. IDs/Host and the enabled development settings live only in ignored root `config.yaml`; no key, JWT or actual credential values belong in source, logs or examples.

Standard-library Ed25519/x509/PEM/JSON v2 produce `alg=EdDSA`, `kid=credential_id`, `iss=developer_id`, `sub=project_id`, `iat=now-30`, `exp=iat+900` and unpadded Base64URL segments. Each new signature is verified with its corresponding public key. The key is parsed once per Provider; a mutex-protected token is reused until 60 seconds before its expiry, then refreshed on demand. No token endpoint or public signing tool exists.

Provider bounds are 4 seconds per request, 128 KiB of decoded JSON, 16 KiB response headers and 4 concurrent calls. The reused Transport has bounded connections, no environment proxy, no redirect following and no application retries. Only explicit `qweather.proxy_url` may select an HTTP(S)/SOCKS proxy. Shutdown cancels pending provider requests and closes idle connections.

Only HTTP 200 and the new `condition.code/text`, numeric `temperature.value` with `unit=°C`, and nonempty `metadata.attributions` are accepted. Values must be finite and within -100…100°C; codes must have a three-digit nonzero-leading numeric form, allowing future provider codes without a frozen icon catalog. Missing fields, duplicate/trailing/invalid JSON, oversized responses and invalid values yield unavailable/fallback. All returned attribution strings are retained, in their original order and content, subject to bounded length/count validation. Upstream bodies, URLs, credentials and Authorization are never included in public errors or application logs.

### Cache and request cost bounds

- One cache per API instance/region, keyed only by normalized coordinates and `zh`/`en`, with no IP/name/user cache.
- Fresh for less than 20 minutes; `stale` is explicit after that. At 60 minutes or later the old observation is unavailable and cannot be returned as current weather.
- At most 512 entries (including short failure records) and 4 active distinct-key refreshes. Same-key cold requests join one flight. Callers with usable stale data return it immediately if another refresh is underway, concurrency is full or the provider is cooling down.
- The first stale request performs one bounded synchronous refresh; a failure returns the still-usable old data. There is no background poller or unbounded goroutine/flight map.
- Failures/timeouts cool the key and provider for 15 seconds. HTTP 429 cools for at least 60 seconds, honoring numeric Retry-After up to 300 seconds. Fresh cached results remain usable during cooling. Capacity eviction and returned-value copies prevent indefinite growth and cross-request mutation.
- Official Fiber in-memory HTTP limiters allow 20 weather requests/minute per trusted resolved client IP and 120/minute per deployment. They are independent of the location/background/suggestion routes. Rate failures retain the unified 429/request-ID/Retry-After contract.

### Weather HTTP contract

`GET /api/v1/start/weather?lang=zh` also accepts `lang=en`; omitted language defaults to zh and unsupported values return the existing HTTP 400 error envelope. Normal weather availability is HTTP 200:

| Field | Contract |
| --- | --- |
| `state` | `ready`, `stale`, or `unavailable` |
| `location` | C1-A city/country/subdivisions/approximate coordinates, or null if no public city is resolved |
| `weather` | null for unavailable; otherwise `temperature_c` (number), `condition_code`, `condition_text`, `fetched_at` (UTC timestamp) |
| `attribution.weather`, `weather_url` | `QWeather`, `https://www.qweather.com` |
| `attribution.geolocation`, `geolocation_url` | `DB-IP`, `https://db-ip.com` |
| `attribution.weather_attributions` | The provider's original `metadata.attributions` array, empty when weather is unavailable |

`fetched_at` is when Go successfully retrieved/validated the response, **not** a claimed observation timestamp. The API accepts only language: supplied IP, latitude/longitude, Host/upstream URL, region or Cookie cannot select another location/deployment. Fiber's existing trusted-peer contract determines the public IP and C1-A determines coordinates. No resolved city means no Provider/cache request. QWeather disabled/unavailable produces `weather:null`, never placeholder temperatures. All outcomes are private/no-store and retain deployment Region/SFW headers.
