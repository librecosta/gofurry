## Storage and privacy

- Host-only `gf-quick-access-CN|INTL` remembers only the enabled Boolean for SSR. The same region preference reaches the initial HTML; no layout flip waits for localStorage. The quick row reserves its height while browser-only items fade in after hydration.
- `gf-quick-access:CN|INTL` localStorage stores `{version:1,pinned:[],recent:[]}`. Pins contain stable ID, name, validated HTTP(S) URL and order. Recent records contain origin-only URL, name, last-visit timestamp and count. No query string, fragment or path is stored in Recent. Explicitly entered pin URLs retain their destination.
- At most 128 pins and 64 recent records are retained; reads reject payloads larger than 256 KiB and validate every field. Invalid/executable URLs and URL credentials are rejected. Blocked cookies/storage degrade to in-memory state; persistence then lasts only for the current page.
- Site identity is lowercase hostname without `www.`, plus any nondefault port; protocol/path variants share a slot. Pins take priority in user order; recent sites fill remaining slots by last visit. Visible limits are 12/10/8/4 at ≥1600/≥1200/≥768/<768px, with a separate management button. Responsive hiding does not remove saved data.
- Only deliberate GoFurry link activations (including portal links and middle clicks) record a visit while enabled. Existing real Home/status/GitHub/source links are covered; search submission uses the existing separate search path and never records queries or destinations. Turning quick access off preserves prior records and stops collecting new visits. This is not browser-history access.
- Unpin removes only the pin; an existing recent record may remain visible. Delete removes the pin and matching recent record. A later explicit visit may add it again. Recent records can also be removed separately.
- No site data is sent to the Go API, Redis, accounts or cookies. Local storage is region-scoped and is not synchronized between CN/INTL. Icons try [Favicon.im](https://favicon.im/api), then the site's own `/favicon.ico`, then Globe. The third-party request contains only the validated hostname, never the saved path, query, fragment, port or credentials. All IP literals, single-label hosts and local/reserved namespaces bypass Favicon.im. This is syntactic hostname validation, not a DNS lookup or a guarantee about a public domain's DNS destination. As with any direct browser request, Favicon.im can see the connecting network address and requested hostname. Images use lazy loading, asynchronous decoding and no referrer; each source is tried at most once per URL. There is no arbitrary-domain backend proxy or target-page script execution.

## Interaction and checks

The `+` manager uses the existing Base UI Dialog and Motion exit lifecycle. Pins support Motion handle dragging, Up/Down controls and handle ArrowUp/ArrowDown. Add/edit, pin/unpin and delete operations all live in this Dialog. Site links keep their native open/context-menu behavior; there are no per-site edit triggers or custom context menus.

F1 separates each transparent tile into a 44px light acrylic icon card (34px favicon) and an independent truncated name. Only the icon card changes its background on hover, over 300ms. The compact form always renders two icon actions (Plus/Check and X); shared validation disables invalid or duplicate submissions, and Cancel is disabled outside editing. Desktop inputs/actions share one row; narrow screens place Name above the URL/actions row without squeezing the URL. `styles/_acrylic-input.scss` provides the same neutral, shadowless 420ms focus/blur surface to management and weather-city inputs, with no hover change. Native `title` tooltips are forbidden by `AGENTS.md` and checked in the focused browser test file; document and Dialog/Popover titles remain intact.

These network results are development-time observations, not permanent guarantees about those sites.

Motion retains the existing 420ms sibling transitions and keyboard ordering. No manager wrapper or data-model change is needed.
