# C2 — Quick access and recent visits

Settings → Basic → Show quick access is off by default. Enabling it uses the existing SearchBox's inline platform picker on desktop as well as mobile, replacing the desktop platform row with one quick-access row. The input retains its 500px maximum width and existing category, suggestion, IME and submission logic. Motion owns the 420ms picker width/row-height and popup transitions; ordinary hover stays at 300ms. Reduced motion removes these animations.

## Storage and privacy

- Host-only `gf-quick-access-CN|INTL` remembers only the enabled Boolean for SSR. The same region preference reaches the initial HTML; no layout flip waits for localStorage. The quick row reserves its height while browser-only items fade in after hydration.
- `gf-quick-access:CN|INTL` localStorage stores `{version:1,pinned:[],recent:[]}`. Pins contain stable ID, name, validated HTTP(S) URL and order. Recent records contain origin-only URL, name, last-visit timestamp and count. No query string, fragment or path is stored in Recent. Explicitly entered pin URLs retain their destination.
- At most 128 pins and 64 recent records are retained; reads reject payloads larger than 256 KiB and validate every field. Invalid/executable URLs and URL credentials are rejected. Blocked cookies/storage degrade to in-memory state; persistence then lasts only for the current page.
- Site identity is lowercase hostname without `www.`, plus any nondefault port; protocol/path variants share a slot. Pins take priority in user order; recent sites fill remaining slots by last visit. Visible limits are 12/10/8/4 at ≥1600/≥1200/≥768/<768px, with a separate management button. Responsive hiding does not remove saved data.
- Only deliberate GoFurry link activations (including portal links, middle clicks and menu Open) record a visit while enabled. Existing real Home/status/GitHub/source links are covered; search submission uses the existing separate search path and never records queries or destinations. Turning quick access off preserves prior records and stops collecting new visits. This is not browser-history access.
- Unpin removes only the pin; an existing recent record may remain visible. Delete removes the pin and matching recent record. A later explicit visit may add it again. Recent records can also be removed separately.
- No site data is sent to the Go API, Redis, accounts or cookies. Local storage is region-scoped and is not synchronized between CN/INTL. The browser contacts a displayed site's own `/favicon.ico` with no referrer; errors fall back to Globe. There is no icon aggregator, arbitrary-domain backend proxy or target-page script execution.

## Interaction and checks

The `+` manager uses the existing Base UI Dialog and Motion exit lifecycle. Pins support Motion handle dragging, Up/Down controls and handle ArrowUp/ArrowDown. Site actions are available by right click, Shift+F10/ContextMenu and a focusable/touch-visible ellipsis button. Base UI Menu manages keyboard focus and dismissal. Menu deletion retains the exiting tile until the full popup exit finishes.

API suggestion fixtures remain test-only; no default sites or fabricated history are included in product code.
