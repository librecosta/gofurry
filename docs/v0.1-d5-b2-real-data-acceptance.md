使用 2026-11-15 真实旧站备份完成了隔离恢复、提取、导入、对账和故障恢复。可迁移数据的首次导入与重放一致。61 条 Logo 引用仍待处置，隔离导入器的最终状态为 `incomplete`。本批地址、分类和发布决议留待确认。

## 备份及恢复

外层为 212,771,397 字节的 Zstandard 压缩 TAR。六个归档成员均符合清单。解包后，`SHA256SUMS` 中五个成员的校验值全部吻合。内层是 PostgreSQL 18.3 生成的未压缩 Custom Dump，格式版本 1.16。验证前后的外层文件 SHA256 一致。

## D5-B1 导入及幂等

初始只读计划找到 25 个 Site 和 66 个 Game 需要合法 slug。隔离执行使用契约允许的固定装饰性 slug `site` 和 `game`，通过明确决议记录。唯一对象身份仍由 UUIDv7 和 16 字符 Public ID 决定。为 184 条合规 Logo 创建隔离绑定决议。最终 Dry Run 后，批次、Site 和 Game 均保持 0 行。

- 创建并逐条核验 742 条稳定映射，涵盖 247 Site、261 Game、16 合集、4 标签类别和 214 标签。524 个应有 Public ID 的对象均通过长度、字符集、唯一性及映射一致性检查。Site 的 494 条、Game 的 522 条、合集的 32 条人工本地化与 Seed 逐值一致。人工标签及类别的 436 条本地化也一致。
- Steam 的 261 条来源按原 Game 归属，核对 AppID、规范商店 URL 和激活状态。主验收库没有合并实体。Steam 元数据投影为空，5,053 条人工标签关联进入专用人工关系。
- 合集的 69 条人工成员与顺序、28 条动态规则、0 条源排除逐条一致。用 Seed 独立计算出 524 条有效成员关系，与 SQL 视图完全一致，其中 455 条只来自动态规则。
- 保留了 22 个 Site 的明确归档、34 个 Site 的成人标记和 63 个 Game 的成人发布阻断。未归档 Site、Game 和合集保持草稿。地址证据、旧精选与分类按冻结规则留证，实际正式主备地址、分类和公开记录均为 0。
- 首次写入产生 1 个批次和 1,225 条阶段回执。一轮 `apply`、同计划再次 `apply` 与 `verify` 用时分别约 16.5 s、6.5 s 和 4.6 s。第二次导入前后 21 张表的内容指纹完全一致。各目标身份、关系、revision、回执与对象数均未增加。

## 故障恢复

以下测试在独立目标或 Seed 副本上使用同一真实输入。人为注入的条件只用于验证故障路径。

| 场景 | 结果 |
| --- | --- |
| 已提交事务的响应丢失 | 在 PostgreSQL 发出第 6 个 `COMMIT` 成功响应时断开连接。库中已有 6 条回执和 6 个 Site 映射。相同计划重试复用这 6 组 UUIDv7 和 Public ID，补足其余 736 个身份。 |
| Logo 的 S3 写入成功、CDN 返回 503 | 首轮只绑定 183 条。第 184 个引用没有入库，已写的对象仍存在。恢复后只补一条绑定，复用全部 181 个对象。 |
| 损坏 Seed | 修改已封包副本的一行，预检拒绝。主目标的 21 张表指纹保持一致。 |
| 已有 Steam 持有人与合集依赖 | 注入使用同 AppID 的既有人工 Game。导入报告来源冲突，对应合集的人工成员和规则整组等待。配置隔离测试的显式采用决议后，复用原身份与唯一来源，原编辑资料、revision 和标签保持原状，合集恢复。停用来源的变体也保持停用。 |
| 人工编辑保护 | 使用现有 `site-profile` CLI 修改一条已导入 Site 的英文长介绍。重放产生一条 `editorial_conflict` 并保留实际编辑与 revision。 |
| 显式排除优先级 | 真实备份的排除行为在独立事务内补充验收。选取一条真实规则命中的 Game，新增排除后视图立即去掉该成员，随后回滚测试事务。 |

首次运行中的本地 S3 替身需要接受 SDK 的 `x-id` 查询参数。修正验收环境后从新目标库重跑。真实数据运行未发现需要修改 D5-A 或 D5-B1 程序的缺陷，Schema、清洗与业务映射规则沿用冻结版本。
