## Focused checks

- `task tools`, pinned Go formatting, `go vet`, `task check:api`: passed. API build succeeds on Go 1.27.3 without JSON experiment flags.
- JSON v2 tests: Fiber adapters, UTF-8 and exact integer round trips, jsontext raw values, null collections, HTML escaping, malformed/duplicate/invalid-UTF8/trailing input and existing HTTP error envelope pass.
- YAML/CLI tests: missing flag/file, malformed YAML, missing/unknown fields, bad listener/duration/region, environment overrides being ignored, CN/INTL configuration, actual listener startup, same-file healthcheck and graceful cancellation pass. Query parameters cannot change deployment region or SFW metadata.
- Log policy tests: fast health/success requests are silent in production; slow requests and errors remain. Lifecycle logging and request-ID correlation are preserved.
- Web production build and TypeScript: passed. Seven CN tests cover no-JavaScript SSR/CSS, cookies, manual themes, hydration, bilingual controls, Popover/focus, routing and probes. Three focused INTL tests verify default English and access to both locales without region changes.
- HMR/Fast Refresh: passed with browser console errors checked. State and open Popover persist while StyleX/text update. Main local ports verified as 17320/17321; API CLI healthcheck and development `/api/v1/status` proxy return 200 with CN/SFW policy unchanged.
- Docker Compose configuration, independent Web/API builds and disposable container checks: passed on Linux amd64 using the pinned official Node/Go images via their ECR mirror. Inspected read-only explicit YAML mount, no old API business environment variables, `local` driver 5m × 3/compression, healthy probes, bounded production access logs and SIGTERM exit 0 / close hooks for both services. Smoke resources were removed afterward.

## Boundaries and compatibility notes

- Config schema is shared between local/API containers; examples differ only in values. Private config.yaml files are ignored and never baked into images. `--config` is required even for healthcheck; its listener port is derived from the same YAML. No environment lookup, .env loading, source merging or schema/migration work was added.
- Cookie preferences do not select a region. Deployment is CN/INTL, with zh/en available in either; no current user data or cross-region readers exist. CN remains permanently SFW; INTL NSFW and all business/auth/storage features remain deferred. Operators must pair each Web deployment with API/configuration/data in the same region.
- Source tokens were read from the existing Submodule's fixed `b186325` commit. Only consumed global roles were adapted; old source and gitlink are untouched. Fonts are bundled locally, without LESS/Nuxt/Tailwind dependencies.
- First font integration exposed a StyleX multi-CSS hash discrepancy. Consolidating fonts in the existing root CSS entry fixes actual SSR asset loading. Optional StyleX `data-style-src` debug attributes are disabled through its supported option because Start transforms shift SSR/client source lines; HMR/dev classes remain active, with no third-party patches or hydration-warning suppression.
- Local browser checks used installed Chrome via `PLAYWRIGHT_CHANNEL=chrome`; CI installs pinned Chromium. Existing Nitro beta / Rolldown third-party `use client` notices remain. No unrelated multi-browser/business test matrix, production deployment, host daemon change or legacy-site edit was performed.
