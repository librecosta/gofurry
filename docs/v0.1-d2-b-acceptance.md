Implementation commit [`0b9622780ff5b78c33fa1ecaa372d29fb1e2d79e`](https://github.com/librecosta/gofurry/commit/0b9622780ff5b78c33fa1ecaa372d29fb1e2d79e) · [GitHub Actions on that commit](https://github.com/librecosta/gofurry/actions/runs/43173715721)

## Delivered

- `/sites` brings together catalog search, up to three populated editorial slots, the weekly chart, recent additions, eight fixed categories and an optional random pick. The weekly chart preserves each site's original Heat v1 rank after excluding featured sites. New additions follow first publication time.
- `/sites/directory` renders 24 results on the server. Search, category, tags, language and sort use shareable URL parameters. Filter changes work with IME composition, browser history and the mobile filter sheet. Loading more uses the existing opaque cursor, rejects stale responses and offers a refresh that preserves the current filters.
- Site names open canonical GoFurry detail URLs. A separate native link opens the reviewed primary address in a new tab. It remains usable when the existing anonymous click endpoint fails. Discovery does not count cards as detail views.
- Each regional deployment reads its own reviewed SFW catalog. CN serves Chinese at the default path and English under `/en`. INTL serves English at the default path and Chinese under `/zh`. SSR supplies localized titles, descriptions, canonicals and language alternates. Filtered URLs are `noindex,follow`. Invalid locales return 404, normalized aliases return 301, valid empty results return 200 and catalog outages return 503. Existing Site detail and Yearbook routes retain precedence and behavior.

## Schema and operation

Goose `202611120002_site_assets.sql` adds two nullable, checked object keys to `sites`. It adds no table, foreign key, cascade or index. Existing rows remain valid and show deterministic fallbacks until an asset is bound. Catalog reads project the active primary address and logo from the existing bounded queries. Only editorial cards project covers. Image requests go directly to the configured `storage.public_base_url`.

Run the migration explicitly in each intended environment before deploying the new API. The old API can run with the additive schema if a binary rollback is needed.

```sh
task migrate ACTION=up CONFIG=/path/to/private-api.yaml
go -C services/api run ./cmd/api site-assets import logo /path/to/logo.webp --preflight --config /path/to/private-api.yaml
go -C services/api run ./cmd/api site-assets import logo /path/to/logo.webp --confirm-reviewed --config /path/to/private-api.yaml
go -C services/api run ./cmd/api site-assets bind PUBLIC_ID REVISION logo OBJECT_KEY --confirm-reviewed --config /path/to/private-api.yaml
```

Use `cover` and an AVIF file for an editorial cover. An operator confirms publication rights and content review. Import accepts a square still WebP up to 1024 × 1024 and 1 MiB or an exact 16:9 still AVIF up to 2560 × 1440 and 4 MiB. The CLI decodes bounded bytes, calculates SHA-256 and creates the object conditionally under `sites/logos/` or `sites/covers/`. It checks metadata, stored bytes and the direct HTTPS CDN response. Binding rechecks the object and uses the current Site revision. Pass `-` as the key to clear the reference. To roll back an assignment, bind the previous key with the latest revision. Unbinding leaves the immutable object available at its existing CDN URL.

## Local performance and resources

`NAVIGATION_MEASURE=1 task check:catalog` seeded active primary addresses on all synthetic Sites and a logo key on every fourth Site. These are single-machine PostgreSQL 18 measurements with seven daily Heat records per Site. Warm directory times are averages of 20 filtered ranked reads. Discovery is the measured full home feed.

| Published Sites | First directory read | Warm filtered directory | Discovery |
| ---: | ---: | ---: | ---: |
| 100 | 6.85 ms | 6.05 ms | 6.01 ms |
| 1,000 | 9.00 ms | 13.64 ms | 8.02 ms |
| 10,000 | 20.83 ms | 81.76 ms | 27.89 ms |

The separate browser fixture returned 13,715 B of discovery JSON (3 featured, 8 trending, 8 recent) and 15,400 B for the 24-result directory. The two loopback API reads took 28.4 ms in total. Chromium decoded 48,773 B of homepage HTML and recorded 14 ms to first byte and 128 ms to `DOMContentLoaded`. The page used one priority cover (3,602 B in this fixture) and lazy logo elements (526 B for the fixture logo). The directory contains no cover images. Each populated PostgreSQL key contains 81 or 82 ASCII bytes plus row storage overhead. Site media adds no per-card database round trip or object HEAD request on the public read path.
