# GoFurry VNext D1-A — Site / Game Identity & Public URL Contract

Status: **Design frozen / implementation scope**. Date: 2026-11-11. Repository: `librecosta/gofurry`, **develop** only.
Source references: legacy `gofurry/gofurry-nav-site` (`dev`), new GoFurry's `AGENTS.md`, `.agents/architecture.md`, `apps/web/src/locale-path.ts`, `services/api`, wallpaper migration and admin boundaries. The new site currently has no Site/Game production schema. Harvest V0.1-D has independently implemented Web and Steam Providers; do not copy their internal implementation or DB schema into GoFurry.

## 0. Product and scope

GoFurry continues to have **two** core business domains: **Site** (navigation) and **Game** (games). No global `content` supertable, no third public "observations" domain, no independent "collection directory" service. Domain records belong to the GoFurry regional PostgreSQL; Harvest separately owns Targets, Schedules, Permits, Observations and their bounded history.

D1-A is concerned with **identity**, **minimal content foundations**, **canonical public URLs** and **future-compatible external identities**.

D1-A includes:
- UUIDv7 internal PKs, random stable Public IDs and canonical slugs for Site and Game.
- Minimal draft/publish/archive lifecycles and zh/en display text.
- Website primary/alternate addresses and game source-platform identity records, with no assumption that one Game equals a Steam AppID.
- Read-only public data contracts and canonical SSR URL behavior; internal business service/DB integration tests.
- A **specified**, not necessarily populated, legacy numeric ID migration map and redirects; the actual old-site data import follows in a dedicated migration stage.
- Reserve a stable **Site Yearbook URL**; do not generate yearbooks in D1-A.

Not in scope: Harvest binding/Consumer/Schedule (D1-B integration work), Site fact aggregation/yearbooks (D1-B or separately named follow-up), all legacy `gfn_collector_*`, `gfg_game_v2_collect_*`, change/metric engines, UGC/comments, Steam/itch.io crawling, new Admin UI, GoFurry CN→INTL Sync, complete game tag taxonomy, recommendation systems or site category editorial UX. No premature generic CMS or platform registry.

Existing wallpapers, Start, login boundaries, storage and Redis must remain intact.

## 1. Three identities, three purposes

### Internal database key

- `sites.id`, `games.id`, and new domain entity IDs use Go 1.27 `uuid.NewV7()` with PostgreSQL `uuid`. No auto-increment, `serial`/`bigserial`, timestamp-derived public IDs, Redis-issued IDs, Snowflake or Steam AppID-as-PK.
- Internal UUIDs are not part of public canonical URLs; cross-domain FK integrity is enforced within a regional GoFurry DB.

### Public ID

- `public_id` is independently generated from `crypto/rand`, exactly **16 lowercase Crockford-style Base32 characters** using alphabet `0123456789abcdefghjkmnpqrstvwxyz` (80 random bits). Implement unbiased uniform index generation, unique DB constraint, collision retry on unique violation; no deterministic encoding of the internal UUID, creation date, sequence or old numeric ID. Generate once at creation; never regenerate on title/slug/platform/domain changes, archival or import.
- Public IDs are immutable, unique within each entity type (a shared ID namespace across Site/Game is unnecessary because URLs are typed). Do not reuse archived IDs.
- Public ID reduces sequential enumeration; **it is not a security authorization control or a guarantee against crawl discovery**. Legitimately published URLs appear in site maps/internal links, and public reads remain rate-limited and cacheable.

### Slug

- One canonical, editable, **language-independent** ASCII slug per Site/Game: `[a-z0-9]+(?:-[a-z0-9]+)*`, 1–80 characters, lower-case. Derive an initial candidate from an available canonical Latin/English label when safe, or require a short explicit operator slug; do **not** invent Chinese transliteration. Avoid classifying a user-provided slug as a filesystem path or request URL.
- Slugs are **not globally unique**. They are decoration, not lookup authority. Resolve by Public ID only, compare slug to current canonical slug and send a single permanent redirect for published content if mismatched. Old slugs need no dedicated redirect table.
- Locale-specific titles change independently; they do not mutate canonical slug unless an editor explicitly changes it.

## 2. URL contract and HTTP semantics

Canonical path shapes:
- `/sites/{public_id}/{slug}`
- `/games/{public_id}/{slug}`
- `/sites/{public_id}/{slug}/yearbook/{yyyy}` (reserved D1-B; must not publish an empty placeholder)
- `/sites/{public_id}` and `/games/{public_id}` redirect to current full canonical path if published.

Apply the **existing** `localizedPath(pathname, locale, region)` rules: CN default zh unprefixed and `/en/...`; INTL default en unprefixed and `/zh/...`. The path structure and Public ID remain identical across regional projections; hostname differs. No cookie/IP/browser-language redirect of an explicit localized URL.

Public GET:
- Published and locally allowed content => 200 SSR, correct title/description, canonical URL and hreflang only for actual published translation/region alternatives. Missing locale text must be **explicitly omitted/unavailable**, not silently fabricated. Preserve title and site/game identity if another valid locale is visible; do not auto-translate source descriptions. A language missing its publishable content must not produce fabricated translated SEO metadata.
- Known published Public ID with old/wrong slug => 301 to current canonical path, preserving locale and **safe** intended URL structure; no arbitrary user-supplied open redirect.
- Unknown, invalid, unpublished or disallowed Public ID => no public metadata leakage; return real 404, not fallback to a different site/game. For archived content, policy must be explicit and consistent; initially 404 for current detail, while future intentionally published yearbooks may remain reachable by their own policy.
- Backend unavailable => 503, not 404 or empty successful result. Public SSR must read GoFurry's own DB/API only, never call Harvest per page. Current `__root.tsx` uses private/no-store for Start preference routes: avoid accidentally inheriting inappropriate cache/head behavior for indexable Site/Game pages; make status/head/cache policy explicit and verify in tests.
- Canonical, sitemap and internal navigation use only the current Public ID + Slug. No slug-only route. No sequential next/previous ID controls. Public listing uses reviewed filters and cursor/page semantics, not raw DB identifiers.

Legacy routes from `gofurry/gofurry-nav-site`:
- old primary Site: `/site/{positive_numeric_id}`, old alias `/sites/{positive_numeric_id}`;
- old Game: `/games/{positive_numeric_id}`.
- On the **new site only after an explicit audited migration map is populated**, legacy numeric routes redirect once to a matching new published entity canonical URL. Preserve localized prefix; archived/unmapped => appropriate 404/410 per later migration policy. Old numeric IDs are never treated as new Public IDs, and no automatic arithmetic mapping is allowed.
- Specify durable old-key -> new-UUID/Public-ID mapping in the migration plan; no importing old database connections, old numeric PKs, or old data in D1-A. Do not create redirect stubs that misrepresent legacy URLs before mapping exists.

## 3. Site domain — minimal real model

A Site represents **a curated website/community/service identity**, not one domain name, IP address, Harvest Origin or DNS record. Its UUID/Public ID survive domain moves and ownership/editorial content changes. Two websites can share infrastructure/hostname; do not deduplicate sites by root hostname or a simplistic registrable domain.

Recommended minimal persisted facts (SQL design may express localized texts in compact separate child rows):
- `sites`: internal UUIDv7, immutable `public_id`, `slug`, lifecycle status `draft|published|archived`, optimistic `revision`, created/updated/published/archive timestamps.
- `site_localizations`: `site_id`, `locale` (zh/en), curated name and optional bounded summary. Exactly one entry per locale, no unbounded raw HTML; publishing validates at least one usable locale and SEO route behavior for the other. No automatic fallback mislabeled as a translated value.
- `site_addresses`: distinct HTTP(S) business navigation URLs, with one active `primary` address per published Site and optional `alternate` URLs. URL may include a meaningful path/query: do not assume the business URL equals the Harvest root Origin. Reject userinfo, control characters, dangerous schemes, fragments or credentials; normalize host/port/case without deleting meaningful paths/query parameters. Address changes do **not** mutate Site identity. Do not create an automatic Harvest Target when an address row is inserted in D1-A.
- Category/group membership, order, curated icons and affiliated links are **Site domain data** and follow later Site taxonomy/Admin work. Do not conflate category with technical fingerprint.

For simplicity, no generic cross-domain `resources` supertable and no `content_entity` registry. Do not add a site-to-domain history event ledger until the D1-B evidence contract; the Site address changes themselves use standard revision/audit semantics.

## 4. Game domain — identity independent of Steam

A Game is a curated **game work/product** with UUID/Public ID and bilingual editor text, independent of any platform or a Steam AppID. It may exist before any collectible upstream is configured.

Recommended minimal persisted facts:
- `games`: UUIDv7, stable Public ID, slug, lifecycle, revision and timestamps.
- `game_localizations`: bounded zh/en curated name and summary, without silently copying upstream text into operator-written descriptions.
- `game_sources`: an *external platform identity*, with FK `game_id`, `platform_code`, validated `external_key`, optional authoritative source URL, source state and explicit primary/presentation preference if one is needed. Unique normalized `(platform_code, external_key)` when it denotes the same platform object, with manual conflict handling; the actual platform identity is not the Game PK.
- Steam: `steam` code + validated positive uint32 decimal AppID, canonical decimal string and official Steam URL as a **link**, not a second identity. Steam details, price, news and players later originate from Harvest `steam.app` and will be imported only after the D1-B contract. Do not couple a Game to exactly one Steam listing by schema.
- Future platforms (itch.io, Epic, own distribution): keep `platform_code` open for **reviewed**, typed integration/links; do not pretend Harvest supports their providers today. A game can have multiple source rows. No automatic inference of demo/DLC/parent-package equality from one title or one source result.
- Tags, creator relationships, game collections, recommendations, showcase, prices and player samples are separate later domain data, not mandatory nullable columns on `games`. Do not migrate old `gfg_game` every field now.

## 5. Publishing, editing and security

- The GoFurry regional PostgreSQL is the **sole owner** of Site/Game editorial content and publication lifecycle. Harvest owns ingestion facts and quotas only; LibreCosta Admin is a separate authenticated internal product and will call explicit GoFurry management APIs in a later stage. **Do not expose unauthenticated Site/Game mutations in D1-A**.
- Use a small internal domain service/repository for creation and updates, tested with isolated fixtures. Publication requires a canonical slug, usable display name and at least one valid primary URL (Site); Game must have a curated name but **does not require Steam**.
- `draft`, `published`, `archived` lifecycle and optimistic revisions; archive retains UUID/Public ID/history. No cascade physical delete of source identities or yearbook ancestry. Audit writer attribution will be integrated with Admin's verified actor protocol later; do not fabricate actor identity.
- Preserve regional policy: CN permanently SFW; INTL is independent but currently has no live NSFW content. Do not implement new moderation, NSFW data publishing, UGC or regional keyword bans under an identity migration.
- Regional databases and local UUIDs may differ. The *same approved shared editorial entity* carries the **same** immutable Public ID and canonical slug in CN and the reviewed INTL projection. The CN→INTL publishing projection will map public identity to region-local row IDs without cross-DB foreign keys, direct remote DB queries or user data transfer. INTL-only editorial resources may originate there; never auto-merge entities just because title/domain/AppID matches. No Sync implementation in D1-A.

## 6. Yearbook URL commitment and D1-B handoff

The reserved canonical annual URL belongs to the **Site identity**, not its present hostname. All historical Web Observations, source domains and ownership periods need to map to that Site in the **later** Collection/Fact contract.

A 2026 Site Yearbook may be generated after UTC 2026 closes; it is not published without sufficient time coverage and verifiable evidence. No empty SSR yearbook placeholders or synthesized annual "availability" figures.

Harvest's default event retention is 14 days and history/samples 30 days. D1-B must use consumer ingestion, **long-lived compact semantic facts**, sampled-coverage summaries and evidence/version provenance, rather than annual queries against Harvest or duplicating all raw response bodies. Do not count `/changes` events as total successful samples. Reported change first-observed time is not necessarily real deployment time. Fingerprint rule upgrades must not be reported as mass live site migrations.

## 7. Legacy data and tests

The old Site and Game identities are numeric. Old schema also embeds collection tables, HTTP/DNS logs, snapshots, metrics, contest and historical data. D1-A will NOT import them as new schema or use old DB as canonical source. Create a **migration mapping specification** (type + legacy positive ID -> new immutable Public ID) and seed deterministic mock mappings in tests; real reconciliation, backup and import belong to migration stage.

Mandatory deterministic checks:
1. 10k+ UUIDv7 and random Public ID generations: format/entropy tests; verify Public IDs are not sorted/predictable by create-time/sequence, uniqueness collision handling, immutable update policy and no accidental public UUID exposure.
2. Public ID + slug normalization, collisions, deliberate slug rename, canonical 301 with same locale, malformed/unknown/unpublished ID 404 and database outage 503.
3. CN zh /en and INTL en /zh prefix behavior, SEO title/canonical/hreflang only for published locale, no cookie-based language redirect, stable public identity in two independent DB fixtures.
4. One Site with primary/alternate URL, address changing without Site identity mutation, path-containing site URL; do not mistakenly equate business URL with Harvest Origin or use hostname as unique Site key.
5. One Game without Steam, one with Steam + another manually recorded source, duplicate AppID across games rejected, invalid/zero/out-of-range AppIDs rejected. Game identity stable after Steam source removal.
6. Archive and revision conflicts do not delete identity or allow unpublished data to leak in public lists/routes. Field-source precedence is not invented in D1-A.
7. Legacy numeric route example mappings redirect to canonical URL; unregistered/unmapped/archived legacy IDs never reveal a record. No mandatory live old-DB dependency.
8. Goose forward migrations, sqlc type mapping, FK/unique/partial indexes, PostgreSQL 18 isolation, Go 1.27.3 and Fiber route inventory. Existing wallpaper rows, Start routes, auth boundaries and HTML cache behavior must remain intact.
9. Public frontend SSR smoke verifying real 200/301/404/503 and stable metadata, no Harvest fetch on request, lightweight pages without full content/UI redesign. API failure does not silently become empty success.
10. `task check` / targeted DB integration and browser tests; none of the tests reset the shared durable developer databases.

## 8. Delivery boundary

Deliver a narrow D1-A foundation in **librecosta/gofurry/develop**, using existing `services/api` Go module, Fiber routers, pgx+sqlc, explicit Goose migrations and `apps/web` TanStack Start patterns. If implementing the entire frontend catalog/listing UI would expand scope, deliver tested read models and functional SSR detail route shells rather than redesigning navigation or games UX.

No new repo, service or cross-product Go module; no shared collector DB; no auto-created Redis or DB instances. No production migration or updates to `admin`, `harvest` or legacy repo.

Write concise `docs/v0.1-d1-a-acceptance.md` with actual tests, sample canonical localized URLs, one Site and Game fixture, region isolation and known limitations. Commit to develop. Do **not** tag/publish a release without approval.

After D1-A acceptance, the next design step is **D1-B — Harvest Binding, Evidence Aggregation & Site Yearbook**, with a careful separation of lightweight collection bindings, independent Change Stream consumer, long-term fact events/coverage and annual public artifacts.
