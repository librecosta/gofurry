## 数据库与运行

- 新增 Goose 前向迁移 `202611130001`。`game_approved_presentations` 每 Game/语言保存已批准名称、简介、来源、Observation 和规则证据。人工本地化按语言优先。失效、撤稿、重建或来源变更无法清空已批准快照。可信的同源资料变化可刷新自动快照。
- `catalog_publication_decisions` 按实体 revision 保存操作者、原因、动作和时间。Site 分级沿用 `site_navigation_reviews`。`site_public_navigation` 与相关索引移除必填分类条件。`site_technology_snapshots` 按绑定和 Scope 保存紧凑的 HTTP、TLS、技术指纹和撤稿状态。每个资料页最多显示五条。原迁移、Public ID、资产、年鉴修订和 Start 样式保持原状。
- 部署时先用各区域显式 YAML 执行 `task migrate ACTION=up CONFIG=<region.yaml>`，再启动匹配的 API 和 Web。此次迁移仅在一次性数据库执行。验收从 D3-A1 Schema 开始，回填过期记录、保留旧撤销，再重复执行迁移确认幂等。
- 用同一显式 YAML 运行 `catalog-publication diagnose` 查看缺失展示资料的已发布 Game、以及仍只开放兼容详情的旧 Site 数量。已有可信分级记录时可用 `--inherit-legacy-sfw` 每次继承最多 128 条。普通 Site 可在 `catalog-publication set site PUBLIC_ID REVISION publish` 使用 `--confirm-sfw --actor … --reason …` 一次记录来源和发布。明确成人处置沿用 `navigation review --keep-taxonomy`；Game 解封使用 `catalog-publication set game PUBLIC_ID REVISION clear_block`。状态操作要求 revision、actor 和 reason。

## 实际检查

- `task check:catalog` 通过。Go catalog、yearbook、navigation 集成测试使用 PostgreSQL 18.6、Redis 8.2.1。Playwright 的 Catalog/Yearbook 13 项及 Sites/Profile 9 项通过，包含两区域 SSR、重定向、真实 404/503、可访问性和图片回退。Site Profile 样本约 19.2 KB，本地端到端约 20 ms，SSR 保持 1 次区域 API 请求。
- `task check:collection` 通过。运行真实 GoFurry、固定版本 Harvest V0.1-D 及模拟上游，覆盖 Consumer 410、暂停快照、Harvest 服务停止、HTTP 500、PostgreSQL/Redis 暂停与恢复、一次性 Job、持续更新和 10,000 条 Candidate 准入回归。分页快照样本 157 ms，采集联调向模拟上游发出 24 次真实请求。公开浏览无实时 Harvest 请求。另行验证了原始投影清理后历史 HTTP 证据仍可读，未知规则集和撤稿 TLS 被排除。
- Go vet、单测、构建、`task sql:check`、Web 构建与 TypeScript、SCSS Modules/React HMR 两项通过。`task check:web` 通过 88 项，3 项需显式开启的真实本地天气 API 测试按既有配置跳过。Windows 本地 Docker Hub token 端点超时，使用相同版本的公共 ECR 基础镜像完成 Compose 构建与容器冒烟，确认非 root、探针和 SIGTERM。

## 遗留

- D3-A2 仍负责首次自动分类、Steam 发现及完整资料投影。缺少正面证据的候选维持原安全边界。
- 旧 Site 缺可信 SFW 记录时继续只公开兼容详情和年鉴。旧 Game 缺人工或可恢复的已批准资料时保留身份，页面明确显示名称及简介不可恢复并使用 noindex。实际数量需在目标环境显式迁移后诊断。
