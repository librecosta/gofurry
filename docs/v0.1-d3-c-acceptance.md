# V0.1-D3-C 游戏详情、媒体与平台观测验收

## 交付

- 游戏详情沿用 D1 的 Public ID 与规范路径。CN、INTL 根据路由语言 SSR 名称、简介、来源和 SEO。旧 Slug 返回 301，草稿、归档及被封禁作品返回 404，数据库断开时返回 503。无译文的路由保留来源语言并标记 noindex。
- `GET /api/v1/games/:publicID` 保留原 DTO。`?profile=1&locale=…` 增加发行来源、发行日期精度、平台资料、媒体、按 AppID 和商店区独立呈现的有效报价、采样时间、首批官方动态及最多六条相关游戏。推荐依据公开合集及受控类型交集。
- `/news` 使用发布时间、GID 和 AppID 组成键集游标，每页六条。官方动态按 AppID/GID 去重，只显示标题、发布时间与官方链接。
- `/insights` 按需读取单个 Steam AppID、单个商店区的历史，支持 7、30、90、365 个 UTC 日。图片和视频画廊在交互后加载，Base UI 处理全屏 Escape 与焦点恢复，视频使用原生控件。价格和玩家图提供键盘刻度、触屏读取和观测明细。

## 数据来源与留存

Goose 前向迁移 `202611150001_game_insights.sql` 增加两张业务表和相关索引，沿用 UUID 与有效时间绑定。

- `game_player_daily` 每个来源、出口及 UTC 日保留最多 48 个实际半小时桶的最新采样及证据 ID。日均值和采样最大值从这些桶计算。0 是实际观察到的 0，缺失日期断开。原始 30 天记录按原规则清理，长期日记录继续保留。
- `game_price_observations` 按来源、出口、商店区、币种和来源语言记录实际发生的成功报价。单日每组最多保留 96 条观测，按真实时间选取日末报价。相同 Observation 重放不写新记录，相同价格重复确认不形成变化。变化时间表示采样观察到变化的时间。缺价和采集空白保留为未知，free 与有币种的 zero_price 独立呈现。
- 两类历史仅以观测发生时生效的绑定归属写入。历史事务随 Consumer 位置提交、ACK 重试与 410 快照重建。迁移可回填仍有证据的现存价格及半小时桶。来源停用后，已积累的证据及持久资料仍可读。人工名称和简介优先。当前报价与当前玩家样本分别使用 48 小时及 2 小时边界。
- 时间线使用已确认的 Steam 价格变化及 Steam 新闻发表时间。itch.io 仅展示可信的官方作品链接。既往多年价格、玩家与发行变更资料留给有实际证据的 D5 回填。

## 实测

- 隔离 PostgreSQL 18.6、Redis 8.2.1、固定 Harvest `349730b5c3ff57be084dfac72dfb77f19dacb54c`。模拟 Steam 购物区及官方 API 经过真实 Harvest Worker、Consumer 和数据库。验证了 US/USD 从零价变为 1,499 分只生成一次变更，CN/CNY 免费、HK/HKD 缺价及零玩家数据相互独立。浏览器夹具另覆盖 HKD 有价报价和双 Steam 来源。
- 真实 Harvest 联调验证丢失 ACK、事务回滚、重放、410 重建及采集端恢复。六路并行重放保持价格证据未重写。来源解绑、31/181/365 日窗口和原始桶清理后，基础资料、封面和有效历史仍可读取。显式封禁覆盖详情与历史边界。
- 桌面 1,280px 与窄屏 390px Chromium 验证明暗主题、双语 SSR、无 JavaScript、目录返回、画廊键盘全屏、失效媒体、视频非自动播放及移除、新闻分页、图表缺口、键盘取值。截图由 `game-profile.spec.ts` 输出到隔离 Playwright 报告目录。
- 本地运行 `task check:api`、`task sql:check`、`task check:catalog`、`task check:collection`、`task check:web`、`task check:hmr` 和容器启动、健康及 SIGTERM 检查。本机 Docker Hub 认证网络失败，镜像构建改用同版本官方公共 ECR 镜像。最终 GitHub Actions 以 `develop` 同提交的 Foundation checks 为准。

## 性能

Windows Docker 上预热后每项 12 次测量，样本为 100、1,000、10,000 个游戏。约 20% 的工作负载有真实格式的稀疏历史夹具，每个有历史的作品含 15 个玩家观察日和 10 个 USD 报价日。下表测量 Go 服务调用，包括 PostgreSQL 往返和 DTO 构造。

| 游戏数 | 详情加相关推荐 P50 / P95 | 30 日 Insights P50 / P95 | 两张历史表及索引 |
| ---: | ---: | ---: | ---: |
| 100 | 4.8 / 13.3 ms | 4.7 / 7.1 ms | 229,376 B |
| 1,000 | 8.4 / 10.0 ms | 5.0 / 6.2 ms | 1,286,144 B |
| 10,000 | 42.4 / 47.4 ms | 4.7 / 4.9 ms | 11,878,400 B |

10,000 游戏时单次详情分配约 14 KB，Insights 约 28 KB。画廊和 Insights 各自使用延迟加载的前端块，生产构建中分别约 9 KB 和 7 KB 未压缩，另复用现有运行时。浏览器验证初始页面不请求大图画廊或视频。容量测量基于夹具，真实多年度存储与 CDN 表现要等运营观测。下一阶段进入 D4 — Admin & Operations。
