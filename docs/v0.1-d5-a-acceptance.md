# D5-A 旧站审计与候选 Seed 验收

使用 Go 1.27.3、一次性 PostgreSQL 18 和合成数据完成验收。三份合成 Schema 经 `pg_dump -Fc` 和 `pg_restore --no-owner --no-acl` 恢复后运行实际 CLI。真实旧站备份和 Logo 镜像仍由用户保管。

## 实测

- `task check:legacy-seed` 覆盖 `inspect / extract / verify`，GFN 七张表、GFG 十一张表及 GFA 类型计数。夹具含中文、缺翻译、上海时间、软归档、旧成人证据、重复 AppID、开放与历史主目标、孤儿关系、主次标签、合集规则/排除、旧第五槽和排除发行证据对账。
- 同一输入两次成功提取的内容 SHA256 相同。PostgreSQL 容器停止后仍完成离线校验。额外文件、内容篡改、错误 Schema、带写权限的账号、数据库配置串用及危险路径有自动检查。连接失败和公开汇总不包含凭据或候选数据。
- Logo 夹具包含有透明度的非正方形 PNG、JPEG、AVIF、原样保留的 WebP、旧键 SHA 前缀不匹配、损坏、APNG、SVG 和符号链接。两条有效合成 Logo 引用产出一个经过现有 SiteLogo 验证器的 WebP。缺失和拒绝项保留 Site。
- Windows 本机 Ryzen 7 5800H 的 96×40 透明 Logo 编码和复验约 7–18 ms/次，Go 总分配约 5.3 MB/次。三档 PostgreSQL 夹具含 Logo 和离线自校验，范围见下表。堆取样每 5 ms 一次，包含 Go 测试运行器和抽取器，且不含 PostgreSQL 容器 RSS。

| 合成 Site 行 | Site NDJSON 字节 | 提取加复验 | Go 堆取样峰值 |
| ---: | ---: | ---: | ---: |
| 100 | 79,599 | 0.21 s | 9.2 MB |
| 1,000 | 795,102 | 0.30 s | 8.6 MB |
| 10,000 | 7,977,105 | 1.17 s | 8.6 MB |

本地通过 `task check:api`、`task sql:check` 和 `task check:legacy-seed`。GitHub Actions 的 `legacy-seed` job 在自身 PostgreSQL 容器重做恢复、抽取和验证，工作流不上传 Seed 或媒体。 [develop 的检查记录](https://github.com/librecosta/gofurry/actions/workflows/check.yml?query=branch%3Adevelop)

## 命令和私有 YAML

从仓库根目录构建。Windows 使用 `bin\legacy-seed.exe` 或直接在根目录运行 `go -C services/api build -o ../../bin/legacy-seed.exe ./cmd/legacy-seed`。

```sh
go -C services/api build -o ../../bin/legacy-seed ./cmd/legacy-seed
./bin/legacy-seed inspect --config .local/legacy-d5.yaml
./bin/legacy-seed extract --config .local/legacy-d5.yaml
./bin/legacy-seed verify --config .local/legacy-d5.yaml
```

私有配置示例。将 `backup_sha256` 替换为独立核对的完整旧备份归档 SHA256，填入隔离读取账号的专用密码。三库必须是独立的 `legacy_d5_` 命名，`gofurry_database` 填新站当前库名用于拒绝同名连接。示例使用固定地址，网络隔离方式见下一节。

```yaml
snapshot_id: legacy-2026-11-15
backup_sha256: aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa
gofurry_database: gofurry_cn_dev
# output_dir: /private/d5/seed
# offline_logo_dir: /private/d5/legacy-object-mirror
gfn: {host: 127.0.0.1, port: 5432, name: legacy_d5_gfn, user: legacy_d5_reader, password: "FILL_PRIVATELY"}
gfg: {host: 127.0.0.1, port: 5432, name: legacy_d5_gfg, user: legacy_d5_reader, password: "FILL_PRIVATELY"}
gfa: {host: 127.0.0.1, port: 5432, name: legacy_d5_gfa, user: legacy_d5_reader, password: "FILL_PRIVATELY"}
limits:
  max_source_rows: 250000
  max_package_bytes: 1073741824
  max_logo_objects: 5000
  max_run_seconds: 900
```

- 源主机只接受 `127.0.0.0/8` 或 `::1` 字面量。清除当前工具进程继承的 `PG*` 配置项。会话锁定 UTC，每库分别显式开启 `REPEATABLE READ READ ONLY`。事务之间的同源性取决于操作者使用同一个冻结备份和禁止恢复后写入。
- `output_dir` 默认是仓库根目录下已忽略的 `.local/legacy-seed`，也可用绝对路径或 `--output` 指定。源镜像和输出目录必须分开。Linux 新建目录/文件权限为 0700/0600。Windows 使用私有父目录并检查继承的 NTFS ACL。工具拒绝路径穿越和符号链接。
- `limits` 缺省采用示例硬上限，可下调。单个源文本/JSON 字段上限 8 KiB，NDJSON 行上限 256 KiB，地址索引中保留的 URL 数据上限 32 MiB。GFA 类型统计有独立 250,000 行上限。PostgreSQL 语句限时 30 秒。工具在失败时尽可能写出脱敏的 `<snapshot-id>.failed/reports/summary.json`，不会覆盖已存在的同名包。
- `inspect` 只写 `<snapshot-id>.inspect/reports/summary.{json,md}`。`extract` 先写私有临时目录，完成离线校验后再固定为 `<snapshot-id>`。`verify` 只读候选包，校验结构、源表/索引行数、源键顺序、引用与异常对账、SHA256、Logo 尺寸与格式。相同内容的哈希忽略 manifest 的运行时刻。外部核对包完整性时，可独立记录工具输出的 `content_sha256`。
- 输出状态 `ready_for_D5_B` 表示候选包通过结构和对账校验。`asset_complete` 单独指示已引用 Logo 是否都成功打包。Logo 空引用只记为 `missing_icon`，跨 Site 对象键、找不到镜像对象、格式不支持或校验失败都会使 `asset_complete=false`。`incomplete` 表示硬错误。
- 唯一素材来源是配置给定的私有镜像。旧对象键按旧写入代码检查 Site ID 和原始 SHA256 前缀。支持静态 PNG/JPEG/WebP/AVIF，输入最多 8 MiB 和 16 兆像素。SVG、ICO、其它未支持格式和动画逐条报告。转换采用等比缩放、居中透明留边与静态 WebP，逐图解码核对 Alpha，再通过现有 SiteLogo 校验器。对象按新字节 SHA256 去重。镜像缺省时保留每条 Logo 引用并报告 `asset_unavailable`。

## 手动隔离恢复

1. 在专用的私有工作目录核对备份归档 SHA256 和清单，核实归档仅含预期成员，每个必需文件只出现一次。将 `gfn.dump`、`gfg.dump`、`gfa.dump`、`manifest.txt` 和 `SHA256SUMS` 作为已点名的普通文件取出，核对每个 dump 的 SHA256，使用 `pg_restore --list` 检查备份格式、PostgreSQL 版本与 SQL 对象。保存 `globals.sql` 作为受限备份资料，恢复命令只使用三个 schema/data dump。
2. 使用确认无误的 PostgreSQL 18 镜像，在临时 Docker 容器及独占卷恢复。可采用 `--network none`，不发布任何端口。把只读 dumps 挂到 `/dumps`，从单独的私有密码文件初始化容器。先拉取并核对镜像，再启动隔离容器。命令中的目录及容器名须改为此次专用值。保留原备份。

   ```sh
   docker volume create legacy-d5-pg-private
   docker run -d --name legacy-d5-pg-private --network none \
     --mount type=volume,source=legacy-d5-pg-private,target=/var/lib/postgresql \
     --mount type=bind,source=/private/d5/dumps,target=/dumps,readonly \
     --mount type=bind,source=/private/d5/container-password,target=/run/private/postgres-password,readonly \
     -e POSTGRES_PASSWORD_FILE=/run/private/postgres-password \
     postgres:18.6@sha256:5a5a84b19854a9ffaa54082c166ff4ec27473a361e496e5ea167f298f2da9722
   docker exec -it legacy-d5-pg-private psql -X -U postgres -d postgres
   ```

3. 在隔离容器的 psql 中创建恢复角色及只读角色。使用 `\password` 交互输入本次专用读者密码，然后退出 psql。恢复过程中如果发现缺失或未预期的扩展及 SQL 对象，先检查归档和隔离环境，再处理兼容性。

   ```sql
   CREATE ROLE legacy_d5_restore NOLOGIN;
   CREATE ROLE legacy_d5_reader LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION NOBYPASSRLS;
   \password legacy_d5_reader
   CREATE DATABASE legacy_d5_gfn OWNER legacy_d5_restore;
   CREATE DATABASE legacy_d5_gfg OWNER legacy_d5_restore;
   CREATE DATABASE legacy_d5_gfa OWNER legacy_d5_restore;
   \q
   ```

   ```sh
   for name in gfn gfg gfa; do
     docker exec legacy-d5-pg-private pg_restore -U postgres --role=legacy_d5_restore \
       --exit-on-error --no-owner --no-acl --dbname=legacy_d5_"$name" /dumps/"$name".dump || exit 1
   done
   ```

4. 为读者按表授权。在隔离容器的 `psql -X -U postgres -d postgres` 执行以下命令。GFA 缺少 `gfa_content_idea` 时跳过该表的授权，GFN/GFG 利用各自 Schema 检查报告结构差异。

   ```sql
   \connect legacy_d5_gfn
   REVOKE CREATE, TEMP ON DATABASE legacy_d5_gfn FROM PUBLIC;
   REVOKE CREATE ON SCHEMA public FROM PUBLIC;
   GRANT USAGE ON SCHEMA public TO legacy_d5_reader;
   GRANT SELECT ON gfn_site, gfn_site_group, gfn_site_group_map, gfn_collector_domain,
     gfn_target_tracking_periods, gfn_site_primary_target_periods, gfn_featured_site TO legacy_d5_reader;
   ALTER DATABASE legacy_d5_gfn SET default_transaction_read_only = on;
   \connect legacy_d5_gfg
   REVOKE CREATE, TEMP ON DATABASE legacy_d5_gfg FROM PUBLIC;
   REVOKE CREATE ON SCHEMA public FROM PUBLIC;
   GRANT USAGE ON SCHEMA public TO legacy_d5_reader;
   GRANT SELECT ON gfg_game, gfg_tag_category, gfg_tag, gfg_game_tag, gfg_game_collection,
     gfg_game_collection_item, gfg_game_collection_tag, gfg_game_collection_exclusion,
     gfg_game_collection_home_slot, gfg_game_first_available, gfg_game_release_state TO legacy_d5_reader;
   ALTER DATABASE legacy_d5_gfg SET default_transaction_read_only = on;
   \connect legacy_d5_gfa
   REVOKE CREATE, TEMP ON DATABASE legacy_d5_gfa FROM PUBLIC;
   REVOKE CREATE ON SCHEMA public FROM PUBLIC;
   GRANT USAGE ON SCHEMA public TO legacy_d5_reader;
   GRANT SELECT (kind) ON gfa_content_idea TO legacy_d5_reader;
   ALTER DATABASE legacy_d5_gfa SET default_transaction_read_only = on;
   ```

5. 使用隔离容器的网络命名空间运行 Linux 版工具。在 Linux 上按上文构建，在 Windows 上为 Docker Desktop 交叉构建 Linux 版，例如 PowerShell 中临时设置 `$env:GOOS='linux'`、`$env:GOARCH='amd64'`，构建后清除。示例中的二进制和绝对路径换为私有实际路径。配置设 `output_dir: /seed`，有镜像时设 `offline_logo_dir: /objects` 并加只读 bind mount。`env -i` 清除 PostgreSQL 镜像继承的 `PG*` 变量。先执行 `inspect`，再执行 `extract` 和 `verify`。在 POSIX 主机上可用自己的 UID/GID 运行并保持输出 ACL。工具容器使用临时文件系统，身份须能读取私有配置并写入 `/seed`。

   ```sh
   docker run --rm --network container:legacy-d5-pg-private \
     --mount type=bind,source=/private/d5/linux/legacy-seed,target=/tool/legacy-seed,readonly \
     --mount type=bind,source=/private/d5/legacy-d5.yaml,target=/private/legacy-d5.yaml,readonly \
     --mount type=bind,source=/private/d5/seed,target=/seed \
     --entrypoint /usr/bin/env \
     postgres:18.6@sha256:5a5a84b19854a9ffaa54082c166ff4ec27473a361e496e5ea167f298f2da9722 \
     -i /tool/legacy-seed inspect --config /private/legacy-d5.yaml
   ```

   在已隔离的本机 VM 环境也可以用回环端口发布和宿主机 CLI。真实备份、Logo、恢复库和 Seed 始终在私有环境内。只需分享 `reports/summary.md` 或 `reports/summary.json`。其余文件包含旧站原始字段、身份和素材引用。

真实旧库行数、数据歧义分布和可打包 Logo 比例待上述隔离运行核对。当前阶段交付候选包验证和字段映射。新站身份分配、URL 重定向、分类决议和业务导入在对应后续阶段处理。 [字段映射](v0.1-d5-a-field-mapping.md)
