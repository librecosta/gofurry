## 0. 产品目标与严格边界

D5-A 产出**可复核的人工数据抽取与清洗工具、明确版本的 Seed 候选数据、Site Logo 资产准备流程、可分享的脱敏审计报告**，为 D5-B 新站模型适配与导入器，以及 D5-C 生产 Bootstrap 包准备输入。本轮**不**对新站数据库进行导入、创建生产资源、绑定新站 Site Logo、修改 GoFurry 业务表/Goose Schema、生成新站 UUIDv7/Public ID、实现旧 URL 301、启动 Harvest、部署生产或修改 Admin。

严格保留旧站人工运营资产，不以运行时间/采集状态/空标签/无 Logo 作为删除或下架条件。所有不确定、重复、无法转换字段都有**逐项机器可核对的异常分类**；不把异常悄悄跳过、归零或强制要求用户逐条手工审核。人工纠错是少数真实身份冲突的例外。

**本轮决定**：
- 完整保留：Site/Game 人工文案及原始身份、Site 分类/分组及权重、Game 自定义标签类别与规则、人工资源/社群链接、合集及规则、旧发布/归档/成人标记、旧 ID 关联、需要保留的 Site Logo；
- 只保留为人工来源引用：旧 Site 追踪目标配置与有效主目标期间，用于重建 URL，而不是带入旧采集器；
- 不迁移任何 Site Cover、Game Cover/Header/Steam 媒体、首页 Hero、旧背景花纹或壁纸。以后由新站人工策展 / Harvest 正常采集；
- 不迁移旧 Steam 新闻、价格/玩家历史、DNS/HTTP/Ping/TLS/技术指纹、采集器队列/Schedule、指标/访问统计/旧评测、评论/IP/用户、抽奖、GFA 账号与密码/Session/审计。旧 `gfa_content_idea` 非正式内容 Seed，D5-A 可仅统计数量，若确有价值另出经过授权的候选清单，**默认不导出正文或人员数据**；
- 旧时间、内容分级、外链以原始可证含义存储，不猜测“旧创建时间=首次发布时间”“未填写 Adult=已确认 SFW”“标题相似=同一作品”。

## 1. 输入和离线运行安全契约

### 1.1 完整备份与隔离恢复

- 备份包始终由用户保管；Codex 只实现工具与合成夹具，**不得连接旧生产容器/生产数据库/生产 R2 或 COS，不要求上传数据库、密钥、Globals、整包给聊天或 GitHub**。
- 为实际 D5-A 运行提供明确的本地流程文档：用户确认 SHA256 后，在临时、网络受限、非生产 PostgreSQL 18（建议独立 Docker 网络和卷）恢复 `gfn`、`gfg`、`gfa` 为带 `legacy_d5_` 前缀的全新 DB；`pg_restore --no-owner --no-acl`，只使用临时专用角色，不自动执行 `globals.sql`。Restore 包含 SQL/扩展，需在受限隔离容器执行，不能作为可信应用 SQL 对公共环境运行。
- 源 Extractor 必须使用 **独立最小 SELECT 权限**（最好数据库级 `default_transaction_read_only` 并强制显式 `READ ONLY` 事务），仅连接用户显式 YAML 指向的三个独立恢复 DB；拒绝源数据库名恰为 `gfn/gfg/gfa` 或与目标 GoFurry DB 相同，拒绝未显式配置的默认 DSN/PG* 环境回退。不能以只读事务替代对生产来源的网络隔离。
- 确认 `pg_dump`/Schema 版本及所需表、列、类型；缺表/结构差异应明确 failed/unsupported 并生成报告，不猜字段、不执行 DDL 兼容性修复。一次审计读取源库应基于同一已冻结备份、三库分别只读一致快照。
- 图标来源可由私有 YAML 显式选择**离线对象目录**（优先）或权限仅限读旧对象的固定对象存储来源；绝不允许从数据库字段构造任意外网 URL 拉取、不读取新站生产 R2、不枚举未引用的旧 Bucket；源凭据/对象键只在私有输出清单和脱敏日志中出现。没有图标读取条件时允许 `inspect/extract` 完成数据导出并列出 `asset_unavailable`，**最终生产 Bootstrap 不得宣称 Logo 已完整打包**。
- 默认输出在忽略的 `.local/legacy-seed/` 或显式的本地私有目录，权限 0700/0600；阻止符号链接穿越、`../`、绝对路径覆盖和恶意压缩包条目；不要上传 Seed、原始表行、媒体、凭据到 Git/GitHub、日志或 CI Artifacts。

### 1.2 单一 CLI 工具

在 GoFurry 仓库新增一个**轻量独立的 Go 命令**（命名可依仓库惯例，如 `legacy-seed inspect|extract|verify --config <private.yaml> --output <dir>`）；复用 Go 1.27.3、pgx、JSONv2 和当前验证习惯，不引入通用 ETL 框架/新服务。所有连接、路径、是否导出 Logo、固定资源额度都来自单份强校验 YAML；不使用环境变量隐式配置。CLI 的导出不写入任何 PostgreSQL。真实恢复命令只在文档给出，不得由 `extract` 自动运行，更不得接收生产 DB 在线连接作为默认输入。

- `inspect`：只读结构/行数/异常分布与来源映射可行性检查，生成聚合报告，不写 Seed；
- `extract`：输出内容 Seed、关系与可选实际 WebP Logo；至少支持内存/时间/文件数和单文件大小有界、流式 NDJSON；逐条先校验后写临时目录，成功后原子固定目录；失败保留错误报告但不能留下伪装完整的成品；
- `verify`：完全离线，不连接 DB/对象存储，严格解析文件结构、Schema Version、行计数、相互引用、所有字节 SHA256、图片尺寸/格式与压缩安全；明确 `ready_for_D5_B` vs `incomplete`，**并非** ready-for-production。

## 2. 输入表/字段的具体范围

**GFN / Site**
- `gfn_site`：旧正整数 ID、`name/name_en/info/info_en`、`create_time/update_time`、`nsfw` 原始有效值、`deleted/deleted_at/deletion_reason_code/deletion_reason`、`icon` 对象键（仅内部素材索引）。明确拒绝伪造访问数/国家/公益标签为新业务属性。
- `gfn_site_group` + `gfn_site_group_map`：旧分组 ID、人工中英文名称/简介、priority、Site 关系、人工 weight，**保留全部分组与关系**。新版八主类映射后置 D5-B；D5-A 只输出带原分类/新类 `unmapped` 的建议诊断，不能擅自归类或删除。
- `gfn_collector_domain` + `gfn_target_tracking_periods` + `gfn_site_primary_target_periods`：只取可以用来证明 Site 当前/历史目标关联的必要元数据、开始/结束/basis。有效主目标优先 `explicit`；`single_target_inferred` 和 `deterministic_fallback` 必须标注推断级别。**探测 Target 并非自然等于公开正式访问 URL**；可选择可信可构造的 URL 作为 proposed 地址，不能将旧探测结果/重定向/HTTP code 冒充正式地址。缺主地址、多个冲突、无效协议时保留 Site 与候选地址/证据，标记 `address_ambiguous`、`address_missing`、`address_invalid` 等。
- `gfn_featured_site`：完整保留被精选 Site ID 与历史 weight 作为可选策展输入；不自动写新站三个槽位。
- 旧站 Site Logo 实际对象见 §4；旧 Hero、背景/封面/导航金句公告的公开运行功能**不在迁移范围**，避免引入与新站不相关的数据表。

**GFG / Game**
- `gfg_game`：旧 ID、名称/简介双语、`resources/groups/links/developers/publishers` 人工 JSON、人工 `release_date` 原文、AppID（仅用于来源身份关联，排除不合理/重复值并报告）、创建修改时间、原有特色策展字段（如 weight/showcase_eligible）作为带来源历史提示，而非默认映射新站排序。头图、旧 view_count 不导出为生产字段；
- `gfg_tag_category`、`gfg_tag`、`gfg_game_tag`：保留标签类别 ID/code/双语名称简介/排序/归档状态，标签 ID/code/双语/归档状态，game↔tag 与 normal/primary/secondary 角色。**旧自定义标签与 Steam Genre 永远不混为一谈**；既有人工关联不会因 Steam 更新、归档的标签、没有新分类映射而被删除。
- `gfg_game_collection`、`gfg_game_collection_item`、`gfg_game_collection_tag`、`gfg_game_collection_exclusion`、`gfg_game_collection_home_slot`：保留旧 Code、双语名称简介、状态、实际发布时间、手动固定成员、自动 Tag Rule、排除项与旧 1–5 首页槽。保留原始集合公式：
  `effective_members = (manual_members ∪ tag_rule_matched_members) − explicit_exclusions`
  其中只用未归档 Tag/Category 匹配，Public SFW 另有资格过滤；不得在 D5-A 将动态规则“拍扁”为永久静态名单。**旧人工成员行没有 position 字段；仅可为输出稳定排序建立 `export_order`（如旧 ID），不可冒充运营编辑顺序。** 旧 1–5 槽不要擅自裁成新站 3 个合集槽，也不要因当前新站的 512 人工成员上限截断数据。
- `gfg_game_first_available` / `gfg_game_release_state` 中来自旧人工明确输入的字段作为**有来源的候选**可留原始时间文本与精度，采集推断部分不在 Seed 公共展示事实内；不可用旧 State 创建新站实际历史证据、价格图或“发行日期已证实”判断。
- 保留人工明确关联的旧作品和资源信息；对于游戏 `adult` 标签及旧公众可见语义分开提取**原始证据与清洗判断**，未知不等于 SFW。没有逐条人工复审要求，留待 D5-B 从可信旧规则批量继承。

**GFA / Admin**
- `gfa` 默认只统计非敏感对象数量；`gfa_admin_account`、密码、Session、IP、审计、评论者身份不读取至 Seed。现有 Admin 身份单独管理，**不作账号迁移**。可单独记录 `gfa_content_idea` 的数量和类型分布，但无授权时不导出标题、备注或人员字段。不得用 GFA 数据库表名/结构缺失阻塞 GFN/GFG 的正式业务 Seed。

## 3. 清洗语义：归属、完整性与生命周期

- 所有 Site/Game/Tag/Collection 与关系都保留来源 `{database, table, legacy_id}`、有效的原始数据、被规范化的目标字段及清洗状态（`usable|needs_mapping|conflict|invalid|archived` 等有版本枚举）。旧 ID 仅为历史身份，**不可重新作为新站 PK**；D5-A **不生成** UUIDv7、随机 Public ID、Slug 永久分配或绑定新站业务身份。D5-B 才定义和冻结映射，防止数据集重复导出后身份漂移。
- 规范化只做可证安全转换：文本有效 UTF-8、有限长度、去控制字符、统一空白、已知语言代码、明确 URL 规范化（仅 http/https，无认证/危险路径）；保留必要原文与 `transformation` 说明。原始值过长或无效绝不静默截断入正式字段，可在私有异常表保存保守的受限值和来源 ID。对旧 JSON 逐类严格解析，未知格式/潜在敏感 URL 不直接写入“生产安全链接”字段。
- 字段缺失≠“不要导入整条记录”。缺少翻译、封面、分类、Logo、可信地址或 Steam 细节，只使该字段 unresolved，不从历史身份集合删除实体。旧软删除/归档仅继承明确来源状态；不因旧 URL 现在不可访问而自动归档，也不在清洗时在线访问第三方网站重新审核。
- 旧 `create_time` / `update_time` 为不带时区 `timestamp` 时按旧应用的 **Asia/Shanghai 墙上时间**解释，并同时保留 raw 与转换的 UTC 时间。真实发布时刻和创建时刻分开；未知首次发布时间保留 null，不能把 Seed 导出时间写成作品首次公开时间。
- Steam AppID 必须严格是有效正整数平台键。检查重复 AppID 及同作品多来源、缺 AppID；仅将其视为 identity matching evidence，**不能根据名称自动合并不同 Game**。一个旧 Site 拥有多个域名不表示多个 Site；两个 Site 共用域名也不能静默合并。
- 所有旧审核/分级标记的原值、解释依据和缺失/矛盾要分别记录；Site `nsfw='0'` 和 Game 非 `adult` 标签可能属于不同等级证据，按旧公开读取逻辑判断，不要自创“全部安全”规则。不存在截止时间、未刷新自动下架或要求批量人工复审的迁移门槛。
- 关系对账必须保留因源对象缺失、归档、未知字段或上限溢出导致的异常，并按 `legacy_id` 精确定位。**不得为追求 0 错误而删除异常源行**。

## 4. Site Logo：唯一需要迁移的旧媒体

- 源为 `gfn_site.icon` 指向的旧 Managed Asset Object Key；真实二进制**不在 PostgreSQL Custom Dump 中**。只处理 Seed 中被引用的 Logo；不要下载/转换任何 Site Cover、Game 媒体、首页 Hero、背景花纹、壁纸或未引用的对象。
- 采用白名单旧对象键（`nav/sites/.../icon/...`，根据实际编码和路径验证），只从明确私有离线镜像目录或限定 Bucket/prefix 的 read-only 对象存储客户端按键下载。拒绝相对遍历、绝对 URL 任意抓取、重定向至外部、无限重试。每图的大小/像素/内存和总数量设置上限；下载/读取后完整解码，拒绝损坏、动画及解码风险；提取时不要泄漏凭证或完整对象清单至公开报告。
- 处理结果必须通过**现有 GoFurry SiteLogo 格式验证**（`image/webp`、正方形、最大 1024×1024、最大 1MiB，并遵循现有容器/解码检查）。符合新站条件且字节有效的 WebP 可直接保留；其它来源按等比缩放、透明留边、居中、不自动裁掉 logo 文本/轮廓的策略生成 WebP（无透明语义的背景要保持来源观感），丢弃不必要元数据。严格核对输出解码、宽高、Alpha、尺寸、SHA256；超限进一步有界压缩或标为 `conversion_failed`，**不能跳过验证器**。
- 文件名采用 `assets/site-logos/<sha256>.webp`，推定新对象键 `sites/logos/<sha256>.webp`；同内容去重。每个引用生成关联索引：`legacy_site_id, source_object_key(private), output_sha256?, output_path?, output_key?, status, width, height, byte_count, conversion`。公开聚合报告不包含完整 source_object_key；私有 Seed 持有足够 provenance 以便追踪。
- Logo 缺失或不合规不得阻断 Site 文字/身份的导出。最终 D5-C 真正生产包必须实际包含所有标记为 `ready` 的 Logo 字节；此时 D5-A 只可宣称“Seed 候选资产齐备数量 / 异常数量”，不是生产上传完成。不上传/删除/覆盖任何新旧 Bucket 对象。

## 5. 候选包与报告结构（严格小而清晰）

D5-A 输出**私有目录候选包**，非生产 Bootstrap 成品：
```text
.local/legacy-seed/<snapshot-id>/
  manifest.json                 # schema_version=1，原始 backup SHA、source commit、UTC created、数量、文件 hash
  content/
    sites.ndjson
    site_groups.ndjson
    site_group_members.ndjson
    site_addresses_candidates.ndjson
    site_featured_candidates.ndjson
    games.ndjson
    game_tag_categories.ndjson
    game_tags.ndjson
    game_tag_members.ndjson
    game_collections.ndjson
    collection_manual_members.ndjson
    collection_tag_rules.ndjson
    collection_exclusions.ndjson
    collection_home_slots.ndjson
  assets/
    site-logos/<sha256>.webp
    site-logo-index.ndjson       # 私有溯源索引
  reports/
    summary.json                # 可安全共享的汇总，仅数量与异常分类
    summary.md
    issues.ndjson               # 私有逐项异常，勿上传/提交
    mapping-candidates.ndjson   # 私有人工分类和跨平台身份建议，不自动决议
  SHA256SUMS
```

- NDJSON 必须按源 ID / 明确复合键排序、UTF-8、固定序列化键与空值策略；Schema Version 严格校验；相同输入与规则版本重复执行内容与资产哈希相同。可以在 `manifest` 中区分执行时刻等允许变化的元信息；内容哈希不能因为运行时间发生变化。
- `summary.json/md` 不含完整网站 URL、Logo Object Key、游戏外链、人工内部备注、数据库名以外的访问地址、用户信息或 Credential，适合用户上传供设计复查。完整 Seed 和 `issues.ndjson` 是**私有**资产，不能误认为公开开源内容。
- 建立逐表和实体级对账：`source_rows = exported_usable + exported_unresolved + explicitly_excluded_with_reason`（每条有追踪）；每个关系要通过引用检查并说明孤儿/冲突；不能因去重或筛选导致没有记录的数量差。单一 Steam AppID 重复、Tag code 重复、分组映射歧义、合集规则上限/关联冲突、Logo 重复/missing/unsafe、旧日期解析冲突均独立报告。
- 不无条件失败于正常的数据质量告警（例如一条 Site 缺 Logo），但 Schema 无法读取、源库不一致、源表漏记录、归档校验不一致、SHA不匹配必须硬失败。报告写明 `extract_complete`、`asset_complete`、`clean_seed_ready` 及各自**具体**理由，不将“提取完成”误称“可生产导入”。
- **D5-A 不生成** `gofurry-bootstrap-v1.tar.zst`：最终紧凑包与真实生产导入器属于 D5-C。可以输出独立压缩候选供离线转移，必须可重新校验、私有且不上传 CI。

## 6. 实施与验收矩阵

**实施者只拥有仓库时（无用户备份字节）**：
