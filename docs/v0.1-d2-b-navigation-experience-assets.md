# GoFurry V0.1-D2-B — Navigation Discovery Experience & Site Asset Contract

**Status: frozen / implementation-ready** · 2026-11-12.
**Repository:** librecosta/gofurry · **branch:** develop.
**Baseline:** D2-A implement bf86697ee455b2e845e8d2807d70eae8a08aa4ec; GitHub Actions 43066543875 succeeded. See docs/v0.1-d2-a-navigation-discovery-heat-editorial.md and docs/v0.1-d2-a-acceptance.md.

## 0. Product intent and scope

Start is the user's personalized start/home experience. Sites is an **editorially composed Furry website-discovery channel**, not a second Start and not the old fully dynamic group-based directory. Games remains an independent channel.

D2-B delivers **functional, genuinely SSR-rendered public pages**:
- canonical /sites and its zh/en region-prefixed variants: curated homepage;
- canonical /sites/directory and locale variants: search, combination filters, stable ranking and "load more";
- accurate, complete website card content: curated logo, optional featured cover, vetted primary visit URL, bilingual name and summary, fixed category/labels;
- isolated, reusable Site asset import/reference flow that doesn't compromise Start wallpaper storage;
- tests for SEO, data safety, interaction, mobile, light/dark, performance and **Start preservation**.

D2-B does **not** rebuild full Site details (D2-C), add any Game UI, introduce Admin CMS/editor UI (D4), import old site records (D5), publish adult data, implement user accounts/comments, or build geo heatmaps. No new microservice, database, general-purpose media library, arbitrary page layout JSON, scheduled external scraping or email. Old navigation site source is read-only reference.

## 1. Fixed homepage information architecture

Site homepage: /sites (localized with existing locale-path.ts: CN zh default unprefixed, /en/sites; INTL en default unprefixed, /zh/sites).

**Six fixed sections in this presentation order:**

1. **Channel introduction + internal search.** Short zh/en heading and one clear sentence describing discovery. Search Site directory data, NOT external engines. Primary CTA "Browse all sites / 浏览全部网站" links to /sites/directory. No oversized fullscreen Hero, background switching, saying, personal quick links or duplicate Start widgets.
2. **Editor's picks.** Exactly the three existing D2-A named slots: primary (large horizontal/content-rich hero card), secondary_1 and secondary_2 (two compact stacked cards at wide screens). Only *these* source names; Admin never supplies CSS/layout/order; missing slots result in responsive, non-ghost layout. Featured image may be absent, in which case use carefully designed typography/logo/surface (never fake placeholder art). Slots can be empty. Section can collapse entirely if all three are unavailable.
3. **Latest arrivals + weekly trending.** At wide screens, recent card grid/list has the wide column and trending sits in a compact companion column. Trending uses ranked numbers and 6–8 result rows, no per-row massive cover. Recent uses up to 8 cards and the genuine first_published_at, not latest Harvest HTTP observed_at or updated_at. Trending is **not** featured; its true rank is not reranked by editorial picks. D2-A already excludes featured and prior slices from homepage candidates; do not tamper with that algorithm on client. Show an explicit "ranking is accumulating" state when heat.status is cold/stale; do NOT mislabel recent content as trending or put zeroes on cards. The corresponding directory ranking remains authoritative.
4. **Explore eight categories.** Fixed front-end registry order: community, gallery, literature, resources, marketplace, knowledge, gaming, events, normally 4×2 on desktop, 2×4 on smaller widths. Each distinct category tile has its name, concise fixed editorial caption, accessible icon and published Site count returned by API. Clicking opens directory with category filter. If count=0, category may remain as an honest empty destination with descriptive zero state; never fabricate entries. Avoid putting eight complete site grids on homepage.
5. **Random discovery.** A single compact feature plus a clear directory link, shown only if D2-A provides a safe random Site. It is not another large section or algorithmic "recommended" stream. Optional: may be folded into the final section.
6. **Footer/hand-off navigation.** Normal site navigation/footer, but do not implement unrelated account widgets, tech-weekly, ads or visitor-map visualization as part of D2-B.

**Layout guidance, not dynamic business data:** constrained centered width roughly 1440–1600px; desktop main/aside about 2:1 (e.g. 8:4 or 9:3 of 12 columns) for recent+trending. Featured primary + stacked secondaries likewise uses the larger primary area. Tablet changes columns progressively; mobile stacks naturally and puts relevant interactive/reading content before optional recommendations. Avoid fixed-width blank aside, horizontal page overflow, popover-only access, and excessive first-screen empty whitespace. Cards have consistent densities but the three section treatments remain visually distinct.

**Visual direction:** warm/light restrained surfaces and existing GoFurry light/dark semantic tokens, no hard outlines on every card, gentle depth, subtle dot/texture only if already allowed by shared tokens. Use SCSS Modules and Motion only when useful for entry/selection; reduced motion and keyboard focus are first-class. Do not introduce Tailwind, StyleX, another icon/UI library, global styles, unbounded gradients or liquid glass on every list item. Avoid new full-width hero art. The existing Start's polished material integrations are off-limits.

## 2. Website Card interaction and content

One **small family of clearly named cards**, not a universal component renderer:
- Standard SiteCard for latest/directory, responsive 2–4 columns based on available width: real Logo (or deterministic fallback monogram/icon), localized title, short summary, **primary category**, up to a few selected tags/languages, and separate actions. Keep baseline heights predictable and protect against overlong titles/translations. Prefer image contain, not crop, for logos.
- Featured SiteCard variant: same Site identity but optional approved 16:9 cover for primary/secondary editorial placement, stronger description and separate visit CTA.
- Trending row: rank, small logo, title, primary class or brief type label, no fabricated numeric Heat score.

**Interaction semantics:** primary title/clearly designated body opens internal canonical Site detail /sites/{public_id}/{slug}, separate visibly accessible "Visit website / 访问网站" native anchor opens the **vetted** primary Site business URL in a new tab (noopener noreferrer). Avoid nested links/buttons, entire-card click-traps, unlabelled icons or hover-only outbound affordances. On touchscreen, both intents remain distinct. Keyboard users can activate either; visible focus with existing component-specific feedback.

For outbound actions, **reuse** D2-A's siteOutbound beacon/keepalive pathway (only on real eligible user events). No new counting endpoint, URL redirect intermediary, tracking popup, link shortening or blocking navigation while a beacon waits. Opening the internal detail is not counted as a detail_view until the existing SiteDwell verifies ~3s visible dwell. Cards appearing on screen never count as views.

A Site without a reviewed main URL or whose public identity becomes disallowed must not create an unsafe external action, and published discovery data must still respect existing site_public_navigation visibility. Never expose adult/unreviewed draft data via featured URL/image or regional fallback.

## 3. Full directory (/sites/directory)

Directory **is not homepage cards repeated endlessly**. It is a tight, efficient discovery/workbench view:
- At top: modest page heading, published total and prominent Site keyword input.
- A **compact horizontal filter bar**, NOT a permanent desktop left-hand sidebar. Filter dimensions: fixed eight categories; controlled tags (currently 12); reviewed supported site languages; sort.
- Categories/tags/languages allow multiselect with OR within dimension and AND between dimensions (as already implemented in D2-A). Explicit selected chips and one-click removal/reset. No country, nonprofit/profit, host country, TLS/CDN or technology stack filters; no frontend adult toggle while regional backend is SFW.
- Desktop: category chips or button-group for frequently used classification, an accessible filter popover/dialog for supplementary tag and language controls. Mobile: compact search, selected filter summary and one accessible bottom sheet/dialog with all options. Draft selection applies **atomically** on Apply; Cancel leaves committed criteria untouched. Use Base UI primitives, trap focus correctly, Escape/backdrop close semantics, focus restoration and input state after refresh.
- Text search IME-safe (no request during composing); **~300ms debounce** while typing and immediate Enter to commit. Normalize to D2-A max 80 Unicode characters; empty input removes keyword filter. Do not block typing with arbitrary invalid option sets.
- Sort options: Relevance (only if q nonempty), Latest Added, Weekly Heat, Site Name. Default for nonempty q relevance; otherwise latest published, as D2-A defines. If Heat status is stale/cold and API reports effective_sort=published_desc, the UI **must disclose the fallback** instead of claiming trending order.
- URL is the shareable source of committed query/filters, using canonical explicit query keys matching API (q, category, tags, language, sort). Stable sorted codes avoid duplicate URLs. A user's back/forward/history refresh must recreate the same filters. Cursor stays in controlled pagination state and must be reset whenever committed criteria changes; scroll position and accumulated results behave predictably. Do not expose site private UUID or credentials in query. Filtered/search query pages default noindex/follow to avoid unbounded duplicate SEO; unfiltered canonical directory remains indexable.
- SSR first page (24 by default); client "Load more" from D2-A opaque next cursor and append de-duplicated by **Public ID** while preserving order. No autoplay infinite scroll; no simulated page numbers. Abort/drop old responses on typing, locale, sorting, filter, region or route change. Reset or offer a safe "refresh results" on D2-A 400 stale cursor. Preserve already visible results while next page loads; failure is a retryable inline state and does not destroy committed filters.
- Distinguish valid empty results (200), missing filtered category (zero), temporarily unavailable API (503), stale cursor (400), load failure, and current list refreshed after edition. No silent success with empty placeholder after network failure. No fixture/demo entries in production.

Home and Directory must use the existing API scopes:
- GET /api/v1/sites/discovery: fixed named featured, trending, recent, categories, random and heat metadata.
- GET /api/v1/sites/directory: q/category/tags/language/locale/sort/page_size/cursor, total, next and effective_sort.
No new duplicate search backend or full-text engine under D2-B unless a reproducible high-priority defect is proven. The 10k-site D2-A fixture measured ~113ms warm filtered ranking; record realistic layout/data costs, optimize measured bottlenecks rather than add speculative infrastructure.

## 4. Site display assets — **small, complete** operational contract

**Current implementation gap:** D2-A Card has Site Public ID, slug, localizations, classification/tags, language and published date; it does **not** include a reviewed primary visit URL, Site Logo or editor cover. The existing storage.Store.URL / PutNew only accept immutable hashed **start/backgrounds/** keys; that wall-paper boundary must remain unchanged.

For D2-B introduce Site-specific **narrow** asset handling for logo and cover, not a generic media store:
- Site metadata has nullable references for **logo_asset_key** and **featured_cover_asset_key**, logically owned by the Site; no new general asset catalog table unless proven essential. Update references under the existing Site revision/optimistic-lock domain workflow or a tightly scoped internal Site asset update. No FK or cascade for these fields.
- Immutable content-addressed keys:
  - **sites/logos/{sha256}.webp** (optimized raster logo on a square canvas, transparent allowed, display with object-fit:contain);
  - **sites/covers/{sha256}.avif** (approved 16:9 featured illustration, optional, display with object-fit:cover).
  All hash values must match actual bytes; no raw external image URL, local path, CDN host or user-supplied full URL is stored in PostgreSQL. Avoid SVG upload and embedding HTML/SVG from external source: imported sites can contain untrusted active SVG/script. Use a local static fallback for absent logos and typographic featured treatment when no cover exists.
- Import/assignment **must be usable before D4**: one explicit, operator-only Cobra CLI to validate/preflight and import **already optimized** WebP logo or AVIF cover from a local file, bounded decode (candidate logo <=1024×1024 and <=1MiB; cover exact 16:9, <=2560×1440, <=4MiB), calculate SHA256, perform immutable conditional PutNew into **only** those Site prefixes and validate Head/read/public GET as appropriate. Separate command binds vetted asset key to a real Site with CAS/revision; clear/replacement preserve older immutable objects for safe rollback and future garbage-collection design. The command is not an HTTP upload/admin endpoint and never affects Start's upload pipeline. Respect imported material's license/permission review and do not fetch arbitrary third-party images automatically.
- Existing GoFurry explicit private YAML storage credentials and **region-specific** bucket/public_base_url are reused; expand storage with a strictly typed Site-specific validator/import method or adapter. **Never broaden the existing Start background key allowlist to accept Site keys** and never accept arbitrary object paths. Avoid S3 operations during every normal public query and never couple list SSR to external storage HEAD; validate asset at assignment/import time.
- Public API DTOs provide **trusted resolved asset URLs** and **vetted primary business URL** only for published/region-approved Sites; omit nulls safely. Server derives asset URL from configured owned storage host + validated key with strict HTTPS host/path and no open redirect. Missing storage or missing asset => null with deterministic frontend fallback; no SSR 503 solely because an optional logo is absent. Ensure public origin cannot be confused with arbitrary image URL from source metadata.
- The vetted external primary URL comes from active Site address.kind='primary' in the same regional DB; an image and URL must never alter Site identity or slug. Preserve meaningful business path/query in URL (but don't log them), enforce HTTPS preference and existing URL safety semantics. Only the approved primary URL is shown on listing cards; alternate URLs remain in Site detail (D2-C).
- The cover is used **only** on editorial Featured cards, not downloaded for each standard directory/trending row. No cover required for a Site to be publishable; no automatic blank feature or fabricated stock art. Set stable aspect ratio boxes and lazy/priority loading (first visible featured image can be high priority, below-the-fold lazy). Asset delivery goes direct from trusted CDN, not through GoFurry API bytes; cache immutable hashed assets.

Operator CLI is temporary workflow, the underlying service can be reused by the future authenticated LibreCosta Admin product in D4; do not build a second UI/credential system.

## 5. SEO / locale / visibility

- Actual routes and default-language prefixes must follow the **existing** localizedPath rules, not a new language routing mechanism. /sites and /sites/directory are distinct from /sites/{public_id}/{slug} and yearbook nested path. Validate route precedence and avoid optional dynamic routes swallowing "directory".
- Indexable genuine SSR HTML with real per-page localized title/description; canonical URL for default clean home and default directory, actual published hreflang alternatives when translated page UI exists. Configured WEB_PUBLIC_ORIGIN is trusted from the existing server; no arbitrary Host/open-redirect/cross-region fallback.
- Directory keyword/filtered/sorted pagination states default noindex/follow (do not contaminate canonical with unbounded query variants); links to canonical detail pages remain crawlable. Public home and unfiltered directory are discoverable from navigation/sitemap when sitemap infrastructure is delivered; D2-B may add narrow sitemap entries but must not invent an entire sitemap/crawler subsystem.
- For an individual Site missing a GoFurry localization, use its actual available name with language explicitly indicated; do not claim a missing language translation exists or inject a fabricated bilingual summary. All other UI texts and fixed categories are complete zh/en.
- Static site category Code and fixed layout order belong to front-end product code, not backend-record order. Use D2-A term registry/contract parity test, no dynamic Site section generator.
- CN displays SFW only; INTL remains currently SFW on the backend. No adult records accidentally appear in featured/heat/recent/directory through either SSR data, skeletons or public images. New asset refs should be hidden whenever Site is unavailable.
- A disallowed or archived Site can disappear from home/directory immediately at API read; historical approved yearbooks preserve the separately reviewed existing visibility contract. D2-B must not change the D1-B2 yearbook lifecycle.

## 6. Failure, quality, UX and non-goals

- SSR must not depend on Harvest, third-party Site servers, Redis heat availability, R2 HEAD, GeoIP, weather or Tech Weekly at request time. If the regional PostgreSQL/API is genuinely unavailable, return 503 and a retryable site-specific error, never 200 with an invented empty list. A cold/stale heat head returns empty trending and a transparent fallback sort, while other discovery slices remain usable.
- Site card external links are valid HTML anchors even if interactions are off, disconnected or rejected. No tracking pre-redirect. External open uses noreferrer/noopener, trustworthy target.
- Skeleton only for real pending client operations, not server-rendered fake content. Empty editorial slot or low count is a neutral informative state, not filler.
- Input, text and loading state must avoid content layout jump; image failed loading uses a deterministic fallback and never blocks card navigation. Keyboard focus, Tab order, Escape/Apply, screen-reader labels, aria-live for updated result count, appropriate empty results, responsive overflow and reduced-motion all verified.
- No aesthetic redesign of Site detail, Game, Status, Start or global design tokens. If a shared route/head helper requires a small change, demonstrate the old behavior remains equal. Do not update Golden merely to mask regressions.
