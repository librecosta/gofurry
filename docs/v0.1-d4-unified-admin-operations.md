**状态：冻结 / 双仓一次性实施契约** · 2026-11-15

**Admin 基线：** `0a0c85438183240d4e85ce78e95f0a6d2f9c994e`（既有独立身份、角色、审计、GoFurry 壁纸工作区）
**Harvest 固定版本：** `349730b5c3ff57be084dfac72dfb77f19dacb54c`
**仓库：** `librecosta/gofurry`、`librecosta/admin`，两者各自仅 `develop`，各自提交/CI。**不改** Harvest、Identity、AI Gateway、steam-go、旧站及生产资源。

本轮完整闭环：GoFurry 管理域 API → LibreCosta Admin typed client/auth/audit → 可实际使用的 Sites、Games、Collections、采集运营工作区 → 隔离双服务验收。D4 完成后进入 D5 真实旧站迁移，不再建设第二套后台。

## 0. 核心产品原则

**Admin 用来管理例外，不是给自动化管线制造人工任务。** 普通网站和游戏资料应持续自动发现、更新或通过原有一次发布确认；后台无需逐条复审、逐条给 Game 打标签、逐条填写两份“证据”、逐条续期或在收录前加入精选/合集。自动分类不可靠的候选允许保持内部待定，集中显示有价值的冲突与持续故障，但不能制造每天都要清理的“审核工单”。

永久业务约束：`published` 的 Site/Game 及持久标题/简介/封面、Public ID、合集关系、已积累历史数据在 Harvest、模型、CDN、Redis、API 故障、Consumer 重建、30/180/365 天无新事实时**不自动消失**。目录数据质量和时效观测是独立属性。明确归档、手工撤稿或有证据的成人内容政策处置，是少数可能改变可见性的**显式、持久、可审计、可恢复操作**。后台读取状态不可触发变更。

## 1. 固定职责与信任边界

**Admin（独立仓库）**：
- 唯一运营 UI：复用现有 React SPA + Tailwind v4 + React Router + Base UI + legacy-migrated AppShell、Table、Form、Dialog、Sheet、身份/会话/CSRF、Owner/Developer/Operator；沿用 existing embedded Go single-binary 部署。不得在 GoFurry 公共 React SSR 里另建 Admin。
- Admin 的区域专用数据库只存管理员账号、Session、Admin 操作审计；**不得直连 GoFurry PG、R2、Harvest PG**。后端固定 `gofurry` product client 携带已配置 Bearer 和服务端生成的 actor/request ID、区域和环境断言。浏览器永远看不到 upstream Token。
- 前端只请求 Admin same-origin `/api/v1/products/gofurry/...` 路由；Session 授权和 CSRF 在 Admin 校验；调用未知结果保留表单，展示“结果未知，先重新读取权威状态”而不是自动重试改变数据的动作。禁用自动 mutation retry。

**GoFurry（业务权威）**：
- 扩展已存在 `internal/management` **独立 loopback-only Fiber App**，并复用现有 `catalog`、`navigation`、`collection`、`wallpaper`、`storage` 域方法；不能在公共 `/api/v1` 新增写权限或共享管理 token。现有壁纸端点继续兼容。
- 保留静态 Bearer + precise Actor headers + Region/Environment + request ID 检查，强化每条路由的角色授权（双端 defense in depth）、body/参数限制、revision 冲突、审计。业务实体 ID 是 GoFurry Public ID，内部 UUID 只在必要的受控管理数据中使用，绝不重新生成身份。
- **重要**：GoFurry Management 目前仅当 `database+storage+management` 齐备才启用，源于壁纸要求。D4 应使 **Site/Game 的管理只依赖区域 DB+Management 配置**；缺 R2 时仅照片/壁纸上传等相关操作显示 unavailable，不把全部运营控制台关闭。继续让壁纸发布的严格存储前置条件生效。既有 public 入口和探针生命周期不因管理接口不可用受影响。
- Harvest 仍是 Targets/Jobs/Provider/限流权威。Admin 不获取 Harvest Token、不直接控制 Worker，也不拥有其配置。GoFurry 使用当前 CN 显式 YAML + 原有固定 reader/writer 能力读取自己名下的任务与状态；不做任意跨 Namespace、原始 Observation 日志查询或通用控制平面代理。现有 Harvest reader/writer 若不具备全局 `operations/status` operator 权限，应从 GoFurry 本地 Consumer/Job/候选数据构建准确状态，缺指标明确 unknown，不偷偷提权。
- CN/INTL 仍是两个部署与独立业务数据库。一个 Admin 实例只对应同一区域/环境的 GoFurry，绝不跨区读写、自动 fallback 到另一个区域或共享用户数据。INTL 当前没有运行自己的 Harvest 自动采集时，运营页面要说明来源与状态，不能把“无同步来源”谎报为健康。

## 2. 固定权限与审计

复用固定角色，不建 RBAC Builder、OAuth/Identity、第三方身份、插件管理或新的账号表。Admin 新增静态能力：

| Capability | Owner | Operator | Developer |
| --- | --- | --- | --- |
| `gofurry.catalog.read` | yes | yes | yes |
| `gofurry.catalog.manage` | yes | yes | no |
| `gofurry.operations.read` | yes | yes | yes |
| `gofurry.operations.manage` | yes | yes | no |
| `gofurry.policy.manage` | yes | no | no |

- Catalog manage：编辑 Site/Game 人工资料、官方 Site 媒体、导航精选、游戏/合集精选、合集/成员，明确出版/归档（前置业务规则完整）；无额外审核队列。Policy manage 专门处理明确 Adult Block/解除、危险来源归属或受限恢复；默认不提供“批量全部发布”按钮。
- 操作管理：对单个 Candidate 有界 Retry/补采集、发现 Pause/Resume、明确现有 Collection Reconcile；不授予修改全局 Harvest 网络政策/密钥、任意 Job 重放或跨区域采集的万能权限。
- Admin 的固定 capability + Session/CSRF、后端重新鉴权，GoFurry 管理 App 的 role 条件必须全部实际校验（UI 隐藏不等于授权）。admin actor ID/name/role 从服务端认证会话派生，不信任浏览器传 actor 字段。
- **双层审计**：Admin 复用 `requested → result(success/failure/unknown)` 追加审计（现有 Wallpaper 模式，克制泛化到固定 GoFurry operation allowlist）；GoFurry 权威侧在业务状态改变事务内保存请求 ID / actor、目标、操作和少量不敏感差异，尽可能复用已有 Site Review、`catalog_publication_decisions`、Wallpaper 审计；欠缺的编辑/合集/运维动作只补**最小** append-only 操作记录，不要把整个数据库 row/请求体存日志。未知结果必须可以通过 GET 核对最新 Revision 和操作结果，不能假装原子跨库事务或盲目再提交。

## 3. Admin 信息架构：少而完整

固定导航，复用现有 AppShell：
- **GoFurry / 概览**：一屏可读的 Site（已发布/草稿）、Game、合集数量、最近自动收录、近 7 日真实处理统计、采集 Consumer 状态、异常总量和壁纸入口。无实际采样时显示 Unknown/无记录而不是虚构 0。
- **网站**：站点管理列表（搜索、状态、是否未分类、内容等级等有限字段）；进入详情可编辑中英文名称/简介/详细 Body、主/备访问地址、主/辅类别、受控标签与语言；安全上传/绑定 Logo/Cover（复用现存 `storage.ImportSiteAsset` / `SetSiteAsset` 的真实格式与校验）；预览公开页面；明确发布/归档/恢复与成人处置；Site 的三项固定精选槽位。已有年鉴可只读查看与链接，必要时手动触发原有受控重算，不复制年鉴编辑器。
- **游戏**：列表/搜索（已发布、草稿、受限、来源平台、候选问题），Game 详情以人工编辑/自动资料的**并排可辨来源**呈现：可编辑 zh/en 标题/简介/Slug、修正来源绑定、查看自动字段/观察时间与源、访问公开详情；仅少量显式纠错动作（归档、恢复、成人内容 block/unblock、重新获取特定候选），**不生成每款游戏的审核 Checklist**。
- **合集与精选**：复用 D3-B 持久合集与 6 固定槽。创建/修改 zh/en 名称简介、选择游戏、拖拽或有序重排成员、发布/归档/恢复、首页精选和合集精选；成员的 Game 被归档/blocked 时仅从公众列表过滤，不从数据库中删除；恢复不需要重新编辑合集。可选的精选管理不是自动收录的门槛。
- **采集与发现**：显示 Steam Discovery 当前窗口/游标、预算/暂停、Intake discovered/accepted/deferred 等**聚合计数与有价值的问题原因**、当前 Harvest Consumer 同步/重建情况、最近确认时间及异常。允许受控单条 Steam AppID 提交/Retry、Pause/Resume、必要 Reconcile，不暴露任意 Harvest SQL/凭据/Target 创建 UI/通用 Worker/网络策略配置器。
- **官方壁纸**：原工作区完全保留，不复制上传管线，也不迁移到新站 Web。

运营概览分类只按真实结果统计，不把所有 `deferred` 都叫“待人工审核”。普通网络重试和证据不足是自动状态；只需对**持续无法自动解决的重要冲突**提供“查看原因/可选处理”入口。不要强制每个条目处理后才允许其他内容上线。

## 4. GoFurry Management API 最小契约

所有路径仅挂载 `/internal/v1`，根据已有命名建立**有限固定**类型化端点。建议：
- `/ops/overview`：聚合站点、游戏、合集、Intake/Discovery、Consumer 的真实计数与健康语义；
- `/sites`、`/sites/{publicID}`：管理列表/详情/编辑、分级与出版、精选，受控 Site Asset import/bind；
- `/games`、`/games/{publicID}`：管理列表/详情、人工资料编辑/显式出版策略/来源管理，候选只读 evidence；
- `/games/collections`、`/games/collections/{publicID}`、`/games/features`：复用 D3-B 域 CRUD 和 revision；
- `/operations/discovery`、`/operations/intake`、`/operations/collection`：限定状态、单项 retry、pause/resume、bounded reconcile，必须真调用现有 Domain/Consumer 能力，不写假的“开始采集”状态。

精确形状以现有业务类型为权威，**不要造泛型 `/proxy/:resource/:action` 或把 CLI 的文件路径/stdin 参数暴露给 HTTP**。公开 Game `/api/v1/games/:id` 紧凑 DTO 和 Sites/Start/Yearbook 及历史 Insights API 均保持不变；管理 API 返回详细内部 DTO，但不含 Secret/原始敏感证据内容。Query 长度/页长、body <=16KiB（图片单独流式限制）、revision 与类型严格校验，符合现有 `domainError` 与 request ID 语义。

Asset：Logo 必须合法 square WebP（<=1024、<=1MiB）；封面合法 16:9 AVIF（<=2560×1440、<=4MiB），Admin 图片编辑可复用已实现的安全裁剪/Worker 组件，不能调用 GoFurry public 路由直接 PUT R2；图片确认允许作为*选择上传*一次性操作，不要求每条游戏或网站周期重审。新站 Logo/Cover 只允许属于当前 Site 的安全 binding、Revision 匹配，URL/键由 GoFurry 按真实文件生成与验证。原有壁纸 AVIF/WebP 严格规约完全不变。

跨服务失败：GoFurry 管理入口禁用时 Admin 其他模块正常；管理端业务写已成功但 HTTP 响应丢失时 Admin 显示 unknown 并重新 GET、不能直接自动重试。不可用 Harvest 只造成采集部分 unavailable，不影响 Site/Game/合集编辑和公众访问。持久 Identity/region/publication 政策不在 GET、定时、前端刷新时发生任何隐式变化。

## 5. Admin 前端合同

- 基于 `librecosta/admin` 当前迁移后的 legacy React/Tailwind v4 UI、已有 AppShell/侧边栏/DataTable/Sheet/Dialog/Toast/主题/Unsaved 保护。**不要**使用 GoFurry 公共 SCSS Modules 风格、新建第二套设计体系或“网页套一个 Canvas”。清晰精简的业务表格和编辑器；不做无意义的大屏 KPI/复杂图表/动画。
- 明确空/未连接/加载/失败/未知操作结果/409 冲突状态；无数据时不生成假统计或样例 Site/Game。可检索、可分页，按已发布/错误/未分类过滤；重要动作上下文内执行，不要求切到多个无意义表单。
- Site、Game 的中英文资料可在同一编辑表单内切换，但不要要求同时提供两种语言；来源数据只读与人工覆盖清楚分栏。分类/标签为空不影响正常 Site；由现有校验决定合法性；没有任何按时间自动下架或强制复审 UI。
- 合集成员使用“搜索并选择 + 可见有序列表（可拖拽，也有键盘上/下移动）”，保存一次性替换成员排序；版本冲突保留本地编辑状态。不给 UI 直接编辑原始 SQL/JSON 字段。
- 浏览器不得携带 GoFurry Bearer Token 或 Harvest/AI Gateway/Storage 凭据。前端已有 QueryCache 随 Session 销毁的安全习惯保留；后台所有批量动作有数量和时间上限，取消 UI 请求不等于撤销可能成功的写入。

## 6. 实施顺序（同一个 D4 任务内部完成，不分成 5 个阶段）

1. 对两仓目录、权限、表/领域服务和 Admin 原管理 API 做实际盘点，明确现有方法可复用和最小缺口，不更改基础架构；
2. 先实现 GoFurry 的固定管理路由/领域适配/少量必需 SQL 与管理审计；兼容现有 Wallpaper 路由和启动约束；
3. 再实现 Admin 的固定产品 client、角色 capability、typed handlers 与操作审计；保留既有认证；
4. 在 Admin React UI 实现概览、Sites、Games、Collections、采集运营页面与导航；旧壁纸页面无回归；
5. 在两仓各自进行隔离数据库/HTTP/Browser 联调，修复实际缺陷、生成验收并提交。此阶段只新建有限必要的 Goose forward migrations，不修改以前的迁移。

如实际代码扫描发现某类数据目前不允许安全更改，优先将其呈现为**真实只读诊断**并在验收中注明缺口；不要用手工审批系统或任意宽权限 API 填补。Site/Game 正常编辑与精选/合集 CRUD、采集异常查看和已有发现控制必须真正可用，不能只交付一个“漂亮空 Admin”。

## 7. 强制验收

全部使用明确的**一次性独立** Admin PG + GoFurry CN/INTL PG（符合各自仓库测试命名/用户约束）、测试用 Redis、固定 Harvest Server/Worker 与模拟 Steam/AI 服务；不使用现有持久 `.local/manual` 账号/数据，也不碰共享开发/生产。

- **身份/越权**：未登录、过期/被撤销 Session、失效 CSRF、错误 Origin、错误 Region/Environment、伪造 Actor Headers、Dev 尝试修改、Operator 尝试 policy block、Admin→GoFurry Token 错误、管理端直达公开端口均正确拒绝且不改状态。Cookie/Token 不出现在浏览器日志/URL/API。
- **Site**：列表搜索/编辑双语和安全 URL、无主类别公开展示、Logo/Cover 真正经过图片验证与绑定、三精选槽、发布/归档/恢复及审批例外；无任何定期审核或自动过期。
- **Game**：真实自动 D3-A2-B 收录无需手动审核就进入公众目录；Admin 可查看来源事实与候选、修改仅编辑所有权字段、显式封禁/恢复、取消/再次绑定来源不能改 Public ID。Steam+itch 同作品不被名字错误合并。无来源、无新 Steam 观察不隐式隐藏发布 Game。
- **Collections**：新建、编辑、成员排序/键盘、版本冲突、公开/归档/恢复、六精选槽对应清理/保留、成员 Game 公开资格变化只影响公众投影。
- **Operations**：Steam Discovery 预算/暂停与 Reader 健康，单候选 Retry、真实 Consumer 410 重建/Harvest 停机/AI disabled/Redis unavailable 的状态真实且**不导致 Site/Game/合集后台不可用**；不因缺采样伪造健康 100% 或零异常。
- **跨服务未知结果**：模拟 GoFurry 业务写实际成功但客户端超时、Admin 审计结果写失败；Admin 显示 unknown、刷新看到 GoFurry 实际 Revision、不会无限自动重试/重复写审计，两个服务各自 append-only 审计有共同 Request ID。
- **持久性**：31/181/365 天不采集，管理读、公开列表/详情、封面、历史新闻/价格/玩家日汇总与合集关系保持，唯一允许变化为动态实时字段的「当前」资格和显式成人处置。
- **UI**：1280/390px、Light/Dark、键盘焦点/Sheet/Dialog/文件上传/访问性、路由刷新、Unsaved、失败后编辑保留、隔离的正式 Go Embed 版本。首次加载不预取所有含图片的大表。
- **回归**：GoFurry D1–D3-C、Site/Yearbook、Start、Wallpaper；Admin Accounts/Auth/Audit/Go Embed/Wallpapers/manual launcher，Go/sqlc/web/HMR/containers/CI 各自通过。不能通过修改 Golden/删除测试掩盖失败。真实 local manual 验收脚本可复用但**不得自动重置持久账号或数据库**。
- **容量**：Admin 列表 100/1000/10000 Site/Game 的实际分页时间与 UI 行数；运营聚合按 SQL 索引有界，不每次前端展示执行全表 JSON/原始 Harvest 扫描。
