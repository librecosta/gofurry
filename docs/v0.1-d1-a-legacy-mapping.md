# D1-A legacy Site and Game mapping

The import stage owns two durable maps in each regional GoFurry database. Both use the audited legacy deployment plus a positive signed 64-bit legacy ID as the source key. `legacy_site_ids` points to `sites.id` and `legacy_game_ids` points to `games.id` using restrictive UUID foreign keys. The canonical Public ID is read from the referenced entity. An export or review artifact may include it to verify the join. The map also records the import batch, verification time and verified reviewer when that workflow exists.

| Map | Legacy paths | Example source ID | Fixture Public ID |
| --- | --- | --- | --- |
| Site | `/site/41`, `/sites/41` | 41 | `000000000000000a` |
| Game | `/games/41` | 41 | `000000000000000b` |

Two aliases of a legacy Site share one mapping. Site 41 and Game 41 remain independent. Import reruns must verify an existing mapping before accepting it. A change of destination, a many-to-one merge or a conflicting platform key requires explicit reconciliation. Domains, titles and Steam AppIDs are review evidence. The import assigns and retains immutable Public IDs according to the new identity contract.

After the maps have been reviewed, route handlers may resolve canonical positive decimal keys through their typed map and then read the current published entity. The resolver builds a single 301 using its current Public ID, slug and the request's explicit locale under the local deployment's prefix rules. Unmapped and archived targets return 404 initially. The original query does not participate in the redirect destination. A retired route could use 410 later with an explicit tombstone.

The legacy signed 64-bit range overlaps the 16-character Public ID format. Bare positive decimal paths are reserved for legacy resolution. A randomly generated all-decimal Public ID still has its normal slug-bearing canonical URL. Its bare positive decimal spelling stays reserved for the legacy map. The explicit slug-bearing route uses only the exact typed Public ID.

D1-A tests deterministic mappings in an isolated HTTP fixture that reads the real published API and uses the same localized path builder as SSR. The application returns 404 for bare legacy paths until the import stage installs an audited map. There is no production map, legacy database connection or imported old-site data.
