## Run and inspect

Apply `202611120004_game_intake.sql` with `task migrate ACTION=up CONFIG=<private YAML>` in the intended regional database. The migration adds `game_intake_candidates`, two Game columns for policy and stable display-source choice, and the shared SQL presentation function. It adds no foreign keys, cascades or sequences. Existing editorial Games retain their publication policy and Public IDs.

Use the existing CN Harvest Consumer enrollment, a dedicated namespace, the writer grant for `steam.details` Target, Job and Schedule writes, and the separate reader for Job, History and Consumer reads. Use the same explicit YAML as the existing Harvest setup. Set `harvest.intake_egress_region` to the approved route region. Setting `harvest.intake_enabled: true` also starts Intake with the existing Fiber lifecycle. The default is off. The CLI can tick independently using the same YAML with the automatic loop off. It stores PostgreSQL intent and uses Harvest HTTP for all collection. Redis is optional.

```sh
go -C services/api run ./cmd/api --config /path/to/private.yaml game-intake submit steam APP_ID
go -C services/api run ./cmd/api --config /path/to/private.yaml game-intake inspect steam APP_ID
go -C services/api run ./cmd/api --config /path/to/private.yaml game-intake status
go -C services/api run ./cmd/api --config /path/to/private.yaml game-intake tick
go -C services/api run ./cmd/api --config /path/to/private.yaml collection reconcile
```

Each tick claims at most one candidate per regional database and holds a 45-second fenced lease. Each operation has a 40-second deadline. Only due rows are considered, and failures back off to five minutes and park after eight failed checks. Harvest supplies its own per-Job attempt budget. At most one second Job may be submitted after a verified terminal transient failure. Lost responses replay the durable submission key under the same writer identity and origin for up to 15 minutes. Once its ID is known, recovery uses read-only Job and History calls. The maximum unfinished inventory is 10,000; `dismiss` records a terminal decision and releases admission capacity while retaining the deduplication key. The idle tick can prune up to 128 untouched parked rows over 30 days old that have neither a remote intent nor review evidence. Repeated submissions preserve the original row.

```sql
SELECT platform_code,external_key,state,reason,next_at,target_id,job_id,attempt_id,
       observation_id,game_id,game_source_id,decision_version
FROM game_intake_candidates
WHERE platform_code='steam' AND external_key='3000000001';
```

A Job must match the persisted Target, namespace, normalized request and one-shot cause. Intake checks the accepted Attempt, exact History Job/Attempt IDs, detail scope digest, completion window, output schema v1 and Steam AppID/source fields before using its name and plain-text synopsis. The final PostgreSQL transaction writes the Game/source, candidate outcome, binding and shared Schedule intent together. It picks one daily English/US `steam.details` plan or adopts the existing equivalent scope. The Consumer updates the chosen source from accepted observations and confirms unchanged data. Its active snapshot can refresh that profile after a reset. Temporary failures preserve the last validated projection up to 30 days.

## Evidence and publication

Supply two distinct audited records for automatic publication. One must positively establish the work's anthropomorphic subject matter. The other must positively establish its SFW content. Use the private command `game-intake review APP_ID FURRY_REF SFW_REF --confirm-furry --confirm-sfw`. References are bounded opaque IDs to independently reviewed evidence, such as a reviewed work synopsis and a separate content assessment. Record them before Intake for hands-off publication once a full game, canonical store source, and usable title and English synopsis arrive. A Storefront success or missing adult tags grants no eligibility. Review is versioned and expires after 180 days. `revoke-review` takes effect on the next API/SSR read and preserves identity. Both regions apply the same public gate. Only the existing CN deployment runs the live Harvest integration.

Editorial localizations take precedence over the approved automatic profile. An English source contributes English only. Expired, invalidated or explicitly withdrawn automatic data cannot qualify a Game for publication. A draft with no positive review stays private even when its source continues collecting.

`game-intake relate PLATFORM KEY OTHER_PLATFORM OTHER_KEY FORWARD_REF REVERSE_REF --confirm-reciprocal-work-links` accepts a reviewed assertion that two canonical official product links reciprocate and describe the same full work. A second platform uses the existing `itch_io` source code and the canonical `creator/game` key. Review requires two distinct provenance records. Only a unique existing owner can receive a new source. Case-folded legacy source conflicts and title-only matches defer. Two existing owners produce a merge suggestion. `revoke-relation` disables the automatically attached source and closes its applicable binding while retaining the original ownership and evidence.

## Outstanding boundaries

Harvest History can attribute a material Observation exactly. Its unchanged-confirmation path updates the existing result and emits no Observation with the new Job/Attempt IDs. The candidate stays `observation_unattributed`. To resolve that case automatically without weakening provenance, Harvest would need to expose the accepted Attempt's per-scope confirmation and the immutable ID/hash of the confirmed result. A writer or origin change while a POST remains uncertain also parks the intent rather than risking another Job under a different credential.

Production credential enrollment, positive evidence inventory and live capacity remain outside this isolated acceptance. Steam increment discovery and full metadata mapping belong to D3-A2. This stage uses only the simulated second-source evidence fixture and reviewed itch.io links. Real itch.io collection remains D3-A3.
