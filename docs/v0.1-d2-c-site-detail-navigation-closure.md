## 0. 为什么做 D2-C

Start 是日常主页；Sites 是内容发现频道；一个 **Site Detail** 应该是“可信的兽圈网站资料页”，不是过去的“网站观测/安全多 Tab 工作台”。D2-C 为导航系统最后一轮核心前台阶段，完成 **Site 详情、相关推荐、已存在年鉴的自然入口、少量可信技术概览和频道联通**。做完即停止新增导航主业务功能，推进 D3 Game。

必须先阅读 \`AGENTS.md\`、\`.agents/architecture.md\`、\`docs/v0.1-d1-a-site-game-identity-url.md\`、\`docs/v0.1-d1-b1-acceptance.md\`、\`docs/v0.1-d1-b2-acceptance.md\`、D2-A/B 契约与验收；核对实际 Source：
- \`apps/web/src/catalog/detail.tsx\` / \`detail-server.ts\` / \`detail.module.scss\`；
- \`apps/web/src/navigation/{cards,pages,data,sites.module.scss}\`、\`apps/web/src/start/chrome.tsx\`；
- \`services/api/internal/{catalog,navigation,collection,yearbook}\`；
- \`services/api/internal/database/queries/{sites,navigation,collection,yearbook}.sql\`；
- D2-B \`sites/logo_asset_key\` 与 R2 安全接口。

**本阶段只改 \`librecosta/gofurry\` 的 develop**，不改 Admin、Harvest、Steam SDK、旧站。不得连真实外站进行验收爬取，不自动向持久化开发或生产 DB 执行迁移。

## 1. Site 详情的信息架构与页面体验

固定阅读顺序，不开发配置化 Tab 或运营 JSON 布局。

1. **频道上下文**：沿用 D2-B Sites 的简洁导航头/局部面包屑，可进入 /sites 与 /sites/directory；浏览器返回保持原始筛选与滚动行为，不能丢掉目录中已提交的筛选条件。D2-B SitesFrame 可做范围受控的“详情页面复用外壳”提取，但不得为了它重写现有导航首页/目录。
2. **Site Hero / Profile Header**：已审核 Logo（或优雅文字回退）、真实中英名称、主访问域名的安全显示文本（不要把任意 query/token 暴露在显示标签）、1–2 行定位描述，主分类、补充分类、最多几个标签/支持语言。醒目的两个互不混淆操作：查看 GoFurry 的当前资料、原生“访问网站”外链。详情中的主“访问网站”采用真正的 \`<a>\` 新标签打开；永远不经跳转统计服务。不要放全屏 Hero、额外动态背景、霓虹玻璃。
3. **关于网站**：有详细编辑内容时展示分段介绍；没有时使用已有人工简介作为完整主体，不显示巨大的“待完善”空卡。内容由 Site 编辑字段提供，不让 Harvest 标题/HTML 自动覆盖。
4. **站点信息**：主分类/补充分类链接到已存在可分享目录筛选；语言、经审核的主站/备选访问地址。仅使用安全 URL；备用地址可以折叠显示。不要使用已弃用的国别、公益/盈利属性。
5. **近期关注**：复用 D2-A \`GET /sites/:publicID/stats\` 已审计的七日有效详情浏览/外链点击；只有已达低样本门槛时展示，以“有效浏览”“外链点击”标注，绝不写“独立访客”“访问量精确统计”“评分”或展示内部 Heat 原始整数。没有样本就不渲染，不要标 0。
6. **相关网站**：5–6 个以内，根据同主类、补充类、受控标签、语言等已知审核字段计算明确的相似候选，优先类目相关性，近期热度只作平分优先级；不需要 AI、embedding 或跨网站实时请求。展示使用 D2-B 标准 SiteCard 的精简变体，在桌面侧栏/底部合适位置；移动端移到主内容后方，少展示即可。
7. **技术概览与年鉴**：可验证的技术摘要最多 3–5 项，只有真的存在经过 Consumer 归属和规范化的事实才展示；年鉴列表只展示已公开发布的年份，独立链接到已实现的 \`/sites/{public_id}/{slug}/yearbook/{year}\`。没有采集/没有年鉴时不出现占位区域。技术不是首页大屏、多 Tab、多图表或证书安全评级。

**版式**：桌面内容主栏（约 2/3）和辅助栏（约 1/3），Hero 尽量紧凑但要有视觉层次；平板自然切换，移动端单列；页面允许少数据时自然变短，不强制最小大高度。沿用 D2-B 暖色/克制无边框布局、当前 SCSS Modules、语义 token 与既有 Motion/Base UI/Phosphor；不设计新组件库、复杂玻璃卡、外加大图。自适应长译文、长 URL、Logo 缺失和中英文布局。键盘焦点/读屏、reduced motion、亮暗主题必须验收。

## 2. 长介绍：最小编辑能力，不引入 CMS

D1-A 的 \`site_localizations\` 已有 \`name/summary\`，D2-C 可通过 **新的 Goose forward migration** 添加 \`body\` 或同等 nullable/empty UTF-8 纯文本多段正文（每语言上限建议 8–12 KiB，禁止原始 HTML；以换行分段呈现），独立于用于目录/SEO 的 \`summary\`。

- 不引入动态 Markdown/HTML 富文本编辑器、HTML 清洗依赖、通用区块 schema、所见即所得 CMS、额外文章表或可执行代码。
- 有需要时支持安全的段落与简洁列表；以纯文本分段呈现即可，禁止 raw HTML 或未经审核的外部媒体嵌入。输出始终文本转义。
- 新内容在现有 Site Domain 内使用乐观 revision/CAS 更新单个语言，保留另一语言及既有地址/Logo/审核运营信息，避免 D1-A 的整组覆盖编辑不小心抹除正文。受控 Cobra CLI \`site-profile set-description\`（可采用仓库一致命名）读取审核后的本地文本，须明确 Site Public ID、locale、revision 和审核确认；**不新增公开 POST/PUT**，完整可视化编辑器留 D4 Admin。
- 若编辑流程的操作者审计仍未连接 LibreCosta Admin，不要伪造真实登录 actor。操作需可诊断，必要时记录最小、非敏感的变更来源，不为它另造通用审计体系。
- 没有资料的语言不得凭另一语言描述伪造翻译或 SEO；UI 可显示实际语言来源并明确标识。中英 UI 文案完整。

## 3. Site Detail 公共读模型及可见性

在现有 \`GET /api/v1/sites/:publicID\` 上做兼容增强，避免旁路重复创建第二套身份服务：
- 现有 \`public_id, slug, localizations, addresses, interactions header\` 保留。
- Site only 新增经审核的 \`primary_category, secondary_categories, tags, supported_languages\`，可信 \`logo_url\` 和可选长期正文；视业务读路径决定是否同 API 中投影小型技术摘要。地址中不返回任何私有字段/审核理由。
- 新增可选 \`GET /api/v1/sites/:publicID/related\` 或同等单次受控投影，返回最多 6 个已审核、同地区的 Published SFW Sites，排除当前站点、其他区域不可见记录、旧版 unreviewed/draft/archived、重复 ID。按主类匹配高于补充类、共同标签作为增强，稳定 Public ID tie-break；Heat 只能低权重辅助。**不能用站点国家、域名相似、随机伪造、AI 向量或 Harvest 实时状态进行相似推荐。**
- 精简技术摘要 read model 可独立有界查询：基于 GoFurry 自己的 \`collection_current\` 当前 **active generation** 和 \`site_evidence_changes\` 已持久化语义事实，结合 \`collection_bindings\` 的归属与有效时间及已验证的 scope/schema/ruleset。在输出时只允许极少 whitelisted 技术事实；尊重最新有效绑定，旧域名的历史不能冒充当前技术。参考原 B1 Go \`normalizeWeb\` 的 \`tech.detected.*\`、\`http.response\`、\`tls.certificate\` 规范化格式和 yearbook 的 proven fact rendering，不能直接将整个 JSON 存储/原始 HTML/RDAP 联系方式返给浏览器。时间字段必须是 first-observed / latest-confirmed 明确含义和真实来源，不能称实际上线/技术切换时间；规则升级不等于网站升级。模糊或过期信息标注“上次记录”而非“当前保证”，优先不展示不可靠项。
- SSR 页面**不**向 Harvest、第三方站点、R2 HEAD、GeoIP 或实时探针发请求；最多几次有界的 GoFurry 区域 API 调用，不产生 N+1 DB 查询。年鉴使用已有 published Years API，不破坏年度归档状态/数据修订历史。
- 当前 \`site_public_navigation\` 仅准已审核的 SFW+published+有效主分类。D2-A 还有特殊 \`site_public_history\` 允许旧 D1 测试/待审核 legacy detail 继续访问。本阶段**必须保持旧详情/历史年鉴的既定兼容语义**，但 legacy/unreviewed 不可因此获得新相关推荐、近期统计、技术摘要、目录入口排名或搜索曝光；旧版临时详情可保持最小信息并标记 noindex，完成审核后再启用完整资料。CN绝不能泄漏 mixed/adult；INTL 目前仍同为公开 SFW。所有新增公开查询复用同一权威审核范围，不以 UI 隐藏代替后端检查。
- Site archive/审核撤销应立即从新推荐、统计和详情丰富信息的公开读模型排除；按已经冻结的已发布年鉴归档独立策略保留或隐藏，不任意改变年鉴访问权。
- 资源不存在（Logo/短简介/正文/技术数据/年鉴） => 合法的少字段页面而不是 503；GoFurry 地区数据库/API 真不可达 => 正确 503；不认识 Public ID => 404；Slug 错 => 301 保留 locale 和现有 URL 语义。不得暴露内部 UUID、Harvest Target 标识、管理员凭据或未审核 URL。

## 4. 统计、外链与 SEO

- 继续使用 D2-A 的 \`SiteDwell\` 真实可见停留约 3 秒规则，以及 \`siteOutbound\` 原生外链旁路计数；不能把服务端 SSR 或推荐卡片曝光直接当有效浏览，也不新建计数管线。备用地址访问仍使用同一计数规则，失败永远不阻止导航。
- 阅读详情与访问外部网站是两个清晰的意图，主 CTA 明显，支持中键、键盘、无 JS 时的原生外链；对未知/不安全 URL 不提供链接，不允许用户控制 redirect URL。
- 站点栏目内部分类/标签等点击指向 D2-B \`/sites/directory\` 的规范 URL；不要新建一级分类独立动态路由或更新已固定的八类。
- SEO：title+summary 由当前真实 Site 语言决定，正文不代替规范简短描述；只在有翻译的语言发布 hreflang，缺翻译明确 noindex。canonical 由已验证 \`WEB_PUBLIC_ORIGIN\` 和 immutable Public ID+当前 Slug 组合，/en-/zh- 路由遵循 CN/INTL 缺省语言，缓存保持审核撤销安全；避免把 Site 未审核内容通过预取缓存/客户端旧状态再渲染。
- 浏览器导航从目录回退时保持 filters/history 和合理滚动；使用普通 Router 跳转，不采用强制刷新来重置列表。
- 业务信息与来源事实明确分栏：人工简介/正文不被 Harvest 元数据修改，自动事实不冒充人工审核评价。不存在五星评分或评论计数。

## 5. 与 Start 的唯一受控连接

目前 Start \`apps/web/src/start/chrome.tsx\` 菜单有一个已存在的 **Sites** 禁用项：
\`<button aria-disabled="true" data-target={localizedPath('/sites', locale, region)} ... />\`

D2-C 仅允许把该项目切换成**真实的内部 Link / Popover.Close**，保持原文案、Phosphor 图标、尺寸、CSS class、菜单位置、触发与关闭方式、focus/keyboard semantics 不变。**其他 Home / Games / Login 的 disabled 状态不改。** 不许改 Start 的主题/玻璃/天气/搜索/壁纸/侧栏/全局样式/背景/Rail 元素。只改这一个导航连接行（及必要的行为验收），严禁借机“统一导航”重构整套 Start 菜单。

## 6. 数据库和后端工程边界

- 新 Schema 使用 **Goose forward migration**；不修改 0001–D2-B 历史迁移。简单长介绍应尽量利用已有 Site localization 行，不新加可配置 CMS 表。
- **新字段和关系默认无外键、无级联**；已经审定保留的四个 D1-A 内部从属 FK 不随意修改。无自增主键，Go 1.27.3 原生 UUIDv7、sqlc+pgx、encoding/json/v2；强一致性依赖局部事务、唯一索引、显式业务校验。对收藏/评论/user_id 不预建空表。
- 分离 Router、Handler、Service、Query；现有 D2-A navigation/heat/management 和 D2-B asset 代码应复用。新增只读 API 使用现有 rate limit 和区域头；不要为技术快照复制 Harvest 的目录或调度表。
- 内容编辑采用可审计的受控本地 CLI，后续 D4 LibreCosta Admin 通过 GoFurry 验证的 Management API 接入；本阶段不引入 Admin 凭据库或用户账号系统。
- 所有可见性判断都在 Go 后端执行，不能依赖浏览器 Cookie 或 \`/en\` 路由绕过 CN。Source 技术信息输出无原始 IP、完整 URL query、私密标头、证书敏感数据或 RDAP 私人信息。
- 没有真实 Site 资料时，使用清晰的匿名测试 fixtures 进行验收，不向开发持久 DB 插入假生产站点。不要添加默认生产样例页面内容。

## 7. D2-C 验收，导航阶段完成定义

1. 在一次性 PG18.6 + Redis8 测试环境中，Goose 从 D1-A/D1-B/D2-A/D2-B 向前迁移与重复 up 正确；已有 Site/Game/壁纸/年鉴/Heat/Logo/绑定行与 UUID 不变，无新不必要 FK/cascade。
2. 两个真实已审核 Site 的长介绍（zh/en）、无正文和缺翻译、Logo/URL 异常回退、分类/标签直达目录；CLI 更新一语言正文不覆盖另一语言/分类/地址/R2 对象，CAS 冲突正确。
3. Related：同类/标签排序、Public ID 稳定、最多 6、低相似候选少展示、无成人/草稿/旧版未审核/归档/本体、CN/INTL 独立，无 N+1。
4. Tech：B1 有效绑定 + current projection 的白名单事实，规则变化、域名迁移、过期/失效、410 replay gap、Harvester 停机；没有技术证据 => 不渲染技术摘要；有证据只显示真实来源和 observed-at，不造网站在线率或“安全”评分。
5. Site 详情：已发布年鉴链接、7 日可用互动数据；统计低样本时隐藏；外链断网/Redis 故障仍能打开；3 秒 Dwell 不重复计算；分类/语言、头像、文本、技术/年鉴的双栏→单栏响应式正确。
6. SSR/SEO：CN zh /en、INTL en /zh；200/301/404/503；已审核站点详情索引，已知旧兼容未审核详情安全降级/noindex，隐藏成人不泄露，yearbook 旧 URL/slug canonical 行为不变，Game/Start 不受影响。
7. Start：验证唯一 Sites disabled 项变成可访问的链接，菜单视觉像素布局/键盘操作/动画/主题不变，Home/Games/Login 保持当前政策；全套 Start regression/browser、移动 320/390、暗亮、reduced-motion、HMR 不下降。若 Start 视觉快照有变化，应定位问题，不能直接更新 Golden 遮盖回归。
8. 性能：真实 HTML 体积与页面 API 次数，100/1000/10000 Site fixtures 的 Related/Detail/Tech 数据查询与 PG buffer/CPU，0/1/多事实/大段正文/多语言极端样本；技术读取不重复 N+1；负载本地测量，不夸大生产指标。
9. Docker/Go/sqlc/Browser/Harvest/Yearbook/Wallpapers CI 实际通过。严格使用隔离测试数据库；不自动启动外部在线采集或破坏用户的共享 Tailscale dev DB。
10. 最终提交 docs/v0.1-d2-c-acceptance.md，含真实执行证据、截图/布局验收（必须来自实际浏览器）、新增 schema、CLI、API、性能、Start 门控以及明确遗留问题。CI 与最终 SHA 对应且绿色。推送 develop，不合并 master/pre-master、不发布 Release。

**D2-C 完成后，导航前台基本闭环，下一步直接进入 D3 Game 业务与资料库。** Admin 正式运营界面和旧站真实数据迁移依照 D4/D5，CN/INTL 内容同步依照 D6，公开 Beta 质量与部署依照 D7。不得因为后续用户/评论/站长认领或技术周刊而延迟 D2-C 结束。
