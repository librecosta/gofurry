## 正式初始化步骤与恢复

部署轮次应在 **停止应用写入的全新 CN 预备目标**运行。先验证归档摘要，显式迁移新 PostgreSQL 18，再为它创建独立 `isolation_token` 并将数据库 COMMENT 设置为 `gofurry-d5-b1:<token>`。CLI 仍要求环回 PostgreSQL、独立 `gofurry_d5b1_*` 数据库、环回 HTTPS S3/CDN 和独立 `gofurry-d5b1-*` 桶。准备目标时保持 Harvest、Admin 及其他写入者关闭。若部署目标与预备环境分离，授权部署人员另行整体提升已核验的数据库和对象，保留身份映射、回执、对象键、内容哈希及 Content-Type，并在放流量前复核新环境的数据库和 CDN。直接对在线实例应用不属于这个入口的契约。 [配置与守卫](v0.1-d5-b1-acceptance.md)

```text
task migrate ACTION=up CONFIG=<绝对路径/api.yaml>
go -C services/api run ./cmd/legacy-bootstrap verify --config <verify.yaml> --report <archive-report.json>
go -C services/api run ./cmd/legacy-bootstrap plan --config <install.yaml> --plan <plan.json> --report <plan-report.json>
go -C services/api run ./cmd/legacy-bootstrap apply --config <install.yaml> --plan <plan.json> --plan-sha256 <核准计划SHA256> --report <install-report.json>
go -C services/api run ./cmd/legacy-bootstrap verify-target --config <install.yaml> --plan <plan.json> --plan-sha256 <核准计划SHA256> --report <target-report.json>
```

YAML、计划、报告路径均为绝对路径。验包 YAML 含 `archive`、`package_sha256`、`work_dir`，安装 YAML 另含 `target`。每次执行使用新报告路径。只读计划绑定包摘要、数据库端点和目标身份。中断后保留同一归档、目标、原计划及摘要重跑，回执与 revision 保护已提交的数据及人工编辑。对象上传成功而绑定事务失败时，按原键校验后重用。数据库需要回退时，用经验证的目标 `pg_dump` 恢复到新库后核对对应对象清单。共享的内容寻址对象保留，避免误删其他有效引用。部署完成并有新写入后，回滚需先处理增量差异。

归档对应 2026-11-15 旧站快照。此后新增、修改和删除不会自动进入 v2，旧站与新站并行写入会产生分歧。部署负责人应对切换窗口内的变更做只读差异核对，确认编辑归属并按现有管理流程合入。涉及业务数据增量的处理需单独验收，不能靠重跑 v2 覆盖。

## 后续 Admin

现有管理入口已能编辑 Site 主备地址、分类、标签、普通/混合/成人分级，上传和替换 Logo，并发布、撤回、归档。Game 可编辑人工资料、纠正来源、发布或归档，Owner 可封禁及解除。合集可编辑双语资料、手工成员及排序，并发布及归档。区域资格由各部署的现有后端规则判定。

明确的最小缺口有两项。给 Admin 增加清除 Site Logo 引用的操作，复用已有的 revision 校验和 CLI 清除能力。为导入的合集补动态人工标签规则与排除项的查看和受控编辑，复用现有规则和关系语义。两项都可以在后续运营窗口安排。 [D4 管理能力](v0.1-d4-acceptance.md)
