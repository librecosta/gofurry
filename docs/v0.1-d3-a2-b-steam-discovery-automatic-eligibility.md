# GoFurry V0.1-D3-A2-B — Steam Incremental Discovery & Automated Eligibility

**状态：设计冻结 / 实施契约** · 2026-11-13  
**目标仓库：** \`librecosta/harvest\` + \`librecosta/gofurry\`，均在 \`develop\` 上工作；每个仓库分别提交/验证；**不修改** \`gofurry/steam-go\`、旧站、AI Gateway 或 Admin。  
**GoFurry 基线：** \`a163e4e4e49bbd07c347da07f777ce2026eab73f\`（D3-A2-A 已通过）。  
**核心目标：** 在不要求逐条人工审核/录入的情况下，Steam 新增或变更的 AppID 可以经过有预算的官方发现、可验证的采集、内容/题材自动判断，进入现有 D3-A1 Intake，最终形成**持久**已发布 Game；不能承诺所有 Steam 游戏都会被找到或自动通过。

先读各仓的 \`AGENTS.md\` / architecture / D1-B1、D3-A1、D2/D3-R1、D3-A2-A 验收与契约；核对 Harvest Provider Registry/egress/Job/Observation API、GoFurry Intake 与数据库、\`github.com/gofurry/steam-go v1.3.12\` 的实际 \`api/storeservice\`。任何“已实现”声明必须有对应的真实代码和隔离联调证据。

## 0. 绝对业务边界

1. **低人工**：普通新作品应能够自动发现、采集、定类、创建和按条件发布；现有 \`game-intake review\` 只能作为运营例外纠错，不得是全量人工流程、双证明手工填写或定期续期。AI/规则无法判断时，系统自动尝试补证据或轻量待定，不生成每条必须人工处理的工单。
2. **持久发布**：已发布的 Game/Site、标题、简介、封面、归属、Public ID 和历史新闻不会因为采集故障、数据老化、分类规则升级、API Key 失效、AI Gateway 停机或任何 30/180/365 天计时而自动消失；本阶段不得改坏已修正的 D2/D3-R1。只有明确、持久、可追溯的业务归档或有事实依据的成人内容处置能影响已有发布资格，且能恢复。
3. **两种判断不混淆**：是否兽人相关与是否含成人内容是不同维度。分类/模型输出不得因“没有成人标签”自动等价于已确认 SFW；但也不得额外要求两个操作者签署证明才准普通作品公开。基于足够、可追溯的来源证据进行自动决策；未知保持内部候选，绝不向公众伪造结论。
4. **来源归属**：Steam AppID 归属于 Steam GameSource；Game 身份和 Public ID 与 AppID 分离；发现、新闻、价格、在线人数永远保留平台和区域来源。跨平台关系仍严格遵守 D3-A1，不靠标题匹配合并。
5. **地区产品功能一致**：CN 只对成人内容、评论做明确控制；INTL 目前亦采用已有 SFW 公开策略；不对价格地区/平台/游戏类型增加额外 CN 产品功能限制。当前采集集中 CN，D6 处理 INTL 同步，不另建跨境数据共享库。
6. **零隐式机制**：没有隐藏的 TTL、定时复审、静默清空、失败自动下架、按上次采集时间删除作品、分类变更触发自动回滚发布状态。规则版本变更可以安排自动重新评价，但不能因为“待评价”而隐藏已公开的作品。

## 1. Harvest: Steam 官方分页索引 Capability

真实可用接口：Steamworks \`IStoreService/GetAppList/v1\`，官方文档 https://partner.steamgames.com/doc/webapi/IStoreService 。它需要 Web API Key，支持 \`if_modified_since\`、\`last_appid\`、\`max_results\`、\`include_games\`；响应为按 AppID 递增的 \`apps\`、\`have_more_results\`、\`last_appid\`，单项包含 AppID、name、last_modified、price_change_number。它不返回“兽人/SFW”判断，\`last_modified\` 是商店信息/价格变动信号，不是游戏发行日或 GoFurry 作品变更。旧 \`ISteamApps/GetAppList\` 已弃用。

**复用 \`steam-go\` 的 \`api/storeservice.GetAppList\`**，不能写新的私有 Steam HTTP SDK；新增一个清晰的、编译时白名单控制的 Harvest capability（建议 \`steam.catalog\`，独立固定 singleton resource，例如 \`steam.catalog/public\`；具体命名遵从现有 Provider Registry 约束），不得把全索引伪装成某个 \`steam.app\` 的观测。

- 请求仅允许官方 \`https://partner.steam-api.com/IStoreService/GetAppList/v1/\` 的固定路径和有界、规范参数，明确仅 games；本轮不遍历 DLC、软件、视频和硬件。固定 scope 包含 namespace/egress_region，输出 schema 单独版本化。
- **API Key 仅放在实际执行者的私有 YAML（显式文件配置）中**，由 Worker 在发送请求时注入；绝不放入 Harvest Target external_key、Job params、Schedule params、Observation、Consumer、GoFurry DB、URL 日志或客户端响应。若 SDK/egress 的路径校验无法在注入 Key 后保持可证安全，则先做最小、独立可测的许可扩展；不能默默把 Key 暴露到控制面或日志。无 Key 时明确 disabled/deferred，绝不循环 401 盲重试。
- 返回只是 **有界的索引页**（例如最多几百到 1000 条；根据实际 Observation/body 上限选合理页大小），严格验证 AppID 递增、无重复、有效名称和时间戳、响应体大小、页次连续性；越界/损坏/不一致 => 本页失败、**不能推进** GoFurry 发现游标。用真实 fixtures 校准，而非简单把整个官方响应存为无界 JSON。
- Harvest 保持原有 Server/Worker Permit、egress/bucket/rate limit、重试、统计和 per-Job 幂等。不要另建 Steam crawler、第二套队列、redis broker、任意 HTTP 代理，不能修改 \`steam.details/news/players\` 既有契约。
- **Discovery 索引结果应与普通已绑定 Game 的 Consumer stream 隔离**：优先单独 namespace 与读权限/单例 Target，GoFurry 从其有界 Job/Observation API 拉取页；不能让既有 CN business Consumer 因未知 \`steam.catalog\` capability 报错，也不能把每页成百上千条索引写入 \`game_source_metadata\`。若选其他方案，必须证明完全向后兼容并解释成本。
- 同一索引页响应与 Job/Attempt 需可验证归属；同值确认的问题可只在必要时为 Harvest Job GET 增加最小、向后兼容的 per-scope confirmed-result 引用（含 Observation/hash、确认时间），不把整套事件流重构成新协议。**如果现有来源不足以证明结果属于本次执行，不得把旧页冒充新页并推进游标。**
- Harvest 有权只提供此 capability，不负责判定“furry”、创建 Game、运行 GoFurry 自动发布或存储它的作品业务表。

## 2. GoFurry: 独立持久的轻量发现游标与筛选

新增**最小**业务 Discovery Worker/Service（仍在 GoFurry 单体 API 中，显式配置开启；不另建进程）：

- 保存 \`scan_started_at\` / \`if_modified_since\` 的完整扫描窗口和页内 \`last_appid\`，以及是否完整结束。只在成功验证、保存**本页所有入围候选及其发现去重决策**后提交页游标；全部分页成功后才推进完整窗口水位线。崩溃、停机、Key 失效/429/超时、重叠扫描、同次新增/变更和分页结束必须无遗漏/重复的失败语义。
- 建议初次默认以可控的最近变更窗口启动，保留**可显式启动并可暂停/恢复的冷启动全量回填模式**；不能首次启动就把 Steam 全部游戏逐个请求 details。冷启动大页扫描受小批量预算与节流控制。
- 处理 index 时优先匹配 **已知 GameSource、既有 GoFurry 已审核作品/旧站导入可信种子** 及与兽人相关的明确标题/描述线索；价格变更信号可作为“已收录游戏适时检查价格”的候选，不等价于新游戏或新作品更新。
- \`GetAppList\` 只有名称/AppID/时间，无法独立判定作品题材。**过滤规则不能仅保留含 furry/fox/wolf 等关键词的标题然后宣称覆盖所有兽人游戏**；应允许低频有预算的探索采样与可信种子，后续真实已证明的来源扩展可进入同一个 Intake，绝不制造“搜索覆盖率 100%”假指标。
- 发现索引可跨页临时流式处理、只存窗口游标 + 已选择的 AppID/轻量决策，而不是复制全部 Steam App List 建第二个百万行内容平台。既有 \`game_intake_candidates\` 10,000 未完成条上限严格保持，限流时延迟发现接入而**不是直接丢弃高优先候选或卡死所有索引扫描**；按需求持久少量待输送候选/溢出游标。入围名单必须能重复提交、无重复 Game。
- 所有真正的深度请求走现成 \`Intake.SubmitSteam(key,"discovery")\` 和 Harvest \`steam.details\`。不得直接从 GoFurry API 发公网 Steam 请求、重复实现 Job/Target/Consumer，也不要把 discovery 与 Intake 的生命周期合并成一张万能表。
- 操作接口只给受控 CLI 与内部 API 生命周期，可有 \`game-discovery status\`、\`scan-once\`、\`pause/resume\`、预算/效果概要等，**不开放公共写接口或图形 Admin**；D4 可复用同一业务服务。配置只在明确 YAML，有界分页/日预算、单例/锁和超时，默认关闭；与 Intake 各自的独立处理界限明确。

## 3. 自动题材识别与成人内容判断：取消逐条人工证明

为已有 D3-A1 Candidate 引入**版本化、可解释的自动分类决策**，不再要求 \`game-intake review APP_ID FURRY_REF SFW_REF\` 才能正常发布。

建议内部结果两维：

- \`furry_relevance = relevant | irrelevant | uncertain\`;
- \`adult_content = sfw | adult | uncertain\`.

判定输入只可来自确认归属的 Steam \`details\`、经过验证的内容描述/显式标签或其他可靠证据、必要时允许的媒体分析；不要使用未清洗 HTML、无来源的 AI 推断、用户评价文本、缺失 adult 标签等作为“充分正面证据”。抽取 \`source_id, observation_id, scope, key fields/limited excerpts, ruleset_version, decided_at\` 等**必要**依据。证据不足就待定，不是每条新建人工工单。

**不要要求两份人工审核文件**：明确的正向题材特征、足够的成人内容判断输入及匹配可靠性，在证据充分时由自动策略直接完成公开。旧手工 \`review\` CLI 仅用于例外覆盖、纠错与处理争议，不是业务的前置步骤。

建议两级分类机制：

1. **低成本确定性识别**：商品类型判定，显式题材语义、Steam 实际可获得的元数据、来源特征、已知作品的稳定关联信息；可安全拒绝非 Game/DLC/明显无关项。若要补充如 \`required_age\` / \`content_descriptors\`，应在 Harvest \`steam.details\` 内做受控、向后兼容的最小扩展；不得依赖未经证实的字段，Steam “未填写成人标签”不等于 SFW。
2. **可选的模型辅助识别**：仅在确定性证据不足、候选优先级足够高、日预算允许时使用 **已存在 LibreCosta AI Gateway** 的受控文本接口（当前已有 \`/v1/chat/completions\`，不是完整图像审核产品）。GoFurry 仅作为有限时、有限 token、明确 YAML 配置的内部客户端；不得修改 AI Gateway 仓库、隐式连接环境密钥、存整段上游内容、让模型自己打开未知 URL。返回结构严格校验、来源片段可追溯；调用失败/结果不确定只影响**新候选的判断**，不会导致既有 Game 下架。**模型本身的“自信分数”不足以证明非成人**。
3. 若没有已配置模型或真实证据不充分，仍可通过确定性证据直接自动公开其能证明的高质量候选，其余保持轻量待定并按新资料自动重试。不要“AI 关闭 = 整个 Intake 停止”或“每条都退回人工审核”。

- 对自动首次发布必须保留持久的自动发布依据：明确 Game、GameSource、作品类型、furry 与内容等级决议、证据来源、版本与时间；与现有 \`game_approved_presentations\`/catalog 公共读取结合。使用\`games.status='published'\` 持久状态，**不在 GET 查询中计算当前 AI 分数是否还满足阈值**。
- 如果已发布游戏之后发现**确切成人内容**，按 D2/D3-R1 的持久出版处置写入具体事实、原因与版本并可恢复；单次模型输出“uncertain”、源 HTTP 错误或新规则版本未重新评估不能自动隐藏 Game。CN/INTL 暂按现有 SFW 发布政策，不为游戏题材/Steam 价格增加地域功能限制。
- 允许编辑明确否定自动分类结果；修正值持久优先，下一次采集不能把运营修正覆盖。禁止定期人工复审、180 天证据到期、未采集 30 天隐藏、模型配置变化导致公开内容被动消失。

## 4. 数据模型与工作流边界

优先复用现有 \`game_intake_candidates\`、\`game_sources\`、\`game_source_metadata\`、\`game_approved_presentations\`、\`catalog_publication_decisions\`、\`collection_bindings/plans/current\`。

仅允许针对实际缺口增加：
- 一份极简的 \`steam_discovery_state\`（独立窗口/游标/版本、统计与必要小批量入围状态）；
- 自动 eligibility 的小型决议/版本/来源引用，可以借用现有 Candidate 增列而不是再创通用审查数据模型；
- Harvest 单例 catalog Target 的合理 Provider resource + typed request/output schema，必要的未变化确认附加元数据。

**不要**建立通用审批工作流、评分表、用户行为画像、全 Steam 二次镜像、AI 训练数据库、每个元数据字段一张表、向量数据库、二级大后台、单独 Kafka/Redis 队列、跨库外键或自增 ID。新表默认无 FK/级联，UUIDv7+PG18+sqlc+pgx，Go1.27.3+JSONv2+Fiber v3+Cobra/Viper 仅文件配置。修改都使用**新** Goose forward migrations，不能改写历史。

外部 Harvest 提交不参与 GoFurry PG 事务。先写本地持久意图，远端 Job 需幂等提交或只读核对，源响应验证成功后在单个本地事务内推进发现游标及候选。Steam keys/AI token/原始 HTTP Query 或认证数据不得存到 DB 或日志。

## 5. 验收（两仓分别绿灯，端到端真实代码 + 模拟外网）

- Harvest：真实 Server/Worker、真实 \`steam-go\`、模拟的官方 GetAppList，带 Web API Key 的 Worker YAML；校验唯一注册、固定 Host/Path、敏感 Key 从 Job/Observation/日志/HTTP public 响应中绝不出现、授权和 bucket 扣减、不同分页/限流/恶意数据/超大页、重复任务与同值确认。原 \`steam.details/news/players\` 和 Web Provider 不回归。独立提交与 CI。
- GoFurry：隔离 PG18.6/Redis + 编译后的 Harvest，模拟大于一个索引分页、有间断/失败/重复 AppID/跨窗口变化/价格变更的 Steam API；停止、重启、重复启动/并发两个 worker、Job 丢回包、Consumer 410 时 **完整窗口不漏项，单个候选不重复建档，已发布 Game 不消失**。
- **自动化实际效果**：使用可复核的正面 furry+SFW 与无关、成人、未知、DLC/Demo/同名不同作品等 fixtures，证明**存在不需要任何人工 review 命令即可公开的新 Game**，否则不得声称实现了自动收录；题材误判、成人误放行和未判定比例分别报告，写明 fixture 局限，不能称模拟集代表真实生产精度。
- 至少一种模型服务不可用/关闭、模型返回畸形/虚假引用/超预算时，整个系统继续工作，已发布作品、已经证实的确定性候选不受影响；不能把“AI 关闭”当作必须人工复审每一条的理由。不在测试中调用收费模型，真实分类效果待后续单独评估。
- 执行 100/1000/10000 索引行与 Candidate 指标，明确吞吐、Hash/DB 索引成本和深度采集预算；不得模拟用“批量成功”掩盖单页游标错误。无主分类的 Site 与已有 D2/D3-R1 的稳定公开、年鉴、Start、壁纸、SSR 不得回归。
- 已发布 Game 在**31/181/365 天不采集**、Steam key 失效/源离线、模型服务失联、Consumer 故障时仍 200，真实人工覆盖优先；已显式成人处置的 Game 不因重新扫描解除封禁。
- \`task sql:check\`、\`task check:api\`、\`task check:catalog\`、\`task check:collection\`、适用 Go/HMR/Web/Start/Docker/Containers，两个仓库各自最终 CI 匹配提交并 success。仓库修改只限声明范围，不把样本数据写入共享/生产 DB，不连真实 Steam 或收费 AI 实测。

交付：
- Harvest：\`docs/...d3-a2-b-steam-catalog-acceptance.md\`（文档按仓库命名规则），含 Provider、密钥位置/保护、page/Job 证据、协议变更、CI。
- GoFurry：\`docs/v0.1-d3-a2-b-acceptance.md\`，含自动发现/分类/公开实际轨迹、业务回归、吞吐、准确度测试集局限、Goose/运营 YAML、双仓最终 SHA/CI，以及**仍未实现的真实 itch Provider**。

## 6. 明确不能夸大范围

本轮实现 Steam 官方增量目录发现、低成本候选筛选、与 D3-A1 Intake 实际连通，并建立**可以自动发布至少部分证据充分的正常兽人游戏**的可用代码机制。它不保证全量 Steam 兽人作品覆盖率，不保证 AI 风险分析零错误，不声称当前 itch.io 已采集，也不提供游戏首页/完整目录/合集/视觉页面。

对外正式开放大规模无人发布之前，需要基于旧站真实标注样本（D5 才有真实迁移）衡量误判和自动通过率。没有真实生产样本时报告“待生产质量验收”，而不是要求开发者手工填过场式审核引用。后续 D3-A3 验证 itch.io Provider；D3-B/C 实现游戏页面；D4/D5 完整运营和真实数据验收。
