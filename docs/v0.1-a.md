## Compatibility details and limits

The configuration follows the [TanStack Start Vite/Node hosting guide](https://tanstack.com/start/latest/docs/framework/react/guide/hosting) and [official StyleX Vite integration](https://stylexjs.com/docs/learn/installation/vite/). Start precedes React; StyleX uses its own pre-transform before Fast Refresh. Module-entry SSR needs explicit `devMode: 'css-only'`, an initial `/virtual:stylex.css` link and the official virtual CSS subscriber. A real root CSS entry receives extracted production styles. Theme selection stays entirely in CSS to keep SSR/hydration markup identical.

- Nitro's supported Vite Node adapter is currently a beta. It is pinned and verified here; reassess it with framework upgrades. Rolldown emits `MODULE_LEVEL_DIRECTIVE` warnings for bundled third-party `use client` markers during Nitro's SSR bundle. The build and runtime/hydration tests pass; warnings were not suppressed or patched. Framework startup/shutdown banner lines remain console text alongside the application's JSON logs.
- Docker Hub authentication was unreachable on this host. ECR's mirror of the same official pinned Node/Go versions worked; the README documents the exact build overrides. Default Docker Hub builds were not verified locally.
- Playwright's fresh Chromium download stalled, so local UI validation used installed Chrome via the documented channel override. CI installs Playwright's pinned Chromium; its result is separate from these local checks.
- Container runtime verification covers Linux amd64. ARM64 and production reverse proxy/TLS behavior were not verified. Nginx is an inactive example. No existing Docker service was modified by the test commands.
- PostgreSQL/pgxpool remain deferred because no current code consumes a database. There are no placeholder migrations or resource abstractions.

The supplied root implementation document is preserved as an existing untracked file and is not included in the engineering commit. Commands and structure are documented in `README.md`; CI reuses the same Task checks without initializing the legacy Submodule.
