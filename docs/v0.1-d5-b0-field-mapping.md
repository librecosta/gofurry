# D5-B0 · Source-to-Target 字段映射

**映射 v1** · 输入为实际 D5-A `schema_version=1` · 目标核对基线 `864878f161f080e69266c9d3aa4d83208ebf2d47`

“目标”指基线已有字段。“新增”指 [导入契约](v0.1-d5-b0-editorial-import-contract.md) 限定的 B1 补齐。“证据”保存在私有 Seed 及对账回执中，可按完整旧键找回。实际值、比例和冲突数量待真实备份验收。

## 1. 包与公共字段

| D5-A 实际结构或字段 | B1 用途 |
| --- | --- |
| `manifest.json` 的 `schema_version, snapshot_id, backup_sha256, legacy_source_commit, created_at, content_sha256, files, summary` 及 `SHA256SUMS` | 严格 V1 校验。备份、内容、来源版本、文件 `path/sha256/bytes/rows` 进入核验。快照标签与创建时间用于审计。内容哈希与核准计划摘要决定重放。 |
| 每个内容行的 `source.database, source.table, source.legacy_id, source.key` | 校验源库别名、真实表及完整键。Site/Game/合集/人工类别/标签的实体键进入各自持久映射。关系与异常使用全键，复合键的 `legacy_id` 只重复首项。 |
| `status`、`issues[]`、`raw`、`candidate` | `usable/needs_mapping/conflict/invalid/archived` 为清洗状态。按字段处理，允许有告警的实体保留有效内容。`candidate` 经过目标约束重验。原始值、私有说明及超限占位仅作证据。 |
| `reports/issues.ndjson` 的 `source/code` | 对齐原清洗问题。与 B1 新增的目标冲突分别统计。 |
| `reports/mapping-candidates.ndjson` 的 `source, kind, state, legacy_appid, platform_link_candidates[]{platform,url,relation}` | Site 组对固定词表、Game 对平台的辅助提议。`unmapped`、`steam_identity_candidate`、`conflict`、`unresolved` 及链接关系等都不构成最终决议。 |
| `reports/excluded-release-rows.ndjson` 的 `source/code` | GFG 非人工发行证据的逐键排除记录，计入 `excluded_upstream`。同一旧游戏可在两张发行表分别计数。 |
| `reports/summary.json` 与 `summary.md` | 对账数据和 GFA 脱敏类别计数。GFA 账号、操作员和内容无目标导入。 |
| `candidate.translation_languages` 与 `candidate.*_utc` | 旧 `zh-CN` 映射目标 `zh`，`en` 原样映射。时刻保留旧 raw 和已转换 UTC 两层证据。新站 `created_at/updated_at/revision` 使用实际目标事务。 |
| 含双语文案的各实体 `raw/candidate.name, name_en, info, info_en` | `name/info → zh.name/summary`，`name_en/info_en → en.name/summary`。复用有效纯文本、目标长度 1–160 / 0–2000 字符等验证。无合格名称的 locale 留空。摘要无值用空串，超限或无效摘要在新建实体的有效 locale 中留空并报告。原值保留，禁止截断或伪造翻译。集合层见以下各表。 |

D5-A v1 的实际 `content/` 共 15 个 NDJSON 文件。`site_addresses_candidates.ndjson` 和 `game_release_candidates.ndjson` 覆盖不同的真实 `source.table`。`assets/` 的 `site-logo-index.ndjson` 和内容寻址文件单独对账。 [D5-A 表描述符](../services/api/internal/legacyseed/schema.go) · [实际导出与派生清单](../services/api/internal/legacyseed/extract.go) · [V1 离线校验](../services/api/internal/legacyseed/verify.go)

## 3. Site 历史地址候选

实际文件 `content/site_addresses_candidates.ndjson`。统一派生字段 `candidate.url/address_basis/open_at_snapshot` 为候选证据。只有核准当前地址写 `site_addresses(id,site_id,url,kind,active)`。同站 URL 去重，最多 16 项、唯一主地址。历史区间走保全而非业务地址或重定向。

| `source.table` | 逐字段保全和取用 |
| --- | --- |
| `gfn_collector_domain` | `id/site_id` 定位配置和 Site。`prefix/name/tls` 解释 HTTP(S) 候选，`deleted` 保留生命周期及当前候选缺失原因。无有效归属或历史记录只供查核。 |
| `gfn_target_tracking_periods` | `id/collector_domain_id/site_id/target` 保留跟踪及归属。`tracked_from/tracked_until/tracking_basis/opened_reason/closed_reason/created_at/updated_at` 和 UTC 候选只作历史证据。丢失协议或所有权冲突进入待决。 |
| `gfn_site_primary_target_periods` | `id/site_id/target_tracking_period_id` 对照历史跟踪期，`effective_from/effective_until/basis/created_at/updated_at` 及 UTC 候选用于核对时段、归属和基础。明确的旧主目标依然需要核准为当前业务地址。 |

这三类地址历史不进入 Harvest 绑定、技术快照、年鉴和 DNS。数字路径将来只读取 D1 的已审旧 ID 映射。 [D1 数字路径](v0.1-d1-a-legacy-mapping.md)
