# STEAM-R1-F2 · 公开媒体画廊

## 画廊数据与交互

Game Profile 优先使用本区域 Profile API 的 published_media v2。Web 按封面、角色图、截图与影片处理同一份正式选择，保留各数组的编辑顺序以及字符串 ID。同一个 URL 可以对应不同影片或官方图片角色。媒体语言取自快照，页面语言保持 URL 所指定的语言。使用另一语言的正式快照时，媒体区显示实际语言。[R1-F1 公开媒体契约](steam-r1-f1-published-media-projection.md)

缺少可展示的新版媒体时，画廊继续读取旧版 Steam Source，沿用来源切换、Header/Capsule、截图和 MP4/WebM 直链。正式封面优先在 Hero 显示，加载失败时尝试旧封面。SSR 提供标题、封面、媒体导航和 canonical/hreflang。无脚本时可以打开截图原图、官方图片和直接视频文件。仅有流媒体的影片可从官方 Steam 商店入口查看。

新版画廊按截图、预告片、官方美术分组，图片使用原构图。截图卡优先缩略图，放大优先原图，任意一个加载失败时尝试另一个。Library Capsule、Hero、Logo 和 2× 变体分别标注。影片卡显示名称、封面和可用的精选标记。Base UI Dialog 负责焦点约束、Escape 与焦点还原，左右方向键和前后按钮切换媒体。视频原生控件保留自己的键盘操作。画廊使用现有 Motion 和 reduced-motion 设置。

## 播放与资源生命周期

| 顺序 | 预览方式 |
| --- | --- |
| 1 | 浏览器能识别的 MP4 Max、MP4 480、WebM Max、WebM 480 |
| 2 | 浏览器支持原生 HLS 时使用原生播放器 |
| 3 | 运行时支持 MSE 时，加载锁定的 hls.js 1.6.19 light |
| 降级 | DASH-only 和缺少可播放来源分别提示，保留已发布名称与封面 |

首次打开画廊加载卡片和懒加载图片。打开具体影片后才初始化播放器、检查格式并为选中的来源加载元数据。用户通过原生控件开始播放。直接文件或原生 HLS 失败时，可以沿上表尝试后续可用来源。HLS 加载器在每类请求上使用有限超时，播放使用单一实例和有限前后缓冲。浏览器将部分网络与 CORS 错误统一标记为加载失败，画廊按失败阶段提示。这些错误只影响正在预览的影片。

切换条目、关闭 Dialog、收起画廊和离开游戏页都会停止当前播放。关闭时播放器先退出，Dialog 继续完成自己的退场动画。播放器清除计时器和事件处理器，销毁 HLS 实例，撤销 MSE 资源并移除 video src。已经过期的动态导入、网络与媒体回调无法挂回播放器。

## 加载边界

Web 保留原有旧版 URL 校验，另对公开 v2 URL 实施 2,048 UTF-8 字节上限。使用 HTTPS、已审核 Steam CDN 域名与正确子域边界，限制默认端口、文件扩展名和镜像站静态路径，过滤凭据、查询、片段、控制字符、错误编码和路径穿越。截图、静态图、MP4、WebM、HLS 和 DASH 各自验证。影片名按纯文本渲染。

Game Profile 文档的 CSP 对图片、媒体和连接分别列出允许的 Steam CDN，Blob 只用于 media-src。Steam 中国与 ECCDNX 镜像只允许作为图片来源。目录和 Profile 之间跨文档加载，使 Profile 的 CSP 生效并避免影响其他页面。Profile 间和语言切换继续使用原路由。原生播放以匿名模式连接 CDN。HLS.js 使用 FetchLoader 校验解析后的 Manifest、相对清单、媒体段和初始化片段 URL，请求省略凭据与 Referrer，拒绝重定向并保留必要的 Range 请求。合法且可直接读取的公开 Steam VOD 无需代理。

采集、编辑、发布、数据库和公开 API 契约沿用 R1-F1。R1-F2 的播放范围是原生 MP4/WebM、原生 HLS 与 HLS.js。DASH 来源继续保存在 DTO，公开画廊提供可读的降级状态。
