# Official wallpapers

Local uses read-only `showDirectoryPicker` in supporting secure contexts. IndexedDB `gf-wallpaper-folders/handles` stores one DirectoryHandle per deployment region, never image bytes or indexes. Permission is queried on reuse; only an explicit user click may request it. `webkitdirectory` fallback is session-only and says that selecting again may be necessary. Memory-only scans cover static JPEG/PNG/WebP/AVIF, at most 2000 images/10000 entries/16 levels, files <=50MiB. Scans yield every 32 entries and cancel on workspace close. Fixed restores by relative path without scanning; random uses the current bounded index. Missing files/permissions preserve preferences and fall back to theme, never Featured. Browser local thumbnails use a single shared decoder budget, immediately close ImageBitmap and retain only small page/selected-preview blobs. Page/tab/modal cleanup cancels pending work and revokes their URLs. EXIF is parsed only for the selected file using dynamic exifr, with an explicit date/camera/lens/exposure/author/copyright allowlist and GPS disabled; unsupported metadata leaves normal basic information. No local file, EXIF, filename/path or coordinate is sent to any API/third party.

Native Chrome verification (2026-11-06) used a user-selected generated repository test folder: real DirectoryHandle structured-clone storage, read permission `granted`, 21 files over 9/9/3 pages, JPEG model/copyright and fixed-path refresh restoration passed with no non-GET network requests. The browser's own picker was selected by the user after desktop automation stopped; subsequent application checks were automated. A separate real File input test verifies the compatibility fallback and its lack of refresh restoration. This does not assert File System Access support or permission persistence in every browser; browser/version/site settings control those permissions.

The Start background entry closes Settings completely before opening a separate Base UI/Motion library Dialog, restoring focus to Settings on exit. The desktop workspace is 38% preview/details and 62% browser, at most 1280px/94vw and 90dvh; mobile stacks independently scrollable sections. Featured/精选 and Local/本地 are the only source tabs. Browsing or tab changes never apply an image. Featured pages request nine WebP previews with 300ms cancellable search, fixed-size loading slots and stable paging. At most three recently visited pages live in component memory for 30 seconds. HD is opt-in in the preview; only applying a wallpaper starts the fullscreen HD pipeline. Card and detail pin actions share the same preference. Off, random and fixed are explicit modes; only a confirmed fixed-detail 404 resets the preference.

Each deployment owns `start_wallpapers` and `wallpaper_audit_logs`; no Admin database or identity integration. UUIDv7 IDs, bound pgx/sqlc queries and explicit Goose migrations are authoritative. Configure one private YAML; optional `database: null` and `management: null` keep other APIs independent. Never inherit PG*/DATABASE_URL credentials.

`task migrate ACTION=status|up CONFIG=<absolute YAML>` maintains only the configured deployment. Status is read-only; serve never migrates. `task sql:generate` / `task sql:check` use pinned sqlc. CN/INTL need physically separate databases and credentials.

Management is a separate App, never registered on Public, and requires database, storage, a distinct `127.0.0.1`/`::1` address and exactly 32 crypto/rand bytes as canonical unpadded base64url in `management.token`. No CORS, Cookie authentication, arbitrary object operations or forwarded-client trust. All routes require Bearer plus `X-LC-Actor-ID/Name/Role`, UUID `X-Request-ID`, matching `X-LC-Region/Environment`. Actor claims are audit snapshots from the authenticated Admin service, not separate proof of a human identity or permission. Scope is limited to official wallpapers; Admin capability enforcement arrives in C3.

`GET /internal/v1/readyz` checks database and schema. Public readiness remains about the public lifecycle, so optional wallpaper infrastructure does not disable search/weather. Both Apps share one pool and Service; shutdown drains both before closing shared resources. Management has a 120/minute global budget, 16 active connections, bounded I/O and 90-second operation deadlines. Public retains its existing 1 MiB body limit.

Upload: `POST /internal/v1/start/wallpapers`, multipart fields `image`, `preview`, `title`, optional `source_url`, `credit`, `sort_order`. Both files are mandatory. Unknown/duplicate fields are rejected. Limits: 50 MiB image, 5 MiB preview, 64 MiB entire stream; two concurrent uploads, one full decode at a time. Streaming is enabled and fasthttp's multipart preparse disabled, so files spool once into private temporary files, removed on every return path. Read timeout bounds incomplete clients. No submitted keys or dimensions are accepted.

Since C3, new high-resolution files must be AVIF, previews WebP, both exactly 16:9 by integer cross multiplication. Preview maximum is 480×270; HD remains resolution-independent within the existing 36MP/16384px/50MiB bounds. [gav1d/avif](https://github.com/gen2brain/gav1d) v0.2.6 performs full AV1/item/grid decoding with an explicit pixel limit; x/image/webp performs full WebP decoding. The additional bounded container walk rejects animation, Exif/XMP, unknown metadata items, malformed sizes and trailing data. Maximum 36MP/16384px image and 4MP/4096px preview (including normal 8K images); extreme >20,000 pixels per encoded byte is refused. No system media runtime or transcoder is required. Test fixtures are locally generated synthetic images, not operational content.

Go computes SHA-256 keys under `start/backgrounds/`; uploads use HEAD plus immutable conditional PUT. Existing objects must agree in hash/bytes/type. S3 HEAD/GET and configured public GET are checked before Draft+audit commit. No arbitrary URLs, redirects, implicit proxy, overwrite or deletion. Storage and PostgreSQL cannot commit together: failures leave reusable immutable objects, never fake successful records or blind cleanup. A duplicate original returns 409; only one database row can own its image key. No SFW/copyright approval is implied by upload. Admin generates metadata-free AVIF/WebP from one crop and requests explicit human review.

Management base `/internal/v1/start/wallpapers`: GET list (`status`, literal title `q`, `page` 1–1000, `page_size` 1–50); GET `/:id`; POST multipart; PATCH `/:id` with the editable metadata fields plus required `revision`; POST `/:id/publish|archive|restore`; DELETE `/:id` Draft only, never storage objects. JSON inputs are strict, at most 16 KiB. Metadata edit requires title and replaces title/source_url/credit/sort_order together. Other actions require `{ "revision": n }`; publish additionally requires `"confirm_public_use": true` from the administrator's explicit manual SFW/authorization review. Mutation results return current details, transitions return `{wallpaper, changed}`. A repeated target state with the current revision returns `changed=false`; old versions return 409. UUIDs, version/state mismatches and missing dependencies have bounded 400/409/503 responses.

Only `draft → published → archived → draft` is allowed. Every transition verifies both immutable resources at S3 and the public path before taking a short row lock, then rechecks revision/state. Changes, revision/timestamps and explicit audit summaries commit together. Published timestamps come from PostgreSQL transaction time. Restore always requires another explicit publish. Deletion preserves historical audit without an asset delete or Admin foreign key.

Public `/api/v1/start/backgrounds?page=1&page_size=9&q=` reads only Published rows with PostgreSQL LIMIT/OFFSET, returning `{backgrounds,total,page,page_size}`. Page is 1–1000, size 1–9 and q at most 128 Unicode characters without controls. Literal case-insensitive title/credit search and `sort_order, published_at DESC, id` produce stable pages; count/list share a repeatable-read snapshot. `GET /random?exclude=<uuid>` returns one Published item (or 404 for an empty catalog), excluding the current ID when another exists; it is registered before `GET /:id`. Detail never exposes Draft/Archived. DTOs include title/credit/source URL, asset dimensions/bytes/type and creation/publication timestamps, without audit/actor data. Source URLs are declarations, never fetched.

No static JSON or object HEAD is used by public reads. Each deployment-owned Service caches at most 64 page/search combinations for 60 seconds, checks database reachability even on a fresh hit, and invalidates after metadata/state/delete commits. A generation counter prevents in-flight old reads repopulating an invalidated cache. No stale-on-error or cross-region fallback; no database means an empty page, configured failures mean 503. Public URLs come only from the configured storage base. Browser/API image bytes still go directly to the CDN. Start uses a unified regional versioned `gf-wallpaper:CN|INTL` preference, default official random, official fixed by UUID and off. Only confirmed detail 404 resets fixed to random; timeout/503 retain the selection. Off performs no catalog/image requests. Locale/theme/resize do not change the session selection. The Web metadata relay forwards only catalog parameters, checks Region/SFW and never forwards visitor headers or image bytes.

Migration input remains at `internal/handlers/backgrounds.json` with no runtime embed. `task wallpaper:import CONFIG=... BUCKET=... PUBLIC_BASE=... REVIEWED=true` requires literal local listeners/database, development environment, exact bucket/domain confirmation and human SFW/public-use review. It reads only the configured development objects, fully validates their format/dimensions/privacy and public content, then creates Published UUIDv7 records with system audit. Source URLs are metadata, never fetch targets. No legacy production URL is requested, and no PUT exists in this command. Reruns match immutable assets and preserve any existing state; they cannot republish an archived record. No permanent legacy-ID map is stored. Common credential-bearing source URL queries/fragments are refused to keep secrets out of public metadata and audit.

## Local acceptance — 2026-11-05

C3 migration `202611050002` preserves incompatible C2 legacy rows via PostgreSQL `NOT VALID` constraints, which still enforce **all new inserts/updates**. If a deployment is already compliant it validates the constraints immediately. An old incompatible Draft remains readable/deletable but cannot publish; upload a new AVIF Draft, review it, then explicitly delete the old Draft using its revision. Never silently delete rows, rewrite Published objects or overwrite R2. After explicitly resolving every incompatible row, maintenance may run `ALTER TABLE start_wallpapers VALIDATE CONSTRAINT official_wallpaper_avif` and `... official_wallpaper_ratio`. CN's prior C2 test database contained one WebP Draft; it was reported and left untouched. Existing CN/INTL Published 1920×1080 AVIF + 480×270 WebP records were inspected and comply. C3 acceptance uses new databases instead of resetting those records.
