# Official wallpapers

Each deployment owns `start_wallpapers` and `wallpaper_audit_logs`; no Admin database or identity integration. UUIDv7 IDs, bound pgx/sqlc queries and explicit Goose migrations are authoritative. Configure one private YAML; optional `database: null` and `management: null` keep other APIs independent. Never inherit PG*/DATABASE_URL credentials.

`task migrate ACTION=status|up CONFIG=<absolute YAML>` maintains only the configured deployment. Status is read-only; serve never migrates. `task sql:generate` / `task sql:check` use pinned sqlc. CN/INTL need physically separate databases and credentials.

Management is a separate App, never registered on Public, and requires database, storage, a distinct `127.0.0.1`/`::1` address and exactly 32 crypto/rand bytes as canonical unpadded base64url in `management.token`. No CORS, Cookie authentication, arbitrary object operations or forwarded-client trust. All routes require Bearer plus `X-LC-Actor-ID/Name/Role`, UUID `X-Request-ID`, matching `X-LC-Region/Environment`. Actor claims are audit snapshots from the authenticated Admin service, not separate proof of a human identity or permission. Scope is limited to official wallpapers; Admin capability enforcement arrives in C3.

`GET /internal/v1/readyz` checks database and schema. Public readiness remains about the public lifecycle, so optional wallpaper infrastructure does not disable search/weather. Both Apps share one pool and Service; shutdown drains both before closing shared resources. Management has a 120/minute global budget, 16 active connections, bounded I/O and 90-second operation deadlines. Public retains its existing 1 MiB body limit.

Upload: `POST /internal/v1/start/wallpapers`, multipart fields `image`, `preview`, `title`, optional `source_url`, `credit`, `sort_order`. Both files are mandatory. Unknown/duplicate fields are rejected. Limits: 50 MiB image, 5 MiB preview, 64 MiB entire stream; two concurrent uploads, one full decode at a time. Streaming is enabled and fasthttp's multipart preparse disabled, so files spool once into private temporary files, removed on every return path. Read timeout bounds incomplete clients. No submitted keys or dimensions are accepted.

High-resolution files may be AVIF/WebP, preview must be WebP. [gav1d/avif](https://github.com/gen2brain/gav1d) v0.2.6 performs full AV1/item/grid decoding with an explicit pixel limit; x/image/webp performs full WebP decoding. The additional bounded container walk rejects animation, Exif/XMP, unknown metadata items, malformed sizes and trailing data. Maximum 36MP/16384px image and 4MP/4096px preview (including normal 8K images); extreme >20,000 pixels per encoded byte is refused. No system media runtime or transcoder is required. Test fixtures are locally generated synthetic images, not operational content.

Go computes SHA-256 keys under `start/backgrounds/`; uploads use HEAD plus immutable conditional PUT. Existing objects must agree in hash/bytes/type. S3 HEAD/GET and configured public GET are checked before Draft+audit commit. No arbitrary URLs, redirects, implicit proxy, overwrite or deletion. Storage and PostgreSQL cannot commit together: failures leave reusable immutable objects, never fake successful records or blind cleanup. A duplicate original returns 409; only one database row can own its image key. No SFW/copyright approval is implied by upload. C3 must generate metadata-free compatible images and request human review.
