# D3-A1-R1 — Durable Game Publication & No Implicit Expiry

**状态：冻结、必须优先修复** · 2026-11-13 · 仓库 \`librecosta/gofurry\` · \`develop\`

## 0. 缺陷与决定

这是对 D3-A1 的**纠偏**，其优先级高于 \`docs/v0.1-d3-a1-automated-game-intake-multi-source.md\` 中关于审核到期、自动资料有效期及发布依赖的任何冲突描述。

目前 D3-A1 的 \`game_presentation()\` 要求：
- \`game_intake_candidates.review_until > statement_timestamp()\`，审核后 180 天自动过期；
- \`profile_at > statement_timestamp() - interval '30 days'\`，连续 30 天没有成功更新自动资料后停止对其作为展示来源的资格；
- \`PublishedGame\`、\`PublishedGamePage\`、\`CanPublishGame\` 将 \`game_presentation(...)->>'approved'\` 用作自动管理游戏的公开门槛。

这会让一个已经正式 \`published\` 的 Game 因为时间流逝、Harvest 停机、配额、网络故障、Consumer reset/410、来源临时失效而从公开目录/详情消失甚至变成 404。**这是产品缺陷，不能接受。**

**永久约束**：Game 的作品身份、公开发布状态、最终选择的基础资料是持久业务数据。采集成功或失败、资料多久没有刷新、审核证据多久没有更新，**均不可隐式更改已发布身份的公开状态**。只能因明确的存档/撤稿动作或具有可核对正面依据的内容政策处置改变可见性，并留下持久原因与审计。上述机制不能用“自动下架保证准确”来辩护。

## 1. 两类数据，不能混淆生命周期

**持久作品资料**：
- \`games.id/public_id/slug\`、已发布状态、首次发布日期；
- zh/en 真实名称、简介、作品标签、开发商、发行商、经过验证的封面与关联发行入口；
- 发售时间与状态的已确认事实，保留其精度和来源；
- 编辑值拥有绝对优先权；自动展示值在“发布”时必须形成明确的、持久的已选资料，不能每个公共 GET 重新依赖候选租约或有效期。
- 新增更可靠事实可以修订已选的自动展示快照；单次采集失败、没变化确认、当前代切换和接口离线都不能把快照抹空。不能以一条 30 天 TTL 抹去“已知最后状态”。

**时效事实**：
- Steam 当前价格、折扣、当前在线玩家数、短期趋势等需要注明 \`observed_at\` 与对应平台/商店区域。
- 超过展示时效时可**不再称其为当前值**，展示「上次记录」或只隐藏当前数值；但不得删除已有历史、修改 Game 发布状态或撤销其它持久作品资料。
- 新闻和已发布年鉴按各自既有来源与保留契约处理；其状态不用于自动删除 Game。

**真正的内容政策**：
- 内容等级及相关性可能决定**首次公开资格**，但这是发布决议；发布后不能因时间自动撤销。
- 初期自动分类若还不具备可靠判定，则候选保持未公开，不得将“缺成人标签”伪装为已确认 SFW。D3-A2 应实现自动分类与适当证据以减少人工；不允许把现有 \`game-intake review\` 的两条人工作业证明当成长期必须周期重填的运营义务。
- 若有确切新证据证明需要隐藏成人内容，走**持久、原子、可审计**的明确内容处置（单一原因码、来源/依据、时间、规则版本）；不能由 \`WHERE profile_at < now()-... \` 的瞬时判断隐式隐藏。撤销错误处置必须有恢复路径。CN 仅成人内容与评论有专属约束，其他产品功能保持一致。

## 2. 最小工程修复

1. 通过新的 Goose **前向迁移**修正 \`game_presentation\`、\`CanPublishGame\`、\`PublishedGame\`、\`PublishedGamePage\` 及全部相关公共读取。禁止改写已应用的 \`202611120004_game_intake.sql\`。
2. **彻底移除 180 天与 30 天作为出版/目录/基础资料显示门槛的逻辑**。可以保留原始 \`profile_at\` 作为「最近观测」元数据，但不得用它消除作品身份与基础信息。 \`review_until\` 若保留旧列只作兼容不得参与任何“已发布是否可见”的查询；后续安全清理需通过迁移。
3. 现有 \`game_presentation\` 从 \`accepted\` Candidate 的实时状态、\`game_sources.active\` 等条件即时派生公开名称/简介，这仍会出现隐式失败。应增设**最小持久公开资料快照**或经证明等价的轻量业务结构，在首次发布时锁定至少一种名称与摘要、语言、选择来源和最后成功确认时间；不覆盖原有 \`game_localizations\` 人工内容，不能使用通用 EAV / JSON 页面 CMS。
4. 公开 \`games.status='published'\` 是存在与可见性的权威状态，另加明确、持久的内容处置标记（如确有必要）以执行真正的成人内容撤稿。动态 Candidate/Harvest 资料的过时、缺失和请求错误只影响相关自动字段的质量/更新时间，不影响 200/404。非公开 \`draft/archived\` 和禁止成人内容仍必须真正 404，且不存在数据越权泄露。
5. 处于 \`accepted\` 的候选因来源移除、暂时断开、Observation withdrawn 或 Consumer 重建，不得删除**已公开的持久资料快照**。可把具体失效商店链接单独标注为不可用或移除点击，但页面身份和有效介绍仍须保留。不能错误关联其他 GameSource 或把不安全 URL 保留为可点击入口。
6. 自动 Intake 首次创建仍须确定不是 DLC/Demo、符合题材及当前内容政策后才允许首次公开；但**不要把人为双证据确认设置成永远要重新提交的任务**。D3-A2 的自动证据评估是后续独立能力，不能在 R1 中伪造“已经完全无人审核”。
7. 明确失败语义：暂时 Harvest/API/Redis 无法访问、Steam 停止响应、30/180/365 天没有新观察、单个 Provider 不支持某字段 => **保留最后成功持久资料**。需要首次发布但还没有可用资料时留 draft；不制造 200 空壳或 404 假不存在。
8. SQL 必须继续 \`sqlc+pgx\`，Go1.27/JSONv2，UUIDv7，保持 CN/INTL 数据物理分离。默认不新增 FK/级联/自增 ID，不创建独立服务/消息队列/通用 CMS；不改 Start、Sites、年鉴、Harvest 仓库、旧站与 Frontend 视觉。

## 3. 强制验收：跨时钟与中断场景

所有测试只在隔离 PostgreSQL 18、Redis 与本地模拟 Harvest 进行，不触及共享开发或生产 DB。

- A. 通过现有 Intake 形成一条已公开 SFW 游戏；固定时钟分别快进 **31/181/365 天**，不再次采集、不刷新审核。对应 \`GET /api/v1/games/:publicID\`、列表 SSR 均保持 200，并保留实际名称、简介与 Public ID；Slug、canonical 和首次发布时间不变。
- B. 模拟 Harvest 停止、配额不足、一次 Job 返回错误、失效的 Consumer 410/重建，仍同样可读；价格与玩家数可变为“过时/上次记录”，不能消失整款游戏。
- C. \`game_sources.active\` 解除来源、切换默认展示来源、某些字段 \`withdrawn\`、保留历史观察时，基础资料快照不能随条件过滤而变成空。若地址不安全则移除该外链，不隐藏整页。
- D. 实际人工编辑的 zh/en 名称与简介仍优先，自动来源更新不覆盖编辑，缺少译文不能伪装翻译。
- E. 发布前未知 SFW/题材仍不能公开；**只有显式、持久、具证据的成人内容处置或管理员归档**才能影响既有已发布 Game 的可见性，且审计/恢复路径完整。
- F. 并发、反复 Consumer replay、不确定提交、前向 Goose 迁移旧数据与重新迁移均稳定；旧 D1 人工发布 Game 不改变路径。归档/禁止内容没有因该修复越权出现在目录。
- G. \`task check:catalog\`、\`task check:collection\`、\`task check:web\`、\`task sql:check\`、Go API、Docker/Containers、HMR 的适用 CI 真正通过。禁止删除测试、更新 Golden 掩盖回归、将时间快进测试改成只改业务数据。

交付 \`docs/v0.1-d3-a1-r1-acceptance.md\`，包含修正前后行为矩阵、具体 schema/query diff、真实跨时钟和中断测试、可见性与成人规则边界、是否需要部署前向迁移、最终 commit SHA、CI 链接。

**冻结后的底线：一个已经公开的游戏，不能因为采集器没有按时刷新，就在 GoFurry 上凭空消失。**
