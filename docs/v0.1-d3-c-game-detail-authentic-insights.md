当前实际基础：
- D1 极简 `/{-$language}/games/$publicId/{-$slug}` 详情只有标题、简短介绍和来源链接，`GET /api/v1/games/:publicID` 是紧凑 DTO；
- D3-A2-A 已有 `ReadGamePresentation`、`game_source_metadata`（Steam details/media、按语言/商店区域/出口记录，持久），已有当前 Steam 价格（只在最近 48 小时可称 current）、新闻（每来源有界保存）、玩家数（最近 2 小时视为 current）；

- D3-B 已完成 `game_channel_steam` / GameCard / Genres / Release / Collections 和频道 UI；
- D3-A3 itch.io 结论 **RSS-ONLY**；只能在来源已确认时显示官方 itch 链接，**不能**生成 itch 价格、玩家数、下载量、图表。

**本轮不做**：新的 Steam/itch Provider、Steam catalog discovery、AI/审核与自动建档重构、用户评论/评分/收藏/抽奖、任意 UGC、成人模式、新 Admin 界面、旧站迁移、跨区域同步、大型通用 Analytics CMS、用户行为追踪。新功能只基于**真实已知来源**。

## 1. 绝对业务约束

- **Game 公共身份和已发布内容是持久业务数据**。严禁依据 `profile_at`、`review_until`、Harvest 停机、Consumer 410/reset、报价超过 48 小时、玩家超过 2 小时、没采集到媒体/Genre、图表无历史、AI 模型不可用等，让已发布 Game 从目录或详情变为 404。31/181/365 天无采集也要保留最后已批准标题、简介、Public ID、编辑资料及已积累的有效历史。只有已有明确 `archive` / 持久成人内容处置改变可见性。
- 既有人工 `game_localizations` 优先，`game_approved_presentations` 的批准自动资料次之。自动来源更新不覆盖编辑文本，不因“最新更新的市场”切换主展示源。不存在来源就诚实显示缺失信息，不虚构翻译、精确发行日期、玩家数、完整评论、开发者或历史价格。
- **平台级事实不得被伪装成作品全平台数据**。Steam 同时在线仅为对应 AppID 的 Steam 采样；Steam CN/US/HK 价格不可混币种、不可取最低价后标为作品统一价格；Steam 上架/Coming Soon 不等于作品全球首发。itch 仅为已验证的平台发行链接；Game 一份 Public ID 下可以有多个来源，但按来源分组展示。
- 已发布持久资料与时效数据区分：“当前价格/实时玩家数”受各自时效约束，历史事实标明观测时间/样本覆盖，并长期保留。**实时信息变旧可以失去「当前」标签，但不能静默抹掉作品基础信息或已经合法积累的历史观测。**

## 2. 正式详情 API 和聚合读模型

保留 `GET /api/v1/games/:publicID` 现有紧凑返回完全兼容。建议扩展 **`?profile=1`**（或沿用已有的同等有界领域 API 契约）用于详情 SSR，一次返回：
- `public_id,slug,localizations`、来源语言/翻译状态、已批准资料、标准封面/图片/媒体候选；
- `sources[]` 的发行平台、来源外部键、允许展示的安全官方 URL、active/历史语义；Steam 元数据根据明确 GameSource 与可信 scope 归属；
- 标题/简介、开发商/发行商、受控 Genre、Steam 游戏类型、Windows/macOS/Linux、官方宣告的发行状态/日期精度与原始文字；
- 按 GameSource+店区的有效 Steam 报价、最后确认时间；玩家最新可信采样（带 appID、observed_at）、来源明确的官方新闻（有界）；
- 从 D3-B 已公开/未封禁 Game 中选定的**确定性相关推荐**（最多 6–8 个），优先同真实 Genre、同合集、可信开发者等有效交集；无足够证据可以为空，不以相似名称合并作品、不引入假热度/排名；
- 清楚的 `data_status` 或 `observed_at` 元信息，历史/不可用与真实零价格/零玩家区分。

优先复用 `catalog.ReadGamePresentation`、D3-B 的 `GameCard/ChannelMarket` 以及现存来源/新闻/报价表，避免第二套重型 JSON 聚合。只选择用户真正需要的一种语言与当前地区偏好，读取有界、单次快照、参数化 SQL、无 N+1，公开 SSR **绝不访问 Harvest/Steam/CDN HEAD 或模型**。业务无数据与数据库异常严格区分（404 vs 503）。不能把内部 Observation Hash、Target、Worker 凭据等生产诊断字段无差别公开。

新增 **`GET /api/v1/games/:publicID/insights?range=...`**（或相同风格的有界独立读取），使图表按需获取，不阻塞首屏 SSR。只允许公开 Game；查询范围有白名单、采样点数量上限、来源/地区合法性、失败 503 与真正无样本 200 空序列区分。历史接口返回实际 coverage 和 UTC 观测时间，不因无数据假设零。

## 3. 页面信息架构与视觉

以 **D3-B 的 Game 频道**为视觉基线，继续 TanStack Start + React SSR + SCSS Modules + Motion + 必要 Base UI，不复制旧 Vue 页面或旧 Tailwind。桌面建议主内容+克制的来源信息侧栏；中小屏单列且关键发行入口易访问，不要做嵌套整页滚动 Canvas、巨大塑料发光卡、花哨假科技风。页面要具备足够高的游戏视觉表现，不比首页更简陋。

**固定结构，允许缺数据优雅退化：**
1. **Header / Hero**：实际 Steam header/capsule 或可靠封面、真实作品标题、摘要、来源类型与系统标签；主平台发行按钮。无图片时排版兜底，绝不生成假封面。
2. **发行来源与报价**：Steam 和 itch 等来源分别显示官方链接；Steam 报价明确币种/商店地区、免费 vs 促销零元、折扣及观测时间，失效报价作为历史或不可用，不继续自称当前；无数据不产生虚构卡片。
3. **内容区**：建议 `介绍 / 媒体 / 数据 / 官方动态 / 资料` 五个有语义的 Tabs（可以合理收敛，但不能遗漏功能）。默认介绍的真实文字与核心元数据须 SSR 可读；其他按需加载，Tabs 必须键盘可达/焦点明确，移动端合理横向浏览，不因切换复发多个昂贵请求。可以在侧栏补充开发商、发行商、类型、支持平台及推荐。
4. **相关游戏**：与用户的作品发现路径形成自然闭环，链接新站真实 Public ID URL；无有效候选则不填充假相关推荐。
5. **回到 Games 目录/合集**：不破坏 D3-B 的返回页次、过滤器与滚动位置；页面语言切换、路由深链接、浏览器后退保持可用。

不能出现空的「评论」「用户评分」「抽奖」「收藏」「写点评」模块/Tab/CTA；INTL 不提前实现成人内容，CN 的成人信息依然被明确限制。

### 介绍及资料

- 使用 `SteamDetails.Description` 的**已清洗纯文本**和人工覆盖来展示；不能使用旧站 `v-html` 直接渲染来源 HTML，更不能把普通文本解释为原生 Markdown/HTML；换行/段落应安全可读。
- 开发商/发行商、Steam Genres/Categories、系统声明、语言字段（`supported_languages` 仍可能是未经完整语义解析的纯文本）、发行文本保留来源与上下文。
- 未知发售日不能从 quarter/year/TBA 猜算准确日；逾期 coming_soon 不自动改已发售；按具体来源注明“Steam 发售情况”，而非全平台事实。
- 若某语言不存在实际翻译，继续使用有来源语言的内容回退并保持该语言的 SEO `noindex` 规则，不偷偷生成翻译。

### 图片/视频

- 真实可用的媒体仅来自已验证来源：Steam 最多 8 张 screenshot、4 段 movie，加 header/capsule；多源按来源可追溯，不重复/不渲染恶意 URL。
- 类旧站实现主媒体舞台 + 可键盘操作缩略图、图片全屏 Lightbox、Esc 关闭/焦点返回、移动端适配；视频用户主动点击播放，`preload=metadata` 或更保守，非自动播放，不因为离屏预载多个视频。媒体 CDN 不可用时本区块退化、主页面仍 200。
- 服务器与客户端均对 HTTPS、可信 Steam 资源域、长度、片段/查询及媒体 URL 做合理检查；不得把任意来源 URL 当可嵌入脚本/iframe。SEO OG 图片使用有来源的可用封面，不因图片 HTTP 故障隐式改 canonical。

### 官方动态

- 当前 News 有可靠的 GID、标题、原文 URL、来源、发布时间，但**不保证有可以合法完整复用的正文**。列表/时间轴显示真实标题、来源和日期，原生安全外链打开官方文章。
- 按 (AppID, GID) 去重，按发布时间排序、严格分页/有界“加载更多”；不复制旧站通过 `v-html` 直接显示未经可信清洗的正文。
- 历史新闻既有保留契约继续；没有近期新闻不视作作品过时或发布失败。

## 4. Insights — 真实历史，不伪造旧站 1/3/5 年数据

旧站已有玩家折线、历史价格图、变化时间线；新站目前只有 30 天 `game_evidence_players` 30 分钟桶，**当前价格没有可供恢复多年价格走势的原始历史表**。D3-C 应一次完成**采样持久化 + 可用历史图表**，从真正有证据的日期开始积累，绝不宣称旧站历史已迁移或推断 5 年数据。

**Steam 玩家曲线**：
- 用已有 `game_evidence_players` 作为真实短窗口来源，依据 `source_id + scope_key + observed_at + observation_id` 验证归属和去重。
- 可补最小 `game_player_daily`（或同等有界日汇总）：每日仅从真实采样计算 `sample_count`、采样最大值、采样平均值或加权累积；**不是全体玩家数、不是全天真实峰值**。第一次实施可从实际已有最近 30 天观察回填，往后与 Consumer 更新事务一致；原始 30 天清理前已物化的日汇总保留，不再因原始样本清理导致完整历史无声消失。
- 图表短期提供 7/30 天等实际可用范围；较长范围（90 天/1 年）只有数据真正覆盖后才显示，并注明采样覆盖率。0 是真实 0，缺样本是 NULL/间断，不插值造点。
- 若同一 Game 有多个 Steam AppID，分别展示 AppID 来源，不直接相加为全平台人数。

**Steam 价格历史**：
- 可以增加最小的有界 `game_price_observations`（命名可按已有 schema 调整），从 Consumer **真实成功的价格 Observation** 记录 AppID/来源、商店区域、币种、明确 free/zero_price/priced/unavailable 状态、原价/现价/折扣、实际 observed_at 和 Observation ID；
- 必须区分重复确认同一数值（不制造新变化）与真实价格变动；可以采用每 UTC 日的可靠末次观测 + 真正变更点的紧凑结构，支持简单价格折线/阶梯线。中间缺采集时间**必须断开或明确未知覆盖**；不可将采集区间空白当成原价、零价或一直免费。不可混合 CNY/USD/HKD，不能将“首次采到最低价”冒充“历史最低价”。
- 历史从本次新功能启用后积累；可从**有真实时间与归属证据**的可用现存快照回填，但不能使用最新价伪造过去各天价格。后续 D5 若旧站能迁移有证据的历史，再按独立真实迁移契约补入。
- 不设“超过 30/180/365 天自动抹去已积累趋势”的隐式规则。历史保留与存储成本由有界采样/日汇总控制；原始临时样本可遵守已知明确的 30 天策略，但保留的长期日汇总不跟随删除。带观测时间/来源的历史事实不会自动下架 Game。

**真实变化时间线**：
- 只用 News 发表时间、真实价格观测变化、明确来源发售状态变化和有证据的事件生成条目；没有差异历史就显示“暂无记录”，**不能用新版当前状态倒填一条假的旧事件**。
- 不建立通用事件溯源框架或复杂统计微服务。若只有官方 News + 价格已确认变动，足以构成轻量动态时间线。

**图表与 UI**：
- 先核对 Web 现有图形依赖。采用轻量、可按需加载且真正支持 hover/focus/键盘、移动 tooltip、暗色主题、UTC 轴、缺口和 no-data 的方案；优先复用工具，不为两张图整站加载大型 ECharts 或另造重型可视化平台。
- 0/1 个样本显示明确状态；2+ 个点才绘图。显示`采样平均/采样最高`和真实观察时间，不冒充真实全天峰值。
- 控制最大返回点数与服务端计算开销；图表从细粒度查询变为日级摘要要真实标记采样精度，不生成假的连续数据。

## 5. 安全、状态、边界

- API 与 SSR 公共权限边界沿用 D2/D3-R1：`published AND NOT publication_blocked` 的 Game 可读；已归档/被封禁不会通过详情、Insights、Related、News、媒体 URL、计数泄漏。内部重放/更换来源不能绕开审核决定；入站每个 Public ID/参数/地区都严格验证。
- `GET ?profile=1` 的数据读错误如果只是可选新闻/统计部分，可以明确局部 unavailable，不得把基础已批准 Game 详情改成 404；真正数据库不可用应 503，不能把异常吞成 200 空白。
- 公共游戏卡/详情的图片/动态绝不接受来源不明的 URL、危险 scheme、raw HTML 或 SSR 运行任意脚本。安全外链 `rel=noopener noreferrer`；不追加用户身份/完整请求 URL 进入日志。
- 不扩展 CN 专属业务限制；目前两区产品均仅 SFW，CN 在成人内容和评论上维持约束。INTL 的真正成人模式未来单独设计。
- 同一页面在 Collector 缺席或数据很稀疏时仍可读、有设计感，不用虚构几万玩家、折扣、文章或影片填空。

## 6. SQL 和实现策略

- 优先复用 `game_channel_public`、D3-B GameCard、`game_channel_facts`、`game_source_metadata`、`game_approved_presentations` 和 `game_evidence_news/players`；若确有需要，只通过**新的 Goose forward migration** 增加价格观测与玩家日摘要等少数专用表与合适索引。禁止修改已应用迁移、增加自增主键、通用 EAV/CMS、跨区域数据库访问或无价值级联 FK。
- Consumer 的接受观察、长期聚合/变更、ACK cursor 需要保证幂等和事务性；在旧 30 天样本清理前安全生成历史汇总。来源重绑必须限定有效绑定时间区间，不能把别的 Game 的历史算进来；同一数据重复 replay / snapshot / 410 不得重算多份数据。
- 采集保持现有 Harvest、现有 Schedule 与预算；D3-C 不自动为所有 Game 开启新的高频采集 Job 或所有 CN/US/HK 矩阵，不以图表缺数据为理由消耗大规模额度。原有 Game 即使只有 Steam EN/US 数据也可正常显示。
- 维护地区 DB 的物理隔离；INTL 只有已投影的资料可用时照实显示，无跨境实时 API 依赖。不要修改 Harvest/steam-go/AI Gateway/旧站/Admin。
- 图表与媒体客户端组件按需加载，SSR 首屏只有必需稳定资料；不创建 N+1，每 API 响应有界，保留 D3-B 目录返回历史。

## 7. 强制验收

必须使用一次性 PostgreSQL18.6 + Redis8.2.1 + 固定 Harvest（`349730b5c3ff57be084dfac72dfb77f19dacb54c`）的真实 GoFurry Consumer + 模拟 Steam/AI 上游，无真实公网采集、无共享开发库/生产数据重置。

1. **基础详情**：D1 兼容的 `/games/{public_id}/{slug}` 和 CN/INTL 本地化路由正确 200，错误 slug 301，非法/私有/成人 blocked 404，真正 API 故障 503；URL、Public ID、SEO/canonical/hreflang、语言回退与 D3-B 目录返回均正确；`GET /api/v1/games/:id` 原简洁 DTO 不回归。
2. **多来源与内容**：单 Steam、Steam+itch、两 Steam Source、缺媒体/介绍/Genre/发行日期、仅英文、人工中文简介等都能正确展示；实际 Steam 开发商/发行商、媒体与多地区报价格式及来源准确；不起虚构 itch 价格。
3. **媒体**：有效 Steam screenshots+movies+lightbox、触屏/键盘、Esc/焦点恢复、视频暂停/卸载、CDN 404/加载失败、恶意 URL 均正确；无自动播放，页面无 JS/控制台异常。
4. **动态**：真实新闻 GID 去重、发布时间及官方安全外链、有限分页/加载更多；0 条/只有旧新闻不导致 Game 下架；不渲染来源 HTML。
