# GoFurry V0.1-D2-A — Navigation Discovery, Heat & Editorial Contract

**状态：已冻结（实现契约）** · 2026-11-12 · 目标仓库：`librecosta/gofurry` · 只允许 `develop`。

## 0. 产品定位与本阶段范围

GoFurry 新站以 **Start** 为日常起始页，**Sites** 是独立的兽圈网站发现频道，**Games** 是游戏频道。D2-A 为 Sites 的分类、查找、有效交互统计、近期热度、固定精选策展建立可用、可测试的数据与只读 API，绝不恢复旧导航首页的动态任意分组结构。

权威参考：`AGENTS.md`、`.agents/architecture.md`、`docs/v0.1-d1-a-site-game-identity-url.md`、`docs/v0.1-d1-b1-acceptance.md`、`docs/v0.1-d1-b2-acceptance.md`、D1-A `sites/site_localizations/site_addresses` 表、当前 Catalog API 和 SSR；旧站 `gofurry/gofurry-nav-site` 只能只读对比功能，不复制旧 schema。

**本阶段实现**：
1. 固定八种分类、站点归属与受控标签、支持语言和正式内容等级，去除国家/公益盈利业务语义。
2. 站点发现查询：关键字、分类、标签、语言、排序、分页、低样本与地区可见性，固定结构首页数据 API。
3. 有效详情浏览/外链点击的旁路事件计数、Redis 短时防刷去重、PostgreSQL 每日聚合与版本化七日热度快照。
4. 仅三个固定精选槽位，受控内部写入服务及必要 CLI，前端只认识固定槽位；不实现任意运营布局编辑器。
5. 受控、无副作用的功能验收，兼容 Site 年鉴及 Harvest；对后续地域聚合仅定义接口边界，不实现热力图。

**不属于 D2-A**：完整 Sites 首页或目录视觉、Site 富详情设计（D2-B/C），LibreCosta Admin 业务管理 UI（D4），评论/收藏/用户系统，站长认领，技术周刊，GeoIP 数据库更新器和地理热力图，成人内容开放，CN/INTL 数据同步，旧站真实数据迁移，Game 标签和游戏筛选，额外 Redis/PG/微服务。**禁止触碰 Start 视觉、交互及全局样式。**

本阶段不要修改 `librecosta/admin`、`librecosta/harvest`、旧站、`steam-go`；共享开发基础设施只可安全连接，所有破坏性测试必须使用一次性隔离 PostgreSQL。

## 1. 固定分类 = 产品合同，不是 Admin CMS

只承认以下稳定 Category Code（前端决定展示布局、顺序、图标、文案、分类页展示形式）：

| Code | 中文 | English | 内容职责 |
| --- | --- | --- | --- |
| `community` | 社区交流 | Communities | 社区、论坛、交流 |
| `gallery` | 作品展示 | Art & Galleries | 图像作品、创作展示 |
| `literature` | 文学阅读 | Literature | 小说、同人文学、阅读 |
| `resources` | 工具资源 | Tools & Resources | 工具、素材、教程 |
| `marketplace` | 委托交易 | Commissions & Marketplace | 约稿、制作、交易平台 |
| `knowledge` | 资讯百科 | News & Knowledge | 新闻、百科、资料 |
| `gaming` | 游戏互动 | Games & Interactive | 游戏网站、平台、互动社区；不是单个 Game |
| `events` | 活动组织 | Events & Organizations | 展会、兽聚、社团、活动组织 |

- 分类不是运行时数据库可编辑的分组树；无 CRUD 创建、删除、重命名或排序接口。可以有一个代码内的版本化 registry（Go 与 TS 共源或明确一致性测试），只存稳定 `code`。修改八类需要代码/发布，不通过 Admin 动态改变布局。
- Site 可属于 **1 个主分类 + 0–2 个不同的补充分类**。所有分类必须不同、注册且受审；数据库持久化关系允许站点跨分类搜索，但写入时锁定 Site 并原子校验唯一主类及不超过 3 类。推荐 `site_category_memberships(site_id, category_code, is_primary)` + 唯一/部分唯一索引；不依赖自动自增 ID，也不引入分类主表 FK。
- 草稿可以未分类；Site 新发布或已发布编辑必须具备有效主类。现有 D1-A Published 记录升级后默认为待审核分类，不自动推断，须通过审核补齐后才能参加 D2 首页/目录公开发现；不能破坏既有站点 UUID/Public ID 和历史年鉴。详情的逐步策略需测试，避免开发 fixture 混淆。
- 受控标签（`forum`、`portfolio`、`fursuit`、`tutorial` 等）只表达细粒度用途，不重复分类、语言或内容等级。可按实际站点数据审慎增加有限词表，首版不预置大量虚构 Tag；新增受控标签须有正式 Code/zh/en 显示说明及版本化审查，不开放任意字符串标签直接入库。
- 主分类并非网站唯一功能；它影响卡片的默认说明和默认策展归属；补充类可被搜索和分类目录命中。分类排序/首页版式完全在前端，后端不返回 CSS、布局 JSON、区块排序或任意 Admin 自定义区块。
- 网站自己的支持语言是**被审核的客观语言集合**（标准语言 Code，如 `zh`, `en`, `ja`）；与 GoFurry 的 `site_localizations.zh/en` 资料翻译明确分开。不根据 IP/TLD/单次网页语言自动证明全部支持语言，不支持则不猜测。限制合理数量。
- 旧站 `country`、`welfare`（公益/盈利）不迁为新版 Site 字段或导航筛选，不使用 CDN/域名判定网站国家。未来访问者地理聚合不等于 Site 所属国。

## 2. Content Rating 作为受控一等公民

Site 独立于分类、标签与地区拥有一个明确分级：

- `unreviewed`：尚未完成运营审核，**默认值**，不可参与发现、推荐、热度榜或公开导出。
- `sfw`：经人工确认的普通公开内容；在地区合法/运营核准前提下可以发布。
- `mixed`：普通+成人内容并存；不能仅以“某个入口可过滤”为理由自动标记 CN 可公开。
- `adult`：以成人内容为主；绝不进入 CN 的不允许存储、检索、缓存、索引或公开发布链路。

**当前版本不开放成人内容**。CN 只接纳和展示审核通过的 `sfw`；INTL 当前 API 也是 SFW，因此 D2-A 中 `mixed/adult` 仅有合法部署侧的分级/审核语义，不因为用户切换偏好就返回未经批准的 Adult 数据。未来扩展 INTL 必须独立评审合规、访问限制、审核和缓存边界；绝不能通过仅在前端隐藏代替服务端限制。

- 分级与 Site 发布状态分离。一个 `published` Site 也必须有可见性审核满足条件才进入公开目录、精选、详情相关聚合或统计。
- 评级变更要明确操作者、时间/理由与安全审核状态。D2-A 可先通过内网受控 CLI/域服务记录决定，不搭建 Admin 新认证系统；无未经认证的公开编辑接口。
- 不能使用 Harvest 字符匹配或技术指纹自动决定 SFW/Mixed/Adult。不得把 INTL 成人元数据直接存入 CN “稍后再过滤”。
- 仅为 D2 导航模块建立和使用评级，暂不强行替换 Game 当前规则或网站 Start 搜索平台政策。不得对 Start 的互联网搜索词设置新过滤器。

## 3. Site 发现与搜索合同

Public listing 在 **已发布 + 地区可见 + 审核分级 + 有效分类** 的明确集合中查询；分页只返回这个集合，计数和列表同一策略。不能泄漏未发布内容或隐藏 Adult 候选数量。

首版搜索：
- 关键字对审核后的站点名称、简介及受控标签检索，支持中英文、参数绑定、安全输入上限、明确空词与特殊字符语义；按具体资源规模选择 PG trgm/全文辅助，禁止构造可 SQL 注入字符串。
- 分类（主或补充）、受控标签、网站支持语言可组合查询；默认同类多选可采用 OR，并显式说明跨维度 AND。分类首页使用前端固定 Code，整个站点目录可根据 URL 复现过滤，SSR 首屏数据应为一致快照。
- 排序包括 `relevance`（有关键词才适用）、`heat_7d`、`published_desc`、`name_asc`；未提供关键字则默认明确的 `heat_7d` 或 `published_desc`（固定契约，不允许隐式变化）。稳定 tie-breaker 为 `public_id`，绝不按旧自增 ID 枚举。
- 有界页大小（建议 24，最大 48）和确定性分页/游标，保证筛选切换时不重复/漏记，明确 400/404/503，禁止空数据掩盖数据库故障。若热度快照过期，透明地按可用降级规则返回而非假装热度实时。不能把 Start's external search suggestions 当作 Sites 分类搜索。
- 首页有 **固定的 API slice**：`featured`（精确三个槽位）、`trending`（七日热度榜）、`recent`（最新首次发布）、`categories`（八 Code 的计数）、可选 `random`；API 按稳定语义字段返回数据，不返回页面布局配置。版式在 D2-B 才实现。
- 精选/热门/最新之间应用有限的首页去重/补位以降低显著重复，但公开完整热门榜必须是真实排序，不篡改 Score 或把运营精选混入“自然热度”。候选不够时允许空/隐藏，不插入虚构站点。

## 4. 匿名有效互动与旁路事件

只统计两种：
- `detail_view`：浏览器实际展示 Site 详情、文档可见、累计约 **3 秒可见停留** 后且不是 SSR/预取才发送一次候选事件。不是纯 HTTP GET、搜索爬虫请求量、路由预加载。刷新/重复访问仍须服务端去重。
- `outbound_click`：用户明确点击受审核 Site 的实际访问入口。真实外部 URL 由已发布 Site `site_addresses` 提供，统计事件只携带合法 Site Public ID + 固定事件类型，不能接受任意客户端 URL/redirect/坐标/IP 参数。

**外链行为**：原生 `<a href=... target="_blank" rel="noopener noreferrer">`，不走中转开放重定向；使用 `navigator.sendBeacon()`（或 bounded keepalive POST fallback）旁路尽力发送。统计服务离线或队列失败永远不能阻止外链；未确认的 Beacon 绝不能假装成功计数。只处理同域、受边缘代理信任边界保护的事件，验证 Origin/Fetch Metadata、Content-Type、请求大小和固定 schema；这些不能当成真实人类证明，仍须防自动化。

**匿名防刷与隐私**：
- Redis 原子限流+去重；使用服务端配置的随机 HMAC 密钥，以实际经可信代理校验得到的客户端 IP、站点 Public ID、事件类型和短期时间桶构成不可逆短期键。不要接收客户端自述 IP、伪造 Forwarded-For 或长期设备指纹；不得记录原始 IP、完整 User-Agent、Cookie、请求体或 HMAC 键到数据库/日志。
- 示例策略：每 (Site, 类型, 源 IP) **30 分钟最多计 1 次**，每个 UTC 日最多 **8 次**；短期 Redis key 到期清理（不超过 48h），服务端全局及 IP 限速；支持常见低样本误差和 NAT 共享出口偏差，不宣称真实 UV。数据统计应允许撤销/失效 Site 立即不计。
- 若 Redis 或密钥未配置、数据库不可用、来源无法可信判断，事件可拒绝或不计，**不能在 Redis 失效时无限计数**。GoFurry 页面和外链仍正常使用；API 响应仅表示接收结果，不能阻断页面。不要使用随机本地内存回退以让不同实例失去统一去重。
- 业务数据库只保留按 `site_id, UTC date` 聚合的有效详情浏览量和外链点击量，以及热度快照/算法版本。按可接受规模用直接参数化 PG 原子 Upsert，暂不引入消息队列、Redis 大量累计后异步批量同步或新增常驻统计服务。每个接受事件只计一次，Redis 去重和 PG 失败窗口可能导致漏计而不应导致人为虚增；明确语义和回归。
- 旧站总浏览量如需迁移，只作为**单独的 legacy baseline（以后迁移阶段）**，不得自动加入七日热度或者伪装近期行为。今日开发 fixture 不能成为真实热度。
- 不实施评论/收藏/点赞/评分，也不添加未来 user_id 的强绑定。

## 5. Heat v1：热度不是人工精选

每日两个聚合量 `V_d` 和 `C_d`；固定七日公式：

```text
Heat_7d = Σ[d=0..6] (0.85 ^ d) × (V_d + 3 × C_d)
d=0 = 当前 UTC 自然日
```

- 以 UTC 日计；计算时刻、算法版本、结果依据窗口和聚合截止时间必须明确。权重与时间衰减固定写入算法版本；可用整数定点/确定性精度，不能使用易漂移随机权重。旧数据更长窗口可供趋势报表，但正式热门榜使用该 7 日模型。
- 版本化自动重算，每小时刷新或更高效的周期性刷新（原则上不高于 1 小时延迟目标），受控批量、PG 锁，支持重启/重复执行；多个 API 实例不会同时覆盖或发布不一致快照。服务启动不依赖预热；热度冷启动明确为零/未就绪，不静默查询全部原始流量。
- 初期热门资格：七日 **至少 10 次有效行为、且至少 2 个 UTC 日期有行为**。不足样本的网站仍可出现在最新、精选、目录，不生成假热度，不人为加分冲榜。运营期可在正式算法版本发布后调整，不能任意后台改权重。
- 热门排名仅使用自然热度、确定性 tie-breaker。精选槽位不会影响数值。可在首页展示“本周热门”，不必公开易被游戏化的任意原始分数；公开 Views/Visits 只能解释为有效事件统计，非真实独立访客数。
- 热度可查询空榜，不作自填充。排行榜每个候选都要重新执行服务端发布/内容分级可见性校验，不复用过期成人/草稿记录。

## 6. 固定策展槽位（不实现动态页面 Builder）

**首页只有三项命名的精选槽位**，由产品代码与前端 UI 决定：

- `featured.primary`：一个主推位。
- `featured.secondary_1` 和 `featured.secondary_2`：两个次级精选位。

数据只允许关联经过评级/地区审核的 Published Site；禁止人工调整真实热度。
- 一槽至多一 Site；同一站点默认不能重复占据多个首页精选槽位。
- 后端只保存槽位 Code、Site identity（UUID）、修改版本/时间/审核来源的必要字段；不保存任意 CSS、版式、组件类型、动态 slot 数量和任意页面配置 JSON。
- D2-A 可创建受控域操作 + 明确 CLI 用于设置/清空/预览三个槽位，使用原有显式 YAML 和管理员机本地权限；不要加入公开匿名变更路由，真正的 LibreCosta Admin 认证审计 UI 留给 D4。
- 如已精选网站归档、撤销发布、评级失效或不符区域政策，公开结果自动屏蔽，后台配置保留供审查；不能由被推荐站点 HTML 或 Harvest 自动重新启用。
- 首版仅复用 D1 编辑字段、已管理图标或已审核已有素材引用；主视觉封面上传/编辑器的生产工作流留 D4，D2-A 不新建上传管道或大规模静态资产系统。

首页静态版式（D2-B 才落地）：
1. 频道标题 + 站内检索；
2. 固定三槽编辑精选；
3. 七日热门；
4. 最新收录；
5. 八个固定分类入口；
6. 随机发现 / 完整目录入口。
不重复旧 Start 的搜索引擎切换、大 Hero、背景图、金句、最近访问或自定义快捷入口。

## 7. GeoIP / Future Visitor Geography（只预留，不实施）

当前天气通过本地 DB-IP City Lite MMDB 解析可信 IP，返回**近似**城市、国家及经纬度（四舍五入两位），Weather 请求再访问天气 Provider。该经纬度是区域参考坐标，不是用户精确位置；用户手动选择天气城市及浏览器主动定位**绝不能**作为访客来源分析数据。

未来访客地域热力图应在已接受的有效行为处理链上做**实时、匿名且有限度的地理聚合**（优先国家，必要时城市或粗网格），只存地区日期计数，不长期保存原始 IP、精确经纬度/单访客坐标/完整事件日志；低样本保护、隐私告知、合规、地理库覆盖率与偏差另行评审。不可根据现有只按日聚合的热度数据反向恢复历史用户位置，必须明确未来启用时才有地理数据。

本阶段**不**实现 Visitor Analytics、热力图、GeoIP 自动下载/热更新或更换天气定位源，不改动 Weather 组件。GeoIP 将来按月自动拉取/验证/版本化切换应是独立基础设施维护任务，保留 DB-IP 署名与授权要求。

## 8. Schema、安全边界与不破坏历史

- 通过新的 **Goose forward migration** 扩展当前 D1-A Site Catalog，绝不改写 `202611110001`–`202611110004` 历史迁移；保留 Site UUIDv7/Public ID、Slug、Yearbook/Harvest 事实和壁纸所有现存行与生命周期。
- **默认不新增外键/级联**。分类和统计用 UUID + 稳定 Code、CHECK/UNIQUE/部分索引/受控业务事务校验；确实需要强 FK 的例外必须逐条给出真实一致性收益、代价和替代方案，未经审查不要增加。不要 drop D1-A 已经明确保留的四条高价值 FK。
- 原始 `site_localizations` 只表示 GoFurry 的中英文资料，不用于推断站点支持语言。当前 D1-A SSR 仅支持 SFW 模式；新增内容等级不得破坏默认 SFW Public API/Yearbook 行为或让权限较低的记录在另一个读取入口暴露。全站相同服务端可见性函数要统一复用；年鉴已归档历史记录可继续遵守其现有已发布可见性，但绝不能把当前被合规限制的站点透传给 CN。
- 运营时间：`published_at` 是首次发布时间还是最近发布？D1-A 在重复发布可能覆盖字段；为“最新收录”建立明确的 **first_published_at** / current published 生命周期语义，不能使用 `updated_at` 或 Harvest `confirmed_at` 代替。新增字段通过新迁移向前兼容，不伪造已有站点首发时间。
- 考虑热度快照容量（至少测试 100/1000/10000 Site 的日查询和 ranking），合理的索引与查询边界，基于实际数据报告 SQL、WAL、heap/TOAST 成本，不要求复杂的时序数据库。所有单表主键/行标识不能是自增 ID。
- 公共 API 仅读 Discover 数据或接受严格校验的匿名计数事件；任何分类/精选/内容等级写入都属于受控内部授权面。业务内部事务禁止在 Harvest 不可用时失效。
- 新接口在 CN/INTL 都由部署地区与审核决定数据可见性，语言前缀不是地区授权。CN **没有**成人内容、评论或匿名写入入口。避免为 D2 的“内容审核”额外启用 Start 搜索关键词审查。

## 9. 目标公开 API（D2-A 保持简单，接口形状由现有风格决定）

建议以现有 `/api/v1/sites` 与 `/:publicID` 为基础扩展：
- `GET /api/v1/sites/discovery` -> 固定命名 slice：featured、trending、recent、categories（加可选随机），只返回业务内容与有限计数，不返回布局说明。
- `GET /api/v1/sites/directory` -> 受控 q/category/tags/language/sort/pageSize/cursor 查询，返回可见站点摘要、total/next、过滤条件版本。分页不可泄漏匿名未发布信息。
- `GET /api/v1/sites/:publicID/stats` -> 受控公开聚合（是否暴露数值取决于产品用例），不暴露 IP/HMAC/原始事件。
- `POST /api/v1/sites/:publicID/interactions` -> 固定 enum detail_view/outbound_click，严格体积/Origin/Fetch Metadata/限速/Redis 去重；浏览和跳转绝不能依赖其成功。
- 内部：`catalog` 域写入函数或 scoped CLI 设置分类、语言、等级、精选槽位。集成正式 Admin 登录 UI 留 D4。

路由匹配须在 `/:publicID` 之前注册静态 `/discovery`、`/directory`，不能被参数路由劫持；保持旧 D1-A API 向后兼容，别让 Start 走 Site 目录的搜索实现。Web SSR 读取区域本地 API/PG，不通过 Harvest 或 Admin 数据库。

## 10. 必须真正运行的验收

1. PG18 新建空库与已存在 D1-A/B1/B2 表的向前迁移通过、重复迁移幂等；已有 Published Site、Yearbook、Harvest 事实和壁纸行仍保留，未审核项安全隔离；不用共享永久开发 DB 跑重置测试。
2. 八个分类稳定 Code、跨分类 1 主 + ≤2 次分类、重复/未知/超数拒绝、零分类草稿允许但不可发布到导航发现；Go/TS 代码表一致，Admin 无自由新增分组或首页布局 API。
3. 站点支持语言与站点资料 locale 独立；country/welfare 被忽略/不返回新公开筛选；unreviewed/mixed/adult 的 CN/INTL 当前 SFW 安全测试、草稿/归档不泄漏，不能依赖前端隐藏。
4. 搜索大小写/中文/空字符串/特殊字符/中英文/标签/筛选 AND/OR、相同站点多类别去重、排序分页总数与 cursor 稳定；数据库中断必须 503 非 200 空结果，合法空目录是成功空状态。
5. 有效详情浏览严格 ≥3s 可见后尝试，SSR/预加载和爬虫请求不计；native outbound link 不因计数失败而不能打开；恶意任意 URL/Origin/事件大小/伪造代理来源拒绝，真实有效事件按日累计。
6. Redis 去重/限流 30 分钟与每日上限生效、重复/多实例/缺 Redis/HMAC/数据库失败降级不虚增；不存在原始 IP、UA、坐标或个人路径事件的持久表/应用日志。有效归属只能服务端解析，计数分开。
7. 固定 Heat_7d 公式按 UTC 边界、跨天衰减、低样本门槛、7日窗口、空榜、历史 Views 单独基线；重算/多实例/重试确定性，人工精选不改变原始热度。
8. 三个固定精选槽位合法性、去重、撤稿/归档/评级变化即时过滤、候选缺失空槽保持、热门/最新首页去重不改真实排名；无开放管理路由、无自定义动态布局 JSON。
9. 100/1000/10000 Site fixture 的 SQL/CPU/WAL/heap/index与缓存命中和冷启动，验证真实上限；新服务没有多个常驻业务进程。
10. Start /start、/en/start（INTL /zh/start）、官方壁纸、天气、外部搜索建议、玻璃材质、主题、个性化侧栏、Game 与 Site 年鉴路由及 canonical SSR **完全不改视觉行为**；跑已有 Start Web/Browser/HMR/Container、目录无泄漏、审计错误状态。禁止靠修改 Golden 或跳过用例绿化 CI。
