# Runtime boundaries

Start wallpaper preferences have one controller (`start/wallpaper-state.tsx`) and one fullscreen renderer. Regional LocalStorage stores only version/source/mode/fixed ID or relative path; IndexedDB stores read-only directory handles, never files/indexes. The standalone library closes Settings before opening, separates preview from application, reads nine Published thumbnails per PostgreSQL page and uses cancellable bounded local scanning/decoding. No local bytes, EXIF or paths leave the browser. Public detail/random are Published-only; bounded page caches are deployment-owned and invalidate on publication/archive. Only a confirmed fixed 404 clears a pin; network/503 and local permission loss retain it. See `docs/wallpapers.md` for stable contracts and resource budgets.

- `apps/web`: TanStack Start + React SSR, SCSS/CSS Modules and Motion. Base UI Popover/Menu/Dialog/Tabs/Radio primitives retain positioning and accessibility; SCSS owns visuals and Motion owns entry/exit/selection/image timelines. Controlled roots use `AnimatePresence`, `Portal keepMounted` and `render` composition, with no competing CSS opacity/transform transitions. Nitro's Node preset produces a self-contained `.output`. `/start` loads public background metadata after hydration through one regional API (`WEB_API_BASE_URL`); image bytes go directly from CDN. Preview and decoded AVIF/WebP overlap. API availability never blocks rendering or normal search.
- `services/api`: one Go module pinned to 1.27.3. Cobra requires one explicit `--config` path; Viper validates only that YAML, without environment bindings, search or merge. JSON adapters use standard-library v2/jsontext. `internal/server` owns Fiber, readiness and shutdown; middleware and handlers retain their existing boundaries.
- Middleware order: Request ID → Contrib Zerolog → Recover → Helmet → probes/routes. The outer logger asks Fiber's error handler to render before logging, so errors and panics receive their actual status and correlated ID. Logs use an allowlist of fields.
- API readiness becomes true in `OnListen`, false in `OnPreShutdown`. `GracefulContext` drains requests for up to 10 seconds; both Apps drain before their startup owner closes shared pools/readers/clients. Optional Redis is a startup-owned, shutdown-closed client from the same YAML, with bounded deadlines and local fallback. Optional S3-compatible storage uses bounded HTTP requests and explicit YAML credentials. Public backgrounds read only PostgreSQL, while upload/publication check objects; the development import CLI is create-once and prefix-limited. No prefork is enabled. Forwarded client IPs are ignored unless YAML explicitly names trusted proxy peers/CIDRs; Fiber validates and strips that chain, with no broad private/loopback trust.
- Optional `geoip.database_path` resolves relative to the one API YAML and opens/verifies a local DB-IP Lite City MMDB at startup. The Start location handler does local `netip` lookups only, returns approximate city metadata or unavailable, and is private/no-store and independently rate-limited. It accepts no supplied-IP lookup and logs no client addresses/coordinates. Web SSR does not forward visitor IPs; see `docs/v0.1-c1-weather.md` for the direct-edge Nginx contract, attribution and manual file updates.
- Optional QWeather current weather uses that validated city only. One regional Provider reads a PKCS#8 Ed25519 key once, reuses and refreshes JWTs in memory, and reads Host/IDs/proxy only from the same YAML. Private key paths resolve against the YAML; `data/private/` stays ignored. The local coordinate/language fallback cache caps 512 entries and 4 merged-key flights, with 20-minute Fresh / under-60-minute Stale and failure cooling. HTTP quotas are separate; no arbitrary-coordinate weather or supplied-IP endpoint, environment proxy or background poller exists. Return original provider attribution and bounded ready/stale/unavailable data, never a JWT or raw upstream error. Post-shutdown cancels requests and closes the Transport. The Start widget fetches only its URL locale after hydration, validates deployment Region/SFW headers, cancels replaced work and rechecks after 20 minutes on visibility return. Display-only data stays in React memory; no coordinates or complete response are persisted. Its Base UI/Motion Popover displays the linked provider and required declarations; the redundant attribution-document URL is omitted at the user’s request, while API metadata remains intact. The production Web relay forwards only `lang` and validated `city_id`, never visitor IP headers; real resolution remains the trusted direct-edge API's responsibility.
- Start locale is owned by the deployment-relative URL: CN `/start` + `/en/start`, INTL `/start` + `/zh/start`. Cookie only remembers it; no IP/browser/Cookie redirect overrides an explicit URL. A pathless Start shell preserves background/dialog/search instances across language navigation. Start is noindex; future indexable routes own canonical/hreflang.
- Start's desktop homepage entry opens an Edge/Chrome extension prompt with download disabled until an official store listing exists. Extension page protocols suppress the entry. Ordinary HTTP(S) visits do not infer extension installation. The host-only regional `gf-homepage-entry-CN|INTL` Cookie is read during SSR and can be changed in Settings → Advanced.
- Optional `cities.index_path`, relative to the explicit Go YAML, loads an immutable GeoNames cities5000 catalog at startup. `task cities:init` manually builds ignored local data; no runtime download or external city API exists. City search is bounded/rate-limited and weather accepts only a catalog-validated `city_id`, never client coordinates. Manual and IP locations use the same regional weather Service/cache/quotas. Responses identify `location_source=manual|ip` and GeoNames/DB-IP respectively. The Web relay forwards validated `lang` and `city_id`; no IP headers are forwarded. Only the city ID is persisted under `gf-weather-city:CN|INTL`; clearing it restores network/IP lookup. Device permission is click-only: rounded, transient coordinates are sent in a bounded POST body to `/api/v1/start/cities/nearest`, which scans the same loaded catalog within 50 km and returns only a verified city. It cannot query weather, and body/coordinates must never enter logs. Device failures preserve the previous selection. Weather records/coordinates remain memory-only.
- Theme preference is system/light/dark, stored in a host-only cookie. CSS media-query themes render system colors before JS; React tracks the resolved OS theme after hydration without changing the initial tree. Region remains deployment-owned. INTL may persist an SFW/NSFW preference, while actual API content remains SFW; CN renders no NSFW controls. No user-data clients exist; future readers stay inside their region. Personalized responses are private/no-store.
- Start's visual material is a host-only, regional `gf-start-material-CN|INTL` cookie read during SSR. The supported values are `frosted` (the default and invalid-value fallback), `liquid` (published Liquid Glass Fast/Clear), and `transparent` (borderless theme tints, with no blur or refraction). The same scope applies to visible search categories, the search form background, visible quick-access icon backings, official tools, added widgets and the widget-manager trigger. Popovers, dialogs, menus, header and footer keep their original material. Only Liquid loads the library and observes visibility. Its shared IntersectionObserver follows the actual CSS layout and viewport; list entries keep stable keys and exiting entries release their bindings. Preserve interactive content separately from the backdrop. Retain Frosted until a real SVG filter is ready and on unsupported browsers. Do not add a wallpaper copy for refraction.
- `styles/tokens.scss` contains one Light palette and Dark overrides, including search material roles. `themes.scss` emits inherited CSS properties, with system colors selected by media queries before hydration. The root links `global.scss?url` (fonts/reset/themes); Vite/Start load route CSS Module assets before their components. No styling runtime or virtual stylesheet exists. Keep Start before React; SCSS HMR and Fast Refresh share the existing `task check:hmr` entry point. Native circular theme snapshots remain separate from Motion. See `docs/v0.1-c0.md` for the A/B/C evidence and retained Base UI boundary.
- Production access logs retain errors and slow requests; fast successful requests/probes are skipped through official Contrib hooks. Compose uses compressed local rotation 5m × 3, a read-only explicit API YAML mount, host ports 17320/17321 on loopback and a 20-second stop window. There are no production integrations; Nginx remains an inactive example.

Official wallpapers own an optional regional PostgreSQL pool (`internal/database`, sqlc + pgx, explicit Goose), a wallpaper Service and a separate loopback Management Fiber App. One process owns both listeners; both drain before shared resources close. Database outages stay isolated from other public APIs. `docs/wallpapers.md` owns the management/data contract. No Admin account database, JWT service identity or cross-region query is used.

Site and Game use the same regional pool and separate tables. `internal/catalog` owns editorial transactions, UUIDv7 and immutable random Public IDs. Fiber serves published DTOs only. TanStack Start reads the local deployment's API and renders cookie-independent detail HTML with locale-owned canonical paths. A missing translation is marked unavailable and excluded from indexing. Catalog outages return 503 without changing Start readiness. See [D1-A](../docs/v0.1-d1-a-site-game-identity-url.md).

The optional CN `internal/collection` component uses a dedicated one-connection PostgreSQL pool and a per-namespace advisory lock. Fiber starts and cancels it with the public listener lifecycle. The private CLI owns binding and schedule intent. A staged projection becomes active with its durable cursor before ACK. Compact facts retain source scope, rule versions and effective binding periods for D1-B2. Public catalog reads remain local. See [D1-B1](../docs/v0.1-d1-b1-acceptance.md).

Game Intake uses one regional PostgreSQL candidate lease and a separate, bounded Harvest one-shot Job. History is accepted only from the Job's verified Attempt. The catalog writes the work, platform source and recurring collection intent in one local transaction. Approved Steam title and synopsis live in a bounded source projection updated by the existing Consumer. Editorial text keeps precedence and the public gate checks positive SFW and relevance evidence on every read. The local CLI and optional Fiber tick share the same service. See [D3-A1](../docs/v0.1-d3-a1-acceptance.md).

`internal/yearbook` reads the local Site evidence ledger and daily/monthly coverage. An optional daily task shares the Fiber lifecycle and uses its own one-connection pool. PostgreSQL serializes Site revisions and guards each coverage compaction transaction; public reads select an immutable published revision. SSR and generation never call Harvest. [D1-B2](../docs/v0.1-d1-b2-acceptance.md) describes the annual cutoff, evidence rules, and operations.

`internal/navigation` reads the regional Site catalog through `site_public_navigation`; only published, reviewed SFW Sites with a primary category enter discovery, export, statistics or anonymous counting. `site_public_history` preserves previously public D1 detail and yearbook URLs until their first review. Catalog CLI writes hold the Site revision lock, and public reads recheck visibility even with an older Heat snapshot. Anonymous events require a trusted same-origin edge and shared Redis before a PostgreSQL daily upsert. Optional Heat refresh uses one maintenance connection and a PostgreSQL advisory lock in the Fiber lifecycle. See [D2-A](../docs/v0.1-d2-a-acceptance.md).

TanStack Start renders `/sites` and `/sites/directory` from that regional API. The directory stores filters in the URL and pages with API-owned opaque cursors. Site display assets have typed, immutable `sites/logos/` and `sites/covers/` keys, with operator review and Site revision checks at binding. Public reads project the trusted CDN URL from the stored key. The Start wallpaper store continues to use its dedicated `start/backgrounds/` validation. See [D2-B](../docs/v0.1-d2-b-acceptance.md).

Site profile SSR uses one request to the same regional Site identity endpoint. It reuses navigation recommendations and statistics and the published Yearbook index. The profile's technology projection checks the current primary origin binding, active Consumer generation and normalized fact scope against local PostgreSQL. A replay gap suppresses its exact old generation. The CLI edits one plain-text localization under the Site revision lock. See [D2-C](../docs/v0.1-d2-c-acceptance.md).

C3 requires AVIF HD and WebP preview from one exact 16:9 canvas; preview <=480×270, HD has no fixed resolution within the existing resource bounds. Complete server-side decoding and byte-derived dimensions remain authoritative. Incremental NOT VALID constraints preserve old incompatible rows while enforcing all new writes; publishing incompatible history is denied. Admin forwards only its configured Bearer and verified actor/deployment snapshots, never browser cookies. Business audit and revision remain GoFurry-owned and transactional; Request ID correlates Admin's independent intent/result audit.

Do not turn reference template directories into empty scaffolding. Add business boundaries, persistence and reusable packages only when real functionality requires them.

- Quick access is a local-only Start preference, disabled by default. `gf-quick-access-CN|INTL` contains only its SSR layout Boolean; versioned `gf-quick-access:CN|INTL` localStorage holds pins and bounded recent visits. The root provider records deliberate GoFurry anchor activations only while enabled; search submissions bypass it. No browser history access or backend persistence exists. Pins precede domain-deduplicated recent visits; unpin preserves recent records, delete removes both. All management lives in the `+` Dialog; site links keep native browser behavior. The same SearchBox animates between its desktop platform row and inline picker/quick row. See `docs/v0.1-c2.md`.
- Start's fixed official tools and configurable widget rail share one active surface. Narrow or very short viewports put the two rails below search and allow the document to grow, with filings in normal flow and the wallpaper fixed to the viewport. Regional `gf-widget-rails:CN|INTL` localStorage stores a version, two visibility flags and at most seven unique registered IDs in display order. Restore validates the registry, tabs synchronize through storage events, and unavailable storage falls back to memory. The widget registry is first-party code. Calculator, random tools, unit converter, Navigation Hubs and manager content load on demand. AI Hub, Asset Hub and Game Data Hub share the Navigation category and the same link UI. New Hub icons are local WebP imports emitted as separate cacheable files; favicon.im is a development asset source only for these Hubs. Hub links go straight to official sites with no referrer or opener and are excluded from quick-access recents.

- CN/INTL have equal business/API/interaction capabilities. Approved differences are deployment/data physical isolation, locale/URL defaults, CN filings and NSFW prohibition (all current backend content is SFW), the explicitly approved C5 static regional search catalog (33 INTL / 31 CN before visibility), plus compliance rules with an explicit basis. Do not create regional keyword lists, feature-disable defaults or review gates. Both default to Bing and use the same dynamic DuckDuckGo suggestions; only explicit YAML can disable suggestions. Locale changes labels, never deployment membership. INTL's existing NSFW preference controls only e621/YiffParty link visibility, not external content. The host-only `gf-furry-search-CN|INTL` Cookie defaults enabled and seeds SSR through the existing PreferencesProvider. Disabling it removes Furry and its selectable targets; synchronous selection resolution falls back to an available platform without clearing input or submitting. See `docs/v0.1-c1-d1.md` for the search contract and regional branch audit.
- Redis caches are bounded by domain (suggestions 256/10m; weather 512/<60m with 20m Fresh), with original timestamps, region-prefixed hashed keys, short ownership-checked leases and shared failure cooldown/request budgets. Existing local caches/coalescing and official Fiber quotas remain during outages. No raw IP/query/coordinates enter cache key text or logs; transient rate buckets expire after 60 seconds. No Redis scheduler, persistence framework or IP-to-weather cache exists. Production CN/INTL still require physically separate Redis/data; development namespacing is not a substitute.
