# GoFurry

GoFurry VNext is a pnpm workspace with a TanStack Start SSR Web and a Go/Fiber modular monolith API.

Read `.agents/architecture.md` for boundaries and `README.md` for setup. `docs/v0.1-a.md` records the foundation verification and known limits. Issue #1 tracks deferred integrations; Issue #2 defers shared UI/Go libraries.

- Work on `develop`; preserve existing changes. Do not change `master`, `pre-master`, other repositories or production resources.
- `third-party/go-furry` is read-only legacy reference, excluded from builds. Never advance its gitlink as part of routine work.
- Keep `routers/router.go` (groups), `routers/url.go` (URL mapping), and `routers/health.go` separate. Handlers belong outside routers.
- Prefer Fiber official Middleware / Contrib. Do not introduce global service singletons, speculative modules, shared libraries or database schemas.
- Sources of truth: source/tests, lockfiles and runtime configuration. Root version files and `packageManager` pin tools; `task tools` checks consistency.
- Never log credentials, bodies, cookies, query strings or raw application errors. Use route templates and correlated request IDs.
- `routeTree.gen.ts` is generated by TanStack Start; do not edit it manually.
- Run `task check`; run `task check:hmr` after styling/build-plugin changes and `task check:docker` after container changes. Review the diff and report checks that could not run.
