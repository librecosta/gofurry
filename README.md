# GoFurry

The current `/start` retains its layout, search, theme, weather and local quick access. Official wallpapers now have a regional PostgreSQL catalog and a separate authenticated Management API with immutable R2 storage. No public accounts, Admin UI/client, extension or production deployment is included.

## Setup and development

Pinned tools: Node **24.22.1**, pnpm **12.8.1**, Go **1.27.3**, Task **3.53.1**. Root version files and `package.json` are authoritative; `task tools` checks consistency and Go configuration/JSON rules. Task selects `GOTOOLCHAIN=go1.27.3`; direct Go commands must use that version too.

Run `task install`. Copy `config.example.yaml` to `config.yaml` once (PowerShell: `Copy-Item config.example.yaml config.yaml`), checking first that no private file exists. Then use separate terminals:

```sh
task dev:api
task dev:web
```

- Web: <http://127.0.0.1:17320>; development `/api/**` proxies through Nitro route rules to API port 17321. Production has no general automatic API proxy or cross-region fallback.
- API: <http://127.0.0.1:17321/api/v1/status>. Both expose `/livez` and `/readyz`.
- Standalone API: `bin/api --config config.yaml` (`bin/api.exe` on Windows). Probe: `bin/api healthcheck --config config.yaml`. The probe derives host/port from that YAML, including wildcard listeners.
- Production Web: `task build:web`, then `pnpm --filter @gofurry/web start`. For local Node, set `HOST=127.0.0.1 PORT=17320` (PowerShell: `$env:HOST='127.0.0.1'; $env:PORT='17320'`). The container retains internal port 3000.

## API configuration and JSON

`config.example.yaml` defines one schema: required `server.address`, `server.environment` (`development` / `production`), `deployment.region` (`CN` / `INTL`) and positive `logging.slow_request` (e.g. `1s`), plus optional `storage`, `search_suggestions`, `geoip`, `cities`, `qweather`, `redis`, `database` and `management`. `server.trusted_proxies` defaults to empty; only explicit IPs/CIDRs may supply forwarded client IPs. Unknown YAML fields fail. Cobra requires `--config` for serving, probing and importing. Viper reads exactly that file: no automatic search, merging, environment bindings, .env, or individual business-field flag overrides. Private `config.yaml` is ignored everywhere and excluded from build contexts.

Fiber uses standard-library `encoding/json/v2` and `encoding/json/jsontext` through non-variadic adapters. Existing status/error fields and null collections are preserved. Invalid UTF-8, duplicate JSON names and trailing JSON values are rejected; no Sonic dependency or JSON experiment flags remain.

`GET /api/v1/start/location` resolves an approximate city from an optional local DB-IP Lite City MMDB, without a network lookup. Set `geoip.database_path` in the private YAML; relative paths belong to that file's directory. Unconfigured/missing/corrupt data or non-public/loopback IPs return `unavailable` without affecting other APIs. The database/archive are ignored. See [C1 configuration, attribution, proxy boundary and verification](docs/v0.1-c1-weather.md) before using the result.

`GET /api/v1/start/weather?lang=zh|en` uses that resolved city with an optional QWeather current-weather Provider. The private YAML holds its dedicated Host, IDs, PKCS#8 Ed25519 key path and explicit proxy; no environment credentials/proxy are read. `data/private/` is ignored. JWTs are reused/refreshed only in server memory. A 512-entry coordinate/language cache is Fresh for 20 minutes and can explicitly return Stale for less than 60 minutes; merged requests, concurrency, cooldown and HTTP quotas bound cost. Unavailable means `weather:null`. Original provider attributions are retained; `fetched_at` is retrieval time. The lightweight `/start` widget fetches after hydration, shows sources in its weather Popover and refreshes on a visibility return after 20 minutes, without polling. Automatic IP lookup on local loopback correctly shows unavailable. The linked C1 document includes the opt-in two-request development integration test; ordinary tests use Mock data only.

Manual weather cities are optional: run `task cities:init` (Python 3.10+, one-time official GeoNames downloads), then set `cities.index_path: data/cities/cities.json` in the private YAML and restart the API. Downloads and the compact index stay under ignored `data/cities/`. `/api/v1/start/cities?q=...` returns up to 10 local matches; `/api/v1/start/weather?lang=zh&city_id=1815286` validates the GeoNames ID server-side and uses the existing weather cache/quotas, including on loopback. The weather Popover persists only the selected ID in region-scoped local storage. “Locate current position” asks for browser permission only on a click, then POSTs city-level rounded coordinates to `/api/v1/start/cities/nearest` for a catalog city within 50 km; it never submits coordinates to the weather endpoint. “Use network location” separately clears the ID and restores coarse IP lookup. GeoNames/DB-IP attribution is visible in city selection; weather details retain QWeather and meaningful links to original attribution URLs. Official local QWeather outline SVGs include day/night variants and a neutral fallback; their MIT notice ships in `apps/web/public/weather/`. See the C1 document for snapshot/version, licensing, explicit proxy and update instructions.

## Region, language and theme

`WEB_REGION=CN` (default) or `WEB_REGION=INTL` selects the Web deployment. Set it in the local shell or Web Compose environment. API region is selected only in its YAML. Operators must keep them in the same region and use separate hosts, secrets, databases and user-data storage for CN/INTL. Reviewed public SFW backgrounds may be shared between regions. There are currently no user-data readers or database connections; future data clients must stay within their deployment with no cross-region fallback.

CN defaults to `zh`, INTL to `en`; both offer both languages. Locale never selects a region. Both APIs currently expose SFW policy metadata; CN remains permanently SFW. INTL may remember an SFW/NSFW preference, while actual backend content remains SFW. Search queries/suggestions are independent of site-published content; both regions share the same search behavior and capabilities. No adult-content query module or account integration exists.

Start URLs own language: CN `/start` (zh), `/en/start` (en); INTL `/start` (en), `/zh/start` (zh). `src/locale-path.ts` centralizes prefix construction for future content routes. Explicit URLs are never redirected by Cookie, IP or browser language; `gf-locale` only remembers the choice. Both versions send noindex metadata and X-Robots-Tag and stay out of sitemaps. Future indexable pages must supply independent canonical/hreflang. Other localized business pages are not implemented; the existing engineering diagnostics retain their preference controls.

Theme preference is `system` (first visit), `light` or `dark`, persisted in host-only `gf-theme` for one year. SCSS themes expose semantic CSS custom properties; media queries select system colors before JavaScript, so SSR does not guess the OS or produce a mismatching hydration tree. React tracks the resolved OS theme only in system mode; manual choices remain fixed. Personalized responses remain private/no-store, without a localStorage second source. INTL's `gf-content-preference` remembers only a future preference; CN ignores NSFW and renders no such controls. API SFW policy is unchanged.

The frozen frontend stack is TanStack Start + React, **SCSS + CSS Modules**, **Motion** (`motion/react`) and Phosphor Icons. Sass 1.107.1 and Motion 14.9.0 are pinned in the Web manifest. `styles/tokens.scss` is the single palette, preserving the legacy warm beige/charcoal canvas, text/surfaces, fonts, dot grid, radii and acrylic alpha. `themes.scss` emits Light/Dark/System CSS properties; `global.scss?url` supplies render-blocking reset/fonts/themes, while Vite/Start load route CSS Modules before components execute. There is no StyleX plugin/runtime, virtual stylesheet, Tailwind, LESS or Nuxt dependency. Sass uses its JS implementation and packaged watcher bindings; the optional watcher's build script is explicitly denied in pnpm configuration.

Motion owns popup opacity/translation, Tab layout, segmented selection and image fading. `AnimatePresence` retains complete exits; reduced-motion resolves to zero duration. Static geometry, colors and focus states stay in SCSS; the same property never has both a CSS transition and a Motion timeline. Base UI remains responsible for positioning, focus and semantics after the C0 A/B/C comparison; it has no visual animation rules. See [C0 evidence and decision](docs/v0.1-c0.md). No shared design-system package is introduced.

## Start page

Quick access is opt-in in Settings → Basic. Its single responsive row combines ordered pins with actual GoFurry link visits; a separate `+` opens add/edit/reorder/recent management. Site data stays in region-scoped browser storage, with memory fallback. Only the enabled Boolean is sent in a host-only cookie to keep the SSR search layout stable; searches are never recorded. See [C2 storage, privacy and focused checks](docs/v0.1-c2.md).

Open <http://127.0.0.1:17320/start> after `task dev:api` and `task dev:web`. The homepage `/` is unchanged. The search group is horizontally centered near 27% of the first viewport, with the legacy 500px input width. Five categories sit above it; desktop platform buttons sit below. On mobile, the selected platform and CaretDown occupy the left end of the same input, with a left-aligned menu below it. Provider IDs remain stable across locale changes. Both regions default to the first catalog platform, Bing; manual selection remains unchanged. Enter or the search icon opens an encoded, trimmed query in a new tab; the default native GET form also works without JavaScript. Composition-confirming Enter never submits. Escape closes the mobile picker; arrows navigate its options, and outside focus/click or a desktop breakpoint closes it with appropriate focus restoration.

Start alone uses a fixed, isolated `100dvh` viewport with a full-height main, dynamic viewport spacing and compact spacing for short windows. Its body overrides and the root dot-height cap are scoped by `:has([data-start-page])`; other routes retain normal scrolling. Background layers are absolute at z-index 0 inside that viewport, below the search/header/footer. This removes the root 720px dot overflow on short desktops and the main's excessive minimum-height/padding combination without hiding document scrollbars or remounting images on resize.

The Logo preserves the original SVG alpha mask, constant light-gray color, geometry and 300ms flat hover. Its Base UI Popover contains Home, Sites and Games, with locale-aware target paths. Only implemented destinations are linked: default-language Home opens the unchanged `/` engineering page; missing localized Home/Sites/Games remain unavailable. The portal positioner uses a fixed strategy before/after measurement and an explicit width, without coordinate transitions or render timers. Base UI hides the unpositioned pass; the popup owns 420ms opacity/4px motion. Initial visible-frame bounds and focus restoration are browser-tested.

Top-right actions remain Settings and User. User's Menu contains one disabled Sign in placeholder. Settings has Basic/empty Advanced text Tabs with a Motion underline, unfilled language RadioGroup, 400ms appearance/content selection blocks and a dashed text-only GitHub footer. INTL alone offers SFW/NSFW with the existing current-SFW-only explanation. Base UI retains keyboard choices, dialog focus trapping, outside/Escape dismissal and restoration. Controlled roots use `AnimatePresence`, `Portal keepMounted` and Motion `render` composition for complete 420ms exits, without CSS starting/ending animation rules. Static Dialog centering uses CSS `translate`; Motion owns the separate animated transform. The shared `_start` shell preserves dialog/query/provider/decoded wallpaper across language URLs. No Identity integration is added.

`start/theme-reveal.ts` retains the legacy 420ms circle reveal, now centered on the selected appearance control. React `flushSync` settles the complete new theme before the snapshot. Unsupported API/reduced-motion switches directly. Repeated clicks are guarded; resize, visibility/page changes and unmount release snapshot state. Only color/surface transitions are settled; R2 opacity fading stays independent.

`start/search.module.scss` consumes inherited search material properties. Existing geometry remains: 48px input, desktop platform wrapping and inline mobile selector. Toolbar hover stays at 300ms; search color states use 420ms, and Motion owns the shared platform/suggestion panel's complete 420ms entry/exit. The panel becomes inert during exit and is not removed by an arbitrary timeout. Preview/HD images fade over 480ms, without remounting on resize. Start alone hides the native cancel button and provides a localized Phosphor X, separated from Submit; clearing cancels suggestions and restores focus. Narrow categories have directional overflow cues and focus/selection auto-scrolling. One immediate keyboard-only input ring replaces stacked shadows. Native Up/Down remains available without suggestions; wallpapers are unaffected by theme changes.

`apps/web/src/start/search-platforms.ts` owns the existing, explicitly curated platform catalog (unchanged in D1). Adult/mixed adult-art providers are excluded in both regions; general engines request strict SafeSearch. WikiFur, Epic and ZCool remain, while Wikisource/Project Gutenberg replace the legacy novel providers. External sites own their moderation. `GET /api/v1/start/search/suggestions?q=...` calls DuckDuckGo's official `/ac/` through the regional Go API, independently of the selected search destination. Only the Search category requests suggestions, after 600ms. AbortController, request generations and IME guards prevent stale results; arrows select, Enter/click searches the current platform, and Escape/outside/blur closes. Empty/error/timeout/429 responses leave no empty/loading/error UI. Platform choices and suggestions share one animated panel, so they cannot overlap. Native Up/Down remains available without results.

Online suggestions default to enabled in both deployments, including when the YAML section/flag is omitted. Set `search_suggestions.enabled: false` to explicitly disable the whole feature. `proxy_url: ""` connects directly; an explicit HTTP(S)/SOCKS URL selects a proxy, and HTTP_PROXY/HTTPS_PROXY are never read. Queries are limited to 128 Unicode characters, upstream requests to 3 seconds/64KiB/4 merged-key flights, results to 8 deduplicated phrases and local/shared caches to 256 entries/10 minutes. Control/format characters and malformed input are rejected; there is no keyword allowlist/blacklist or regional content filter. Upstream failures return the unified 503 error envelope and a bounded `X-GoFurry-Suggestions-State` (e.g. timeout/network/upstream_http/invalid_response), with safe correlated server diagnostics; a successful empty upstream response is 200/empty. Explicit disable is 503/disabled, saturation 429/busy. The frontend quietly closes on errors.

Optional `redis` uses the existing regional server: `address` (host:port), `username` (optional ACL user), `password` (may be empty) and `db`, from the same Go YAML only. Blank/unconfigured Redis keeps local fallback. One go-redis/v9 client is created at startup and closed at shutdown. Suggestions share a 10-minute cache; weather shares the original retrieval time, 20-minute Fresh / under-60-minute Stale window and 512-entry cap. Short Redis leases merge cross-process cold misses; weather cooldowns and request quotas are shared too. Redis errors have bounded deadlines and fall back to bounded local caches/official Fiber quotas. Keys hash query/coordinate/client values and carry the deployment namespace; do not log raw inputs or credentials. Production regions must use physically separate infrastructure, not rely on key prefixes as isolation.

Official Fiber quotas and the Redis shared budget each allow suggestions 60/client and 240/deployment per minute, weather 20/client and 120/deployment per minute. Behind the Web relay, clients share its source IP; untrusted forwarded headers are not accepted. The same-origin relay rejects mismatched Region/SFW headers and forwards no visitor credentials or proxy settings. [D1 audit and live evidence](docs/v0.1-c1-d1.md) records the removed CN restrictions, dynamic upstream results, Redis checks and remaining approved regional differences.

CN alone renders small company/filing text with a centered · separator: slightly translucent light text in Light and dark text in Dark, without text shadow, stroke or filter. There is no fill, card, padding or backdrop blur. INTL renders no footer. Public filing metadata is explicit in `apps/web/src/start/filing.config.ts`, with no environment lookup or Go configuration change. Both numbers remain `null`; local review shows non-link pending labels. Before publication, disable `showPending`; populate only this site's approved ICP number and the police platform's issued number, local icon and official query URL. The ICP target is fixed to `https://beian.miit.gov.cn/`. No old-domain registration or invented number/icon is used.

`GET /api/v1/start/backgrounds` reads only Published records from this deployment's PostgreSQL; it performs no object HEAD or image proxying. The 60-second bounded cache invalidates after management changes and refuses database outages. `database: null` returns an empty array; configured failures return 503 without disabling other APIs or falling back to static JSON. Start fetches metadata from its one `WEB_API_BASE_URL`, forwards no user credentials and checks Region/SFW headers. The browser loads WebP preview, then AVIF/WebP high resolution directly from the CDN. Failures retain preview/theme, and theme changes do not reload images. No wallpaper selector or C3 Admin UI is included.

Private YAML `storage` contains `endpoint`, `region`, `bucket`, `access_key_id`, `secret_access_key`, `public_base_url`; all six are required when enabled and URLs must be HTTPS. AWS SDK v2 uses only static YAML credentials, without AWS profiles, environment credentials/proxies or .env. Management additionally requires an explicitly migrated GoFurry database, a distinct loopback address and private random 256-bit Bearer token. It is disabled by default and never mounted on Public. Data/upload/publication and C3 service-header contracts: [docs/wallpapers.md](docs/wallpapers.md).

Prepare an independent database and private YAML without overwriting existing configuration, run `task migrate ACTION=up CONFIG=<absolute YAML>`, then start the API with that YAML. `task migrate ACTION=status` is read-only. CN/INTL require separate databases/connections/credentials. Generate service token bytes with Go `crypto/rand`, encode exactly 32 bytes as unpadded base64url, and store only in ignored YAML. Do not put tokens in CLI arguments, query strings or browser storage.

Admin C3 uses these fixed internal endpoints through its own authenticated backend; no Admin Session or database is shared. New uploads are **AVIF HD + WebP preview, both exact 16:9**; preview <=480×270, HD remains resolution-independent within 36MP/16384px/50MiB. Incremental migration preserves incompatible C2 history and blocks new incompatible writes/publication; never modify the applied first migration or overwrite R2 to convert an old record. Controlled replacement and actual C3 acceptance are recorded in [wallpapers](docs/wallpapers.md). `task check:wallpapers:link CONFIG=<C3专用YAML> OBSERVATION=<浏览器非敏感请求记录>` checks the real cross-service audit Request ID without clearing tables. Existing storage/schema acceptance also includes 4K, strict formats and legacy migration checks.

Development catalog migration: `task wallpaper:import CONFIG=<absolute YAML> BUCKET=<confirmed-dev-bucket> PUBLIC_BASE=<confirmed-dev-domain> REVIEWED=true`. First verify bucket/domain and human SFW/public-use review. This reads `services/api/internal/handlers/backgrounds.json` only as migration input, validates actual development S3/CDN objects and image metadata, creates UUIDv7 Published records with system audit, and safely skips existing records. It never uploads, overwrites or republishes an archived row. Runtime has no JSON dependency. `background-import FILE --config ...` remains a separate development object-only utility using complete format/privacy validation; it creates no database record.

Focused checks: `task check:wallpapers`, `task sql:check`, `task check:wallpapers:db CONFIG=<owned-test-YAML>`. ## Local containers and logs

Copy `deploy/compose/config.example.yaml` to `deploy/compose/config.yaml` once. Its schema is identical to local configuration, with internal port 8080 and production logging. Select its region to match `WEB_REGION`.

```sh
docker compose -f deploy/compose/compose.yaml config --quiet
docker compose -f deploy/compose/compose.yaml up --build --wait
docker compose -f deploy/compose/compose.yaml down
```

Only `gofurry-local` is managed. Host ports default to loopback **17320/17321**, overridable with `WEB_PORT` / `API_PORT`; internal ports stay 3000/8080. `API_CONFIG_FILE` optionally chooses the bind-mount source path, not application fields. YAML is mounted read-only at `/etc/gofurry/config.yaml`; there is no API Compose `environment` / `env_file`. Missing files fail instead of creating directories. Web region is a server-only Node setting, not a client-controlled Vite variable.

Images run non-root, have readiness probes and a 20-second stop window. Logs go to stdout/stderr; Docker `local` rotates at **5m × 3**, compressed. Production suppresses fast successful requests and probes; errors (including failed probes), slow requests and lifecycle events remain. API slow threshold comes from YAML; Web uses one second. Request logs allowlist route templates/status/duration/IDs, excluding credentials and bodies. Framework banner lines may remain plain text.

If Docker Hub is unreachable, the equivalent official image mirror is supported:

```sh
docker compose -f deploy/compose/compose.yaml build --build-arg NODE_IMAGE=public.ecr.aws/docker/library/node:24.22.1-bookworm-slim --build-arg GO_IMAGE=public.ecr.aws/docker/library/golang:1.27.3-bookworm
```

`deploy/nginx/gofurry.conf.example` remains inactive. No Docker daemon settings or production deployments are managed here.

```sh
task tools
task check:api
task build:web
pnpm --filter @gofurry/web typecheck
pnpm --filter @gofurry/web test:e2e
task check:hmr
task check:docker
task check:containers
```

Check INTL defaults separately by setting `WEB_REGION=INTL` and running `pnpm --filter @gofurry/web exec playwright test governance.spec.ts`. Remove that setting before CN/HMR checks. Browser setup: `pnpm --filter @gofurry/web exec playwright install chromium`; an installed Chrome may be selected with `PLAYWRIGHT_CHANNEL=chrome`.

These are focused runtime/configuration/SSR checks, not a multi-browser business matrix. `task check` remains the general repository entry point. HMR temporarily edits/restores the diagnostic route and its SCSS Module; do not edit them concurrently. Container smoke uses example YAML, random ports and its own disposable project, checks the mount/log policy/SIGTERM, then removes only its resources. It never overwrites private YAML.
